01 · ARCHITECTURE DRAWING

Build a Well-Architected three-tier you can defend

ARCHITECTURE

Edge

Route 53 + CloudFront + WAF is the public front. Eliminate answers that skip a stated edge constraint.

ARCHITECTURE

ALB

Layer-7 entry in public subnets. The app stays private.

ARCHITECTURE

Multi-AZ compute

Replaceable instances or containers in two AZs. One AZ is not highly available.

ARCHITECTURE

Data

Multi-AZ database plus object storage. Know RPO if the question is DR.

ARCHITECTURE

Loose coupling

A queue where work can be retried shrinks blast radius when a downstream tier fails.

ARCHITECTURE

Least privilege + encryption

KMS key policy plus IAM. Default deny; expand carefully.

ARCHITECTURE

The full exam pattern

Edge, then ALB, then Multi-AZ compute and data, with a queue to decouple and KMS to encrypt. If an answer violates a constraint, it is wrong.

02 · DEEP DIVE

What you actually need to understand

1

Classic three-tier web

  • Route 53/CloudFront → ALB → private application tier → relational database.
  • ASG spans AZs; database uses Multi-AZ where HA is required.
  • Security Groups reference tiers rather than opening broad CIDRs.
  • Static assets go to S3/CloudFront; ElastiCache can offload hot reads.
  • Secrets Manager/KMS/CloudWatch complete security/operations concerns.
2

Serverless API

  • CloudFront or front end → API Gateway → Lambda → DynamoDB/S3.
  • Cognito handles end-user identity.
  • SQS/EventBridge decouple asynchronous work.
  • Serverless services scale independently and reduce infrastructure management.
  • Use RDS Proxy if a relational DB is required behind high Lambda concurrency.
3

Event-driven microservices

  • Publish domain events instead of making every service synchronously call every other service.
  • Use SNS/EventBridge for routing/fanout and SQS per consumer for durable buffering.
  • DLQs isolate failures; idempotency protects against duplicate delivery.
  • Each service owns its scaling and failure domain.
4

Hybrid enterprise

  • On-premises → VPN or Direct Connect → Transit Gateway → multiple VPCs.
  • Centralized inspection/shared services can be attached to the hub.
  • Organizations/Control Tower/IAM Identity Center govern accounts and workforce access.
  • PrivateLink exposes selected services without broad network routing.
5

Exam method

  • 1. Identify the workload and architecture family.
  • 2. Underline hard constraints: MUST be private, RTO, protocol, no code changes, least ops, most cost-effective.
  • 3. Eliminate answers that violate any hard constraint.
  • 4. Compare the remaining answers on operations, resilience and cost.
  • 5. Flag lengthy questions and return; never leave an answer blank.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Resilient web transaction

Constraint: a public workload must remain available through an AZ failure and absorb bursts. Design: Route 53 and an ALB front Auto Scaling instances across AZs, with Multi-AZ data and SQS for asynchronous work. Why alternatives fail: one large instance is a single failure domain, and synchronous chaining spreads failure.

1 Multi-AZ removes one fault→2 Auto Scaling replaces capacity→3 Queues isolate bursts
WORKED SCENARIO

Choosing DR by objective

Constraint: the business supplies strict RTO and RPO rather than asking for maximum availability at any cost. Design: map backup/restore, pilot light, warm standby, or multi-site to those objectives and test recovery. Why alternatives fail: backups may miss a short RTO, while active-active can overspend for relaxed objectives.

1 RPO limits lost data→2 RTO limits outage→3 Testing validates recovery
WORKED SCENARIO

Resolving two plausible answers

Constraint: two architectures appear technically possible under time pressure. Design: compare each against every superlative and explicit constraint, then choose the simplest managed option satisfying all. Why alternatives fail: keyword matching ignores trade-offs, and adding services can violate cost or operations requirements.

1 Read the final ask→2 Honor every constraint→3 Managed usually lowers ops
05 · EXAM LANGUAGE DECODER

Words in the question that should trigger a design instinct

“least operational overhead”
→ Prefer managed/serverless among otherwise valid answers.
“without modifying application”
→ Look for infrastructure/proxy/migration-layer solution.
“most cost-effective”
→ Do not violate resilience/security just to be cheap.
“millions of requests + unpredictable”
→ Elastic/serverless patterns.
“decouple components”
→ Queues/events.
“single point of failure”
→ Spread across AZs / managed HA.
06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A company needs a public HTTPS website that stays available if one Availability Zone fails. Application instances must remain in private subnets behind a load balancer. The relational database must fail over automatically. The stem asks for the LEAST operational overhead among designs that meet those constraints. Which solution will meet these requirements?
Answer: A. Underline private app, AZ failure, and least ops: ALB plus Multi-AZ compute and managed Multi-AZ RDS is the three-tier pattern. Public instances and self-managed MySQL violate private or operations constraints.

Good to know: Self-managed MySQL across AZs could meet availability if the stem allowed higher operational overhead. A serverless API would win if the stem forbade servers and did not require a relational engine on RDS.
Q2A new JSON API must handle unpredictable bursts of millions of requests and store items in a key-value model. The company wants the LEAST operational overhead and will not manage Amazon EC2 or container hosts. End users will authenticate with a hosted user pool. Which solution will meet these requirements?
Answer: C. Unpredictable scale plus least ops and no servers selects the serverless API pattern. Cognito is the end-user identity piece of that pattern. EC2 and ECS-on-EC2 increase operations.

Good to know: ALB plus Auto Scaling would be correct if the stem required a long-running three-tier app on instances. RDS Proxy would appear if a relational database were mandatory behind high Lambda concurrency.
Q3A retailer runs an order API that must acknowledge accepted orders even when fulfillment is slow or temporarily down. Fulfillment workers already exist in private subnets and can poll for work. The company must not chain every fulfillment call on the user request path and will not keep orders only in instance memory. Which solution will meet these requirements?
Answer: B. Decouple and absorb downstream failure with a durable queue. Synchronous chaining and in-memory stores keep the user path coupled to fulfillment availability.

Good to know: SNS or EventBridge would join the design if the stem required fan-out to many independent consumers. A DLQ would appear if poison messages had to be isolated from the main queue.
Q4A business runs production in one AWS Region and can wait hours to recover a Regional outage and can lose up to a day’s data. Leadership wants the MOST cost-effective disaster recovery approach that still meets those objectives. Continuously running a second full environment is not required. Which solution will meet these requirements?
Answer: D. Loose RTO and RPO make backup and restore the cost-effective starting point. Active-active and full warm standby overspend those objectives.

Good to know: Warm standby or pilot light would be correct if RTO were minutes and RPO were small. Multi-site active-active would win only if near-zero RTO and RPO were hard requirements.
Q5Compliance states the database MUST stay in private subnets with no public IP. The application is a three-tier web app in one VPC. The question also asks for the LEAST operational overhead for a highly available relational engine. One option places Amazon RDS in public subnets. Which solution should a candidate select after eliminating constraint violators?
Answer: A. Eliminate anything public first (MUST private), then among remaining valid designs pick managed Multi-AZ RDS for least ops. A single private EC2 database is a hidden single point of failure.

Good to know: Self-managed MySQL in two private AZs could survive an AZ failure if the stem allowed higher operational overhead. Public RDS would only appear if the private-subnet constraint were absent.
Q6A three-tier design already spreads Amazon EC2 behind an ALB across two Availability Zones in one VPC. The database is a single Amazon RDS instance in one AZ. The exam stem requires the application to remain available through an AZ failure. Operators will not solve this by moving all compute into the database AZ. Which change most directly removes the remaining single point of failure?
Answer: C. Trace the full path: Multi-AZ compute does not help if the data tier is still one AZ. Multi-AZ RDS removes that hidden SPOF. Bigger instances and a second ALB in one AZ do not.

Good to know: A queue in front of workers would be the fix if the SPOF were a synchronous downstream dependency rather than the database AZ. Cross-Region replica would appear only if the stem were Regional DR, not AZ failure.
Q7On a practice item, two remaining answers both meet functional needs for a Multi-AZ workload. One is a self-managed cluster on Amazon EC2 that the team would patch and scale. The other is a managed AWS service with equivalent encryption and Multi-AZ controls. The stem says minimize operational overhead. Which solution will meet these requirements?
Answer: B. When constraints are otherwise equal, least operational overhead selects the managed service. Length of the option text and extra services are not exam methods.

Good to know: The self-managed cluster would be correct if the stem required an OS-level agent or a feature the managed service does not offer. Always eliminate constraint violators before applying the ops superlative.
Q8A company must recover a production database in minutes with little data loss after a Regional event. Restoring last night’s backup from Amazon S3 would miss the recovery time. Leadership still wants to avoid running a second full-scale active-active environment in another Region. Which disaster recovery pattern should a solutions architect choose?
Answer: D. Minutes of RTO with a small RPO need a running (or readily scaled) standby, not backup and restore. Full active-active overspends if the stem does not require it.

Good to know: Backup and restore would be correct if RTO were hours and RPO about a day. Pilot light sits between backup/restore and warm standby when a longer scale-out time is acceptable.
Q9A legacy HTTP application on Amazon EC2 in private subnets cannot be modified. Internet users must reach it over HTTPS. Instances must stay private across two Availability Zones behind a load balancer. The company will not assign public IP addresses to the application hosts. Which solution will meet these requirements without changing application code?
Answer: A. No code changes plus HTTPS and private instances points to TLS termination on the load balancer. Rewriting the app or putting public IPs on hosts violates the constraints.

Good to know: CloudFront with an ACM certificate would appear if the stem also required a global CDN in front of the origin. A Network Load Balancer would win for TLS passthrough of a non-HTTP protocol.
Q10A stem asks for the MOST cost-effective design that remains available if an Availability Zone fails. The current architecture is a three-tier web app with a relational database. One option uses a single AZ to save money. Another uses Multi-AZ compute and Multi-AZ RDS. Which option should a candidate choose?
Answer: C. Most cost-effective still has to meet every hard constraint. AZ failure is hard; a cheaper single-AZ answer is a violator, not a cost optimization.

Good to know: After Multi-AZ is satisfied, then compare remaining answers on cost (right size, avoid extra replicas, avoid active-active DR you do not need). Never drop a MUST for a lower bill.
Q11Several microservices in one AWS account must react independently to the same order-placed event. Each consumer needs its own durable buffer and scaling. A synchronous call chain from the order service is failing when one consumer is down. The publisher must not keep events only on local disk. Which solution will meet these requirements?
Answer: B. Event-driven fan-out is SNS or EventBridge plus a queue per consumer so each service scales and fails on its own. A synchronous chain couples availability.

Good to know: A single shared SQS queue would be enough if there were one consumer. A DLQ on each queue would appear if the stem required isolating poison messages.
Q12A company is connecting an on-premises data center to many AWS VPCs that must talk to each other and to the data center. The team wants a hub for routing rather than a full mesh of VPC peering. VPN or Direct Connect already reaches AWS. Which solution will meet these requirements?
Answer: D. The hybrid enterprise pattern is on-premises to VPN or Direct Connect into a Transit Gateway hub that attaches the VPCs. Peering does not transit and does not scale as a mesh.

Good to know: PrivateLink would be correct if a partner needed one service without broad network routing. VPC peering would win for a simple pair of VPCs with no transit requirement.
Q13A partner VPC must invoke one private application service that runs behind a Network Load Balancer in the company’s VPC. The company will not peer the VPCs, will not attach the partner to Transit Gateway, and will not expose the service on the internet. Which solution will meet these requirements?
Answer: A. PrivateLink publishes a service without sharing the rest of the network. Peering, Transit Gateway, and a public NLB each violate a stated constraint.

Good to know: Transit Gateway would be correct if the partner needed many VPC routes and the company allowed a shared hub. A public ALB would win only if internet exposure were allowed.
Q14An Amazon SQS worker queue feeds fulfillment tasks from an order API. Some messages always fail and block retries for good work. The team wants failed messages isolated after a retry budget so operators can inspect them. Workers must keep polling the main queue. Which solution will meet these requirements?
Answer: C. A DLQ isolates poison messages after maxReceiveCount so the main queue keeps moving. Removing the queue or using instance store couples failure and loses durability.

Good to know: Idempotent workers still matter because SQS can deliver a message more than once. EventBridge archive/replay would appear for bus-level recovery, not for an SQS poison-message path.
Q15A checkout path uses Multi-AZ Amazon EC2 behind an ALB but then calls a single Regional third-party HTTP API synchronously with no timeout or fallback. The exam requires high availability. Counting Availability Zones on the compute tier alone would miss this dependency. Which exam habit most directly reveals this hidden availability risk?
Answer: B. End-to-end tracing finds dependencies whose failure defeats otherwise redundant compute. Counting AZs alone misses a synchronous external SPOF.

Good to know: The architecture fix is often a queue, timeout, or graceful degradation once the hidden call is visible. Do not pick extra AWS services that do not sit on that failure path.
Q16A long scenario lists optional performance wishes and one MUST: application instances stay in private subnets. Two answers look similar; one assigns public IP addresses to the application tier. The item also asks for least LEAST operational overhead among otherwise valid designs. Which step should a candidate take first under time pressure?
Answer: D. Underline hard constraints and eliminate violators first. Fewer components does not rescue a MUST-private miss. Never leave an item blank.

Good to know: After elimination, use LEAST ops or MOST cost-effective among what remains. Flag a lengthy item and return if needed, but still submit an answer.
Q17Workforce users must sign in once to many AWS accounts in an Organization that is standing up a Control Tower landing zone. They need console and CLI access to those accounts. The company does not want a separate IAM user in every account and will not share the root password. Which solution will meet these requirements?
Answer: A. The hybrid/enterprise pattern uses Organizations, Control Tower, and IAM Identity Center for workforce access across accounts. Per-account IAM users and shared root credentials violate that model.

Good to know: Amazon Cognito would be correct for application end users on a serverless API, not workforce access to the AWS Console. IAM users in one account would win only for a single-account shop.
Q18A public web application must stay up through an Availability Zone failure and absorb bursts of asynchronous report generation. Users hit HTTP on an ALB; reports may lag. The company wants Multi-AZ compute and does not want report work on the request path or on a single large instance. Which solution will meet these requirements?
Answer: C. Multi-AZ plus Auto Scaling covers AZ failure; a queue isolates bursty report work from the user path. One instance and synchronous chaining are SPOFs.

Good to know: Multi-AZ RDS would still be required if the stem also demanded a highly available relational store. Lambda workers on the queue would appear if the stem asked for least ops on the report tier.
Q19A company needs a public website that survives an Availability Zone failure, keeps the application private, and uses a managed Multi-AZ relational database. Static assets should not live on the instances. The team will not place application Elastic IPs in public subnets. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. The three-tier pattern is private Multi-AZ compute behind an ALB, Multi-AZ RDS, and S3 for static files. Public app IPs and a single-AZ database violate the constraints.

Good to know: CloudFront would sit in front if the stem required a global CDN. ElastiCache would appear if hot reads, not AZ failure, were the bottleneck.
Q20A mobile JSON API must scale with unpredictable traffic, avoid Amazon EC2 host management, and authenticate application end users rather than IAM users. Data is key-value and does not require SQL joins. The company wants the serverless API pattern. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. The serverless API pattern is API Gateway to Lambda to DynamoDB, with Cognito for end users. IAM users and EC2 hosts fail least-ops and the end-user identity model.

Good to know: SQS or EventBridge would be the extra piece if the stem required asynchronous work off the API path. RDS Proxy would appear if a relational database were mandatory behind Lambda.
Q21Domain events from an order service must fan out to three independent consumers that each need their own backlog and retry behavior. A down consumer must not block the others. The publisher must not call each consumer HTTP API in one transaction. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Fan-out is the bus or topic; per-consumer queues give durable, independent scaling and failure domains. One shared queue or synchronous HTTP couples the consumers.

Good to know: Add a DLQ on each queue when the stem requires poison-message isolation. A single queue is enough when there is only one consumer to decouple.
Q22An enterprise must connect an on-premises data center to six AWS VPCs with centralized routing and must govern new accounts with a landing zone. A peering mesh and per-account IAM users are rejected. VPN or Direct Connect can reach AWS. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. Hybrid routing is Transit Gateway behind VPN or Direct Connect. Account and workforce governance is Organizations, Control Tower, and Identity Center. Both halves of the enterprise pattern are required.

Good to know: PrivateLink would replace broad routing if the need were one service to a partner. VPC peering would suffice for two VPCs with no transit.
Q23A company in one Region has recovery objectives of hours of downtime and up to a day of data loss. It wants the MOST cost-effective Regional DR that still meets those numbers and must prove restores work. A second full-scale production site is not required. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. Loose RTO and RPO select backup and restore; untested backups do not meet the objectives. Active-active and full warm standby overspend.

Good to know: Warm standby would be the pair with failover testing if RTO were minutes. Never disable backups to save money when an RPO still exists.
Q24An order API on AWS Lambda must stay responsive when fulfillment is down, and poison fulfillment messages must not block the queue. Workers already poll from private subnets. The API must not call fulfillment synchronously inside the user request. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. A queue decouples the user path; a DLQ isolates messages that always fail. Both are required for absorb-spikes plus poison isolation.

Good to know: SNS plus per-consumer queues would appear if several independent services consumed the same event. Idempotent processing still matters with at-least once delivery.
Q25A scenario says application hosts MUST remain private and asks for the LEAST operational overhead. After dropping a public-IP option, two private designs remain: a managed Multi-AZ database and a self-managed database on Amazon EC2. The candidate must not leave the item blank. Which combination of steps should a candidate take? (Select TWO.)
Answer: A and B. Exam method: drop constraint violators first, then apply least ops to what remains. Do not pick public-IP for simplicity, and do not leave the item blank.

Good to know: If the stem had required an OS agent the managed database cannot run, the self-managed pair could survive elimination. Flag long items and return, but still submit an answer.
