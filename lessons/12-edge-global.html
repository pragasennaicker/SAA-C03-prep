01 · ARCHITECTURE DRAWING

Build DNS, CDN, and an anycast path to origin

ARCHITECTURE

Users

Global clients need a stable entry. DNS, CDN, and anycast solve different problems.

ARCHITECTURE

Route 53

Latency, failover, geolocation, weighted policies choose which endpoint to answer. DNS is not a cache.

ARCHITECTURE

CloudFront

HTTP cache at Edge Locations. TLS, WAF, and Origin Access Control belong here for web content.

ARCHITECTURE

Origin

ALB or S3 behind CloudFront. Lock the origin so clients cannot bypass the CDN.

ARCHITECTURE

Global Accelerator

Anycast IPs over the AWS backbone for TCP/UDP. It does not cache. Use it when the protocol is not HTTP or you need a static anycast entry.

ARCHITECTURE

The full edge path

Route 53 answers. CloudFront caches HTTP. Global Accelerator is the non-cache anycast path. Both still need a locked-down origin.

02 · DEEP DIVE

What you actually need to understand

1

CloudFront

  • CDN using a global edge network to cache and deliver HTTP(S) content closer to users.
  • Origins can include S3, ALBs and other HTTP endpoints.
  • Cache keys, TTLs and invalidations affect freshness and origin load.
  • Origin Access Control can keep S3 origins private while CloudFront serves content.
  • Signed URLs/cookies can restrict private content distribution.
2

Global Accelerator

  • Uses static anycast IP addresses and routes traffic over the AWS global network to healthy regional endpoints.
  • Works for TCP/UDP-style application acceleration and is not a content cache.
  • Useful when clients require fixed entry IPs and optimized global routing.
  • Health checks and endpoint weighting support failover/traffic shaping patterns.
3

Route 53

  • Authoritative DNS with alias records for AWS resources.
  • Weighted = proportional distribution.
  • Latency = select the configured AWS Region giving lowest latency to the user.
  • Failover = active/passive; Geolocation = user geography; Geoproximity = geography plus bias; Multivalue returns multiple healthy records.
4

CloudFront vs Route 53

  • Route 53 tells the client an endpoint address; DNS answers may be cached.
  • CloudFront becomes the HTTP delivery path and can cache content.
  • CloudFront itself often uses a DNS name returned through Route 53 alias records.
  • They commonly work together rather than competing.
5

Global architecture

  • Static content: S3 + CloudFront is a core pattern.
  • Dynamic global web: CloudFront can still accelerate/collapse connections even when content is not cacheable.
  • Multi-Region application endpoints can use Route 53 or Global Accelerator depending on DNS vs network-layer requirements.
  • Keep origin resources private where possible.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Private global media site

Constraint: users worldwide need low-latency downloads from a private S3 bucket. Design: CloudFront caches objects and uses origin access control to sign origin requests. Why alternatives fail: S3 website endpoints cannot use OAC, and Route 53 alone does not cache content.

1 CloudFront caches objects→2 OAC protects S3→3 HTTPS terminates at edge
WORKED SCENARIO

Global gaming endpoint

Constraint: a latency-sensitive TCP game needs static anycast IPs and rapid regional failover. Design: Global Accelerator sends traffic over the AWS backbone to healthy ALB or NLB endpoints. Why alternatives fail: CloudFront is HTTP-content oriented, while DNS failover depends on resolver caching.

1 Anycast IPs stay stable→2 Backbone reduces internet path→3 Health shifts endpoints
WORKED SCENARIO

Regional active-passive site

Constraint: a web name should use the primary region unless its endpoint is unhealthy. Design: Route 53 failover alias records and health evaluation select the secondary. Why alternatives fail: weighted routing is not inherently active-passive, and latency routing optimizes latency rather than priority.

1 Failover expresses priority→2 Health controls answers→3 Alias targets AWS resource

06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A media company stores public product images in Amazon S3 in one AWS Region. Viewers on several continents report high download latency. The company wants HTTP caching at edge locations and does not want to turn the bucket into a static website endpoint or change the object keys. Which solution will meet these requirements?
Answer: A. Global HTTP cache for static objects is CloudFront with an S3 origin. Route 53 only answers DNS. Global Accelerator is not a cache and does not take S3 as an endpoint.

Good to know: Transfer Acceleration speeds long-distance transfers to S3; it is not the CDN caching pattern. Global Accelerator would appear if clients needed static anycast IPs for TCP or UDP, not object caching.
Q2A company serves media from Amazon S3 through Amazon CloudFront. The bucket must stay private. Users must not download objects by calling Amazon S3 directly, even if they guess an object key. Signed viewer URLs are not required because this catalog is public at the CloudFront URL. Which solution will meet these requirements?
Answer: C. Origin access control lets CloudFront fetch from S3 while the bucket policy denies direct public access, so viewers cannot bypass the CDN.

Good to know: A public website endpoint would allow S3 bypass. Route 53 and Global Accelerator do not keep an S3 origin private. Signed URLs would appear if each viewer needed time-limited authorization.
Q3A training portal uses Amazon CloudFront in front of a private Amazon S3 bucket. Each learner may download one video file for 2 hours after purchase. The bucket must stay private. The company does not want IAM users for learners and will not make the object public. Which solution will meet these requirements?
Answer: B. CloudFront signed URLs grant time-limited access to a private object through the CDN without IAM users or a public bucket.

Good to know: S3 presigned URLs (Lesson 04) would apply if there were no CloudFront distribution. Signed cookies would be better if the learner needed a whole path of files, not one object.
Q4A course platform streams many private HLS segments under one CloudFront path prefix from a private Amazon S3 bucket. Issuing a signed URL per segment is too operationally heavy. Viewers should access the whole path for a limited time after login. The origin must stay private. Which solution will meet these requirements?
Answer: D. Signed cookies authorize many objects under a path through CloudFront. A single S3 presigned URL covers one object and is the wrong layer when the CDN is in front.

Good to know: Signed URLs would be correct for one file at a time. A public bucket policy would violate the private-origin constraint. DNS routing is not authorization.
Q5An Amazon CloudFront distribution caches product pages from an Application Load Balancer origin. The cache hit ratio is poor because a unique request header that the origin does not use is part of the cache key. Origin CPU is high, and the team does not want to lower TTL to 1 second. Which solution will meet these requirements?
Answer: A. Values in the cache key create cache variants. An unused unique header prevents reuse; removing it from the cache policy lets requests share objects.

Good to know: A 1-second TTL would reduce hits further. Global Accelerator does not fix HTTP cache keys. Changing the origin type does not remove the extra key field.
Q6A marketing site uses Amazon CloudFront with an Amazon S3 origin. A CSS file was overwritten under the same object key. The cache TTL is 24 hours, but the broken style must disappear worldwide within minutes. Versioned file names are not in use yet. Which solution will meet these requirements?
Answer: C. Invalidation tells CloudFront to drop a cached object before TTL expiry so edges fetch the new CSS. DNS TTL does not control HTTP cache contents.

Good to know: Versioned object keys would avoid invalidation on the next deploy. Origin access control is a privacy control, not a freshness control. Route 53 TTL only affects how long resolvers cache the CloudFront domain name.
Q7An API on an Application Load Balancer sits behind Amazon CloudFront and returns JSON that may be reused for 60 seconds. The team wants fewer origin requests without serving day-old responses. Invalidating the distribution every minute is not acceptable, and DNS must not be the cache. Which solution will meet these requirements?
Answer: B. TTL is how long CloudFront may reuse a response. Sixty seconds matches the freshness window without a 7-day stale cache or a no-cache design.

Good to know: Global Accelerator is not a content cache. Route 53 latency routing chooses a Region; it does not cache HTTP bodies. A long TTL would need invalidation or versioned URLs when content must change sooner.
Q8A company hosts a dynamic web application on Amazon EC2 behind an Application Load Balancer in one Region. Global users need HTTPS at the edge and optional caching of some paths. The origin must remain the load balancer, not a copy of HTML in Amazon S3. Which solution will meet these requirements?
Answer: D. CloudFront origins include Application Load Balancers. That keeps the dynamic app as origin while the edge handles HTTPS and optional caching.

Good to know: An S3-only origin would serve static copies, not the live ALB app. Global Accelerator in front of S3 is the wrong protocol and origin pairing. Geolocation to instance IPs skips both the load balancer and the CDN.
Q9A multiplayer game uses a custom TCP protocol on Amazon EC2 behind Network Load Balancers in two AWS Regions. Clients must be configured with two fixed IP addresses. Failover must not wait for DNS resolver caches. HTTP caching is not required for this protocol. Which solution will meet these requirements?
Answer: A. Global Accelerator provides static anycast IPs and shifts TCP traffic to healthy Regional endpoints over the AWS backbone without waiting on DNS TTL. CloudFront is an HTTP CDN, not a Layer 4 TCP proxy for a custom game protocol.

Good to know: Route 53 failover would work if DNS cache delay were acceptable and clients did not need fixed IPs. CloudFront would be correct for HTTP(S) content delivery, not this TCP game.
Q10A voice application uses UDP to Regional Network Load Balancers in two AWS Regions. The company wants traffic to enter AWS on static anycast IP addresses and ride the AWS global network to a healthy Regional endpoint. Content caching is not required for the voice packets. Which solution will meet these requirements?
Answer: C. UDP plus static anycast IPs and health-based Regional failover is Global Accelerator. CloudFront caches HTTP; it is not a UDP anycast front door.

Good to know: Route 53 geolocation would steer DNS by country but would not give static anycast IPs or a UDP network-layer path. S3 Multi-Region Access Points are for object storage, not UDP sockets.
Q11A B2B API sits behind Application Load Balancers in two Regions. Corporate firewalls allowlist two IP addresses, and corporate DNS caches answers for many minutes. When a Region fails, clients must keep those same IPs and must not wait for DNS caches to expire. Which solution will meet these requirements?
Answer: B. Allowlisted static IPs plus failover that DNS TTL must not delay is Global Accelerator. Route 53 failover still depends on resolver caches.

Good to know: A very short Route 53 TTL would reduce DNS delay but would not give two stable allowlisted anycast IPs. Signed cookies authorize CloudFront content; they are not a failover fabric.
Q12A company wants 10 percent of DNS answers to go to a new Regional Application Load Balancer and 90 percent to the existing load balancer during a canary. Active-passive failover and lowest-latency Region selection are not the goal. The records should target the two load balancers. Which solution will meet these requirements?
Answer: D. Proportional DNS distribution is weighted routing. Failover is active/passive. Latency routing picks the lowest-latency Region, not a 10/90 split.

Good to know: Failover would be correct for primary-then-secondary. Latency would be correct if users should always reach the nearer healthy Region. CloudFront cache policies do not implement DNS percentages.
Q13A company hosts a public API on Application Load Balancers in two AWS Regions. Users should reach the Region that offers the lowest latency to them. DNS-based steering is acceptable, and the company does not need a fixed percentage split or an active-passive pair. Which solution will meet these requirements?
Answer: A. Latency-based routing selects the configured resource in the Region with the lowest latency measurement to the user. Weighted 50/50 is a split, not a latency choice.

Good to know: Geolocation would be correct if the rule were country or continent of the viewer rather than measured latency. Failover would be correct for active-passive priority.
Q14A web hostname should use the primary Region unless that Application Load Balancer is unhealthy, then it should use the secondary Region. Weighted splits and latency optimization are not required. The records should target the two load balancers with health evaluation in Route 53. Which solution will meet these requirements?
Answer: C. Active/passive DNS with health evaluation is failover routing. Equal weights and latency policies do not express a primary-then-secondary priority.

Good to know: Weighted routing would be correct for a canary. Latency routing would be correct if the nearest healthy Region should win. Geoproximity would be correct if the team needed a geographic bias around resource locations.
Q15A company must serve a country-specific homepage from a Regional origin that holds that country's content. Routing must follow the viewer's geography, not the lowest-latency AWS Region and not a 50/50 DNS split. Both origins already sit behind Application Load Balancers. A default record is allowed. Which solution will meet these requirements?
Answer: B. Geolocation routing answers based on the location of the DNS query, which is how you pin a country to a specific origin. Latency routing would ignore those content boundaries.

Good to know: Geoproximity would be closer if the team wanted to bias traffic around resource locations rather than map ISO countries. Failover is active/passive priority, not country mapping.
Q16A company wants DNS to prefer a nearby AWS Region for Application Load Balancers in two Regions, but will shift extra traffic toward a new Region that has spare capacity. Country-level content laws are not involved, and a fixed 90/10 weight is not required. Which solution will meet these requirements?
Answer: D. Geoproximity routes by the location of resources and a bias expands or shrinks how much of the map a Region wins. That is the spare-capacity shift without hand-mapping countries.

Good to know: Geolocation would be correct for country or continent content rules. Weighted routing would be correct for an explicit percentage split. Failover would be correct for active/passive.
Q17A company uses Amazon Route 53 to point www.example.com at an Application Load Balancer. Global users still wait on every image because nothing caches HTTP responses. DNS already resolves quickly. The team wants an HTTP delivery path at the edge while keeping the existing hostname. Which solution will meet these requirements?
Answer: A. Route 53 answers DNS; it does not cache HTTP bodies. CloudFront is the HTTP path that caches at edge locations. They commonly work together with an alias to the distribution.

Good to know: A 1-second DNS TTL only changes how long resolvers cache the name. Multivalue and extra latency records still return addresses; they do not become a CDN.
Q18A company wants Amazon Route 53 to return several healthy IP addresses for a small fleet and to omit unhealthy ones. It does not need weighted percentages or latency-based Region choice. The fleet is small enough that a full load balancer is not required. Which solution will meet these requirements?
Answer: C. Multivalue answer routing returns multiple healthy records, like DNS round-robin with health checks. It is not a substitute for a load balancer on a large fleet, which this stem excludes.

Good to know: Failover returns one active endpoint. Weighted routing is for proportions. An Application Load Balancer would be the answer if the stem needed Layer 7 routing or a large fleet.
Q19Users worldwide need low-latency downloads from a private Amazon S3 bucket in one Region. The bucket must stay private, and users must not bypass the CDN by calling S3 directly even if they know the object key. Signed viewer URLs are not required. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. CloudFront caches at the edge. Origin access control plus a restrictive bucket policy keeps S3 private so clients cannot skip the distribution.

Good to know: S3 website endpoints cannot use origin access control and a public policy would allow bypass. Global Accelerator does not take S3 as an endpoint and does not cache objects.
Q20A media site uses Amazon CloudFront in front of Amazon S3. Authorized viewers must open private files for a limited time after login. The bucket must remain private, and the company will not create IAM users for those viewers. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. Private origin plus CloudFront signed URLs or cookies is the private-content pattern. A public bucket or IAM keys for each viewer would violate the constraints.

Good to know: Signed URLs fit one object; signed cookies fit a path of objects. Route 53 routing is not an authorization mechanism.
Q21An Amazon CloudFront distribution has a low cache hit ratio and a high origin load. A unique unused request header is in the cache key, and the default TTL is 7 days even though the API may be reused for only 2 minutes. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Hit ratio improves when the cache key only includes values that actually change the response, and when TTL matches the freshness window.

Good to know: Adding more unique headers would worsen fragmentation. Per-second invalidations fight the cache instead of tuning it. Route 53 failover is DNS, not an HTTP cache.
Q22A custom TCP application behind Network Load Balancers in two AWS Regions must present two static anycast IP addresses to game clients. Failover must not depend on DNS resolver caches. HTTP caching is not in scope, and clients cannot change IP allowlists. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. Global Accelerator supplies the anycast IPs and uses health checks to move new connections to a healthy Regional endpoint over the AWS global network.

Good to know: CloudFront is HTTP(S). Route 53 failover still waits on DNS caches. Transfer Acceleration is for S3 transfers, not arbitrary TCP.
Q23A website name should use a primary Regional Application Load Balancer unless it is unhealthy, then a secondary load balancer in another Region. The company does not want a 50/50 DNS split during healthy operation. Both load balancers already exist. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. Active/passive DNS is failover records plus a health check on the primary. Weighted 50/50 is a split. Invalidation refreshes cache, it does not fail over a Region.

Good to know: Latency routing would be correct if the nearest healthy Region should win. Geolocation would be correct for country-based content, not priority failover.
Q24Operations wants 90 percent of DNS answers to stay on the current Application Load Balancer and 10 percent to hit a new Regional load balancer during a gradual release. Failover and lowest-latency Region selection are not required. Both load balancers already exist. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Weighted records plus the actual 90 and 10 weights are the two steps that implement a DNS canary. Multivalue answer does not express percentages.

Good to know: Failover would make the new endpoint take all traffic when marked primary. Geoproximity bias shifts geographic share, not an explicit 90/10 split.
Q25A company hosts a public static website in Amazon S3 in one Region. Global users need low latency, and the hostname www.example.com must keep working. The team wants DNS to point at an HTTP cache, not at the bucket URL alone. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. Static global content is S3 plus CloudFront. Route 53 alias records commonly point the hostname at the distribution. DNS does not cache HTTP bodies.

Good to know: Global Accelerator is anycast TCP/UDP acceleration, not an object cache. Serving the S3 website URL alone would skip edge caching.
