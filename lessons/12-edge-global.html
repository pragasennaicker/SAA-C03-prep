01 · ARCHITECTURE DRAWING

Build DNS, CDN, and an anycast path to origin

ARCHITECTURE

Users

Global clients need a stable entry. DNS, CDN, and anycast solve different problems.

ARCHITECTURE

Route 53

Latency, failover, geolocation, weighted policies choose which endpoint to answer. DNS is not a cache.

ARCHITECTURE

CloudFront

HTTP cache at Edge Locations. TLS, WAF, and Origin Access Control belong here for web content.

ARCHITECTURE

Origin

ALB or S3 behind CloudFront. Lock the origin so clients cannot bypass the CDN.

ARCHITECTURE

Global Accelerator

Anycast IPs over the AWS backbone for TCP/UDP. It does not cache. Use it when the protocol is not HTTP or you need a static anycast entry.

ARCHITECTURE

The full edge path

Route 53 answers. CloudFront caches HTTP. Global Accelerator is the non-cache anycast path. Both still need a locked-down origin.

02 · DEEP DIVE

What you actually need to understand

1

CloudFront

  • CDN using a global edge network to cache and deliver HTTP(S) content closer to users.
  • Origins can include S3, ALBs and other HTTP endpoints.
  • Cache keys, TTLs and invalidations affect freshness and origin load.
  • Origin Access Control can keep S3 origins private while CloudFront serves content.
  • Signed URLs/cookies can restrict private content distribution.
2

Global Accelerator

  • Uses static anycast IP addresses and routes traffic over the AWS global network to healthy regional endpoints.
  • Works for TCP/UDP-style application acceleration and is not a content cache.
  • Useful when clients require fixed entry IPs and optimized global routing.
  • Health checks and endpoint weighting support failover/traffic shaping patterns.
3

Route 53

  • Authoritative DNS with alias records for AWS resources.
  • Weighted = proportional distribution.
  • Latency = select the configured AWS Region giving lowest latency to the user.
  • Failover = active/passive; Geolocation = user geography; Geoproximity = geography plus bias; Multivalue returns multiple healthy records.
4

CloudFront vs Route 53

  • Route 53 tells the client an endpoint address; DNS answers may be cached.
  • CloudFront becomes the HTTP delivery path and can cache content.
  • CloudFront itself often uses a DNS name returned through Route 53 alias records.
  • They commonly work together rather than competing.
5

Global architecture

  • Static content: S3 + CloudFront is a core pattern.
  • Dynamic global web: CloudFront can still accelerate/collapse connections even when content is not cacheable.
  • Multi-Region application endpoints can use Route 53 or Global Accelerator depending on DNS vs network-layer requirements.
  • Keep origin resources private where possible.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Private global media site

Constraint: users worldwide need low-latency downloads from a private S3 bucket. Design: CloudFront caches objects and uses origin access control to sign origin requests. Why alternatives fail: S3 website endpoints cannot use OAC, and Route 53 alone does not cache content.

1 CloudFront caches objects→2 OAC protects S3→3 HTTPS terminates at edge
WORKED SCENARIO

Global gaming endpoint

Constraint: a latency-sensitive TCP game needs static anycast IPs and rapid regional failover. Design: Global Accelerator sends traffic over the AWS backbone to healthy ALB or NLB endpoints. Why alternatives fail: CloudFront is HTTP-content oriented, while DNS failover depends on resolver caching.

1 Anycast IPs stay stable→2 Backbone reduces internet path→3 Health shifts endpoints
WORKED SCENARIO

Regional active-passive site

Constraint: a web name should use the primary region unless its endpoint is unhealthy. Design: Route 53 failover alias records and health evaluation select the secondary. Why alternatives fail: weighted routing is not inherently active-passive, and latency routing optimizes latency rather than priority.

1 Failover expresses priority→2 Health controls answers→3 Alias targets AWS resource

06 · KNOWLEDGE CHECK

Five SAA-style questions

Q1A company serves private S3 objects globally and wants users unable to bypass the CDN by calling S3 directly. Which configuration is recommended?
Answer: A. OAC lets CloudFront sign S3 origin requests while the bucket policy denies direct public access.
Q2A global TCP application needs two fixed anycast IP addresses and fast endpoint failover unaffected by DNS caches. Which service should front it?
Answer: B. Global Accelerator supplies static anycast IPs and routes new connections to healthy endpoints over the AWS global network.
Q3Users should resolve to the AWS Region offering the lowest measured network latency, and DNS-based steering is acceptable. Which Route 53 policy fits?
Answer: B. Latency-based routing chooses the configured resource in the Region that provides the lowest latency measurement.
Q4A CloudFront distribution has poor cache hit ratio because an unused unique request header is in the cache key. What change most directly improves reuse?
Answer: A. Values included in the cache key create cache variants; removing an irrelevant unique header allows requests to share objects.
Q5A company wants to direct 10% of DNS responses to a new endpoint and 90% to the old endpoint during a gradual release. Which policy is designed for this?
Answer: B. Weighted records distribute DNS responses according to relative weights and are commonly used for controlled traffic shifts.
