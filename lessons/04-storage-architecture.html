01 · ARCHITECTURE DRAWING

Build block, file, and object in one workload

ARCHITECTURE

VPC

Storage choice follows the access pattern: one instance, many instances, or no instance at all.

ARCHITECTURE

EBS

EBS is zonal block storage attached to one instance (or Multi-Attach where supported). Snapshot it; it does not span AZs by itself.

ARCHITECTURE

EFS

EFS is shared POSIX across AZs. Use it when many instances must mount the same file system.

ARCHITECTURE

Amazon S3

Object storage. Durability is regional. It is not a file system and not a boot volume.

ARCHITECTURE

S3 Lifecycle

Lifecycle and Intelligent-Tiering are explicit. Objects do not move to Glacier by default.

ARCHITECTURE

FSx

Windows SMB, Lustre, NetApp, or OpenZFS when the workload needs a native file protocol that EFS does not provide.

ARCHITECTURE

Cross-Region Replication

CRR is opt-in. It is not a substitute for versioning, and it is not on by default.

ARCHITECTURE

The full storage picture

One EC2 uses EBS; many EC2s share EFS; objects land in S3 with lifecycle and optional CRR. FSx covers native Windows or HPC file protocols.

02 · DEEP DIVE

What you actually need to understand

1

S3 fundamentals

  • Object storage addressed by bucket/key rather than block or POSIX file semantics.
  • Versioning protects against accidental overwrite/delete and supports replication use cases.
  • Lifecycle rules transition or expire objects according to age/access pattern.
  • Replication can copy objects within or across Regions according to requirements.
  • Presigned URLs grant time-limited object access without making a bucket public.
2

S3 storage classes

  • Standard fits frequent access.
  • Intelligent-Tiering automatically moves eligible objects between access tiers based on observed access and is useful for unknown/changing patterns.
  • Standard-IA and One Zone-IA fit infrequent access with retrieval charges; One Zone trades AZ resilience for lower cost.
  • Glacier Instant Retrieval / Flexible Retrieval / Deep Archive cover increasingly archival access patterns with different retrieval trade-offs.
3

EBS

  • Persistent block storage for EC2 in one AZ.
  • gp3 is a common general-purpose SSD choice because capacity and performance can be provisioned independently.
  • io-class SSD fits demanding IOPS/latency workloads; HDD classes fit large sequential workloads where appropriate.
  • Snapshots provide point-in-time backup and can restore volumes in other AZs/Regions after copy.
4

EFS + FSx

  • EFS is elastic NFS-style shared storage for Linux workloads and can span AZs through mount targets.
  • EFS performance/throughput modes should match access patterns.
  • FSx for Windows File Server provides managed SMB/Windows integration.
  • FSx for Lustre targets high-performance parallel file workloads; other FSx families serve ONTAP/OpenZFS use cases.
5

Data protection

  • AWS Backup can centralize backup plans and retention across supported services.
  • Encryption at rest commonly integrates with KMS.
  • Cross-Region/cross-account backup strategies can improve protection from regional or account-level incidents.
  • Recovery requirements—not backup creation alone—should drive architecture.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Share files across AZs

A Linux web fleet in three AZs needs concurrent POSIX file access and automatic capacity growth. Mount regional EFS through mount targets in each AZ. EBS volumes are zonal and generally not a shared multi-AZ filesystem, while S3 does not provide native POSIX semantics.

1 Regional NFS→2 Concurrent access→3 Elastic capacity
WORKED SCENARIO

Retain rarely retrieved records

Compliance records must remain for seven years, are almost never read, and can tolerate hours before retrieval. Use S3 Glacier Deep Archive with lifecycle transitions and retention controls as required. S3 Standard pays for immediate access that is not needed, while EBS requires provisioned block capacity.

1 Lowest archive cost→2 Long retention→3 Hours acceptable
WORKED SCENARIO

Migrate an SMB namespace

Windows applications require managed SMB shares, Active Directory integration, and native Windows file features. Use Amazon FSx for Windows File Server joined to the directory. EFS exposes NFS rather than SMB, and S3 object storage cannot preserve normal SMB filesystem behavior.

1 Native SMB→2 AD integrated→3 Windows features

Words in the question that should trigger a design instinct

“millions/billions of objects”
→ S3.
“boot volume / block device”
→ EBS.
“shared Linux file system”
→ EFS.
“SMB / Windows file shares”
→ FSx Windows.
“unknown access pattern”
→ S3 Intelligent-Tiering is often attractive.
“archive for years”
→ Glacier classes.
06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A media company runs transcoding workers on Amazon EC2 instances in three Availability Zones. Every worker must read and write the same project files at the same time using POSIX file semantics. The dataset grows without a planned size, and the company does not want to manage file-server instances. The workers stay in private subnets. Which solution will meet these requirements?
Answer: A. Concurrent multi-AZ POSIX access and elastic capacity select Amazon EFS. A single EBS volume stays in one AZ and is not a shared regional file system.

Good to know: FSx for Lustre would be the answer if the stem demanded a parallel HPC file system integrated with S3. Glacier is archive object storage, not a POSIX mount.
Q2A research lab runs tightly coupled high-performance computing jobs on Amazon EC2 in one VPC. The jobs need a parallel file system with very high throughput and must read training datasets that already live in Amazon S3. Operators want a managed file service rather than building Lustre on instances. Which solution will meet these requirements?
Answer: C. Parallel HPC I/O plus S3 integration is the FSx for Lustre pattern. EFS is elastic NFS for Linux, not a Lustre-style parallel file system.

Good to know: FSx for Windows File Server is the SMB and Active Directory answer. EBS HDD classes fit sequential block workloads on a single instance, not a shared HPC namespace.
Q3A company hosts a latency-sensitive relational database on a single Amazon EC2 instance. The database needs durable block storage with consistent low-latency IOPS. The instance and its data will remain in one Availability Zone. Other instances must not mount the same volume as shared storage. Which solution will meet these requirements?
Answer: B. A single-AZ database that needs attached block semantics and predictable IOPS is an EBS io-class (or similarly provisioned SSD) volume. S3 and EFS are not local block devices for that engine.

Good to know: gp3 is the usual general-purpose SSD when capacity and performance can be set independently. Choose io-class when the stem stresses demanding IOPS or latency.
Q4A software vendor stores user-uploaded objects in Amazon S3. Access frequency varies by customer and changes over time, so the team cannot pick a fixed lifecycle day. Objects must stay immediately available over HTTP. Operations wants Amazon S3 to move objects between access tiers automatically. Which solution will meet these requirements?
Answer: D. Unknown or changing access plus immediate availability is Intelligent-Tiering. Deep Archive requires a restore and is not immediately readable.

Good to know: One Zone-IA would be cheaper infrequent access only if the stem accepted a single-AZ durability trade-off. EBS is block storage for an instance, not an object store for user downloads.
Q5A company is retiring an on-premises Windows file cluster used by desktop applications in one office. Those applications need managed SMB shares, Microsoft Active Directory authentication, and Windows access-control lists. Linux NFS is not in use. The company wants AWS to operate the file servers rather than EC2 file VMs. Which solution will meet these requirements?
Answer: A. SMB, Active Directory, and Windows ACLs are the FSx for Windows File Server constraints. EFS is NFS for Linux, not a Windows-native SMB service.

Good to know: S3 File Gateway (Lesson 14) would appear if the stem wanted a hybrid local NFS or SMB cache in front of S3. EBS Multi-Attach is not a Windows file namespace and is not taught as the SMB answer.
Q6A marketing site stores millions of product images as objects. The images are read many times per day from a public website and a mobile app. The company needs eleven nines of durability and does not want retrieval delays or restore jobs. Which Amazon S3 storage class should a solutions architect choose?
Answer: C. Frequent object access with immediate reads is S3 Standard. Glacier classes are archive economics for rarely retrieved data.

Good to know: Intelligent-Tiering would win if access were unknown or changing. Instant Retrieval fits archive objects that are rarely read but must still open in milliseconds when they are.
Q7A hospital must keep medical images for seven years to meet a retention rule. Staff retrieve an object only a few times per year and can wait hours for a restore. The hospital wants the lowest storage cost among Amazon S3 archive classes and does not need millisecond access. Which solution will meet these requirements?
Answer: B. Years of retention, rare retrieval, and hours of restore time select Glacier Deep Archive. Standard-IA and Intelligent-Tiering keep objects immediately available at a higher storage price.

Good to know: Glacier Flexible Retrieval is the middle archive class when restore in minutes to hours is acceptable but Deep Archive’s longer restore is not. Instant Retrieval is the millisecond archive class.
Q8An Amazon EC2 database uses a 2 TB Amazon EBS volume in Availability Zone A. The company needs point-in-time backups and must be able to create a new volume in Availability Zone B in the same Region if Zone A fails. Operators will attach the new volume to a replacement instance. Which solution will meet these requirements?
Answer: D. EBS snapshots are the point-in-time backup for volumes and can restore a volume in another AZ in the Region after the snapshot exists.

Good to know: Cross-Region copy of snapshots is the next step if the stem required a second Region. Instance store is ephemeral and is not a backup. S3 versioning does not apply to EBS volumes.
Q9A partner application must download a private report object from Amazon S3 for 15 minutes after a user clicks a link in a portal. The bucket must stay private. The company does not want to create IAM users for partners, does not want to make the object public, and will not change the partner application beyond the download URL. Which solution will meet these requirements?
Answer: A. Presigned URLs grant time-limited object access without making the bucket public. A public bucket policy would violate the private-bucket constraint.

Good to know: CloudFront signed URLs (Lesson 12) would appear if the stem required a global CDN in front of private S3. Transfer Acceleration speeds uploads over long distances; it is not an authorization mechanism.
Q10Analysts overwrite objects in an Amazon S3 data lake with the same key when they republish a dataset. Last month a bad publish replaced a week of results and the previous object was gone. The company must be able to recover the prior object after an overwrite or delete. Which solution will meet these requirements?
Answer: C. Versioning keeps prior object versions after overwrite or delete so they can be restored. Storage class and Transfer Acceleration do not retain old keys.

Good to know: Replication can copy versions to another bucket or Region once versioning is on. Lifecycle rules then expire old versions when retention allows.
Q11A company stores application logs as objects in Amazon S3 Standard in one bucket. After 90 days the logs are almost never read, and legal still requires them for four years. Restores may take hours. Operations wants Amazon S3 to move objects automatically based on age and does not want a nightly copy job. Which solution will meet these requirements?
Answer: B. Known age plus rare access and long retention is a lifecycle transition into a Glacier archive class. Intelligent-Tiering is for unknown access, not a fixed 90-day archive handoff.

Good to know: If the stem said access patterns were unknown, Intelligent-Tiering would be the better automatic-tiering answer. Replication copies objects; it does not change storage class by age.
Q12A backup application writes large objects to Amazon S3. Objects are read only a few times a month but must remain immediately available. The company can accept storing them in a single Availability Zone to reduce cost. A zone failure may require rebuilding the backups from the source. Which storage class will meet these requirements?
Answer: D. Infrequent access, immediate reads, and an explicit single-AZ cost trade-off select One Zone-IA. Standard-IA still stores across AZs; Deep Archive is not immediately available.

Good to know: Standard-IA is the answer when infrequent access must still survive an Availability Zone failure. Standard is the frequent-access default.
Q13An Amazon EC2 application uses a 1 TB general-purpose SSD volume as its only data disk. Sequential throughput is already fine, but the application now needs more random IOPS. The team does not want to grow the volume solely to get more performance. Capacity must stay 1 TB. Which solution will meet these requirements?
Answer: A. gp3 lets capacity and performance be provisioned independently, which is the constraint against oversizing the disk just for IOPS.

Good to know: io-class SSD is the next step if even gp3 cannot meet the IOPS or latency target. HDD classes are for large sequential I/O, not higher random IOPS.
Q14A video archive sits in Amazon S3 in a single bucket. Producers sometimes need an object within milliseconds, but each object is retrieved only a few times per quarter. The company wants archive storage pricing rather than S3 Standard. Multi-hour restore jobs are not acceptable for the production workflow. Which storage class will meet these requirements?
Answer: C. Rare retrieval that must still open in milliseconds is Glacier Instant Retrieval. Flexible Retrieval and Deep Archive require a restore job.

Good to know: One Zone-IA is infrequent access in a single AZ, not an archive class with Glacier pricing. Flexible Retrieval fits when minutes-to-hours restore is fine.
Q15A company uses Amazon EBS volumes on EC2, Amazon EFS file systems, and Amazon RDS instances in one AWS account. Compliance wants one backup plan, one retention schedule, and centralized restore history across those services. Teams must not keep separate snapshot scripts per service. Which solution will meet these requirements?
Answer: B. AWS Backup centralizes backup plans and retention across supported services. S3 Versioning does not protect EBS, EFS, or RDS as a unified plan.

Good to know: Cross-Region or cross-account copies in AWS Backup are the follow-on when the stem adds a regional or account-isolation recovery requirement.
Q16An Amazon EC2 worker writes unique results to local disk during a 12-hour batch job in a private subnet. If the instance is stopped or the underlying host fails, those results must still exist so a replacement instance can continue. The job is not a tightly coupled HPC cluster and does not need a shared file system. Which solution will meet these requirements?
Answer: D. Unique durable data belongs on EBS, which persists independently of the instance unless delete-on-termination is set. Instance store is wiped on stop, terminate, or host failure.

Good to know: Lesson 03 already established that instance store is ephemeral. This item tests the storage choice: EBS for durable block data on a single instance.
Q17A company stores objects in a versioned Amazon S3 bucket in the US East (N. Virginia) Region. A regulator requires a second copy in the Europe (Ireland) Region that updates as objects are written. Operations must not run a nightly sync job on EC2 and must not download the objects to EBS. Which solution will meet these requirements?
Answer: A. S3 Replication copies objects within or across Regions according to the rule. Versioning on the source is the usual prerequisite for replication.

Good to know: AWS Backup is the cross-service backup answer. EFS does not replicate an S3 object namespace to another Region by mounting it.
Q18A genomics pipeline writes multi-terabyte sequential files from a single Amazon EC2 instance in one Availability Zone. The instance needs a large block volume optimized for throughput rather than random IOPS. The data must persist if the instance is stopped. No other instance will mount the volume. Which solution will meet these requirements?
Answer: C. Large sequential block I/O on one instance is the HDD EBS class (st1). io-class SSD is for demanding random IOPS and latency, which this stem does not ask for.

Good to know: EFS would be correct if multiple Linux instances needed a shared NFS namespace. Glacier Instant Retrieval is object archive, not an attached block device.
Q19Linux application servers in three Availability Zones must share a POSIX file system that grows automatically. Each AZ must keep working if another AZ fails. The company will not manage NFS servers on Amazon EC2 and will not use Windows SMB. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. EFS is the elastic multi-AZ NFS service, and mount targets in each AZ give zonal access without a self-managed NFS farm. Those two steps are jointly required.

Good to know: EBS Multi-Attach does not span three AZs as a POSIX file service. FSx for Windows is SMB. A fuse S3 mount is not the managed POSIX answer the lesson teaches.
Q20A data lake in Amazon S3 is overwritten in place when pipelines republish partitions. The company must recover a previous object after a bad publish and must also keep a copy of new objects in a second Region for disaster recovery. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. Versioning retains prior objects after overwrite. Replication then copies those objects (and typically requires versioning) to the second Region.

Good to know: Lifecycle rules would transition old versions to archive after recovery windows expire. Deep Archive on upload would fight immediate lake queries.
Q21A database on Amazon EC2 in one Availability Zone needs durable SSD block storage and nightly point-in-time backups. If the zone fails, operators will launch a replacement instance in a second AZ and attach a restored volume. The engine cannot use a shared NFS data directory. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Durable low-latency block storage is EBS, and snapshots are how you restore that volume in another AZ. Instance store cannot be snapshotted as durable database storage.

Good to know: EFS is shared NFS, not a typical database data directory. Intelligent-Tiering is an S3 storage class, not an EBS setting.
Q22A company is moving a Windows department share to AWS. Desktop applications in the office require SMB, NTFS-style access-control lists, and authentication against the existing Microsoft Active Directory. The company wants a managed file system in AWS and will not operate file-server instances. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. FSx for Windows File Server is the managed SMB service, and directory join supplies the AD authentication the desktops already depend on.

Good to know: EFS is Linux NFS. A self-managed iSCSI EBS share is not the managed Windows file service the stem asks for.
Q23Compliance requires a single backup policy for Amazon EBS volumes and Amazon EFS file systems, with 35-day retention. Recovery must still work if the workload account is compromised, so copies must land in a separate AWS account in a second Region. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. AWS Backup is the centralized plan across supported services, and cross-account plus cross-Region copies reduce blast radius from a compromised workload account.

Good to know: S3 Versioning does not back up EBS or EFS. Moving data to Glacier changes the storage type; it does not implement the backup policy the stem described.
Q24A simulation cluster on Amazon EC2 needs a high-throughput parallel file system. Input datasets already reside in Amazon S3 and must be readable from the file system without a manual copy farm. The team will not operate Lustre on self-managed instances. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. FSx for Lustre is the managed parallel file system, and the S3 link is how those datasets are presented without a home-grown copy fleet.

Good to know: EFS is the general Linux NFS answer. FSx for Windows does not have a Lustre mode. EBS HDD is single-instance sequential block storage.
Q25A partner portal stores private PDF objects in Amazon S3. Each download link must work for 10 minutes and must not require an IAM user for the partner. The bucket must remain private, and objects must not be readable with a guessable key. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. A private bucket plus a short-lived presigned URL is the lesson’s time-limited access pattern. Website hosting or a public policy would make objects world-readable.

Good to know: CloudFront signed cookies (Lesson 12) would appear if the stem required a CDN in front of private content. Transfer Acceleration is a transfer-speed feature, not an access-control feature.
