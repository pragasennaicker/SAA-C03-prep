01 · ARCHITECTURE DRAWING

Build block, file, and object in one workload

ARCHITECTURE

VPC

Storage choice follows the access pattern: one instance, many instances, or no instance at all.

ARCHITECTURE

EBS

EBS is zonal block storage attached to one instance (or Multi-Attach where supported). Snapshot it; it does not span AZs by itself.

ARCHITECTURE

EFS

EFS is shared POSIX across AZs. Use it when many instances must mount the same file system.

ARCHITECTURE

Amazon S3

Object storage. Durability is regional. It is not a file system and not a boot volume.

ARCHITECTURE

S3 Lifecycle

Lifecycle and Intelligent-Tiering are explicit. Objects do not move to Glacier by default.

ARCHITECTURE

FSx

Windows SMB, Lustre, NetApp, or OpenZFS when the workload needs a native file protocol that EFS does not provide.

ARCHITECTURE

Cross-Region Replication

CRR is opt-in. It is not a substitute for versioning, and it is not on by default.

ARCHITECTURE

The full storage picture

One EC2 uses EBS; many EC2s share EFS; objects land in S3 with lifecycle and optional CRR. FSx covers native Windows or HPC file protocols.

02 · DEEP DIVE

What you actually need to understand

1

S3 fundamentals

  • Object storage addressed by bucket/key rather than block or POSIX file semantics.
  • Versioning protects against accidental overwrite/delete and supports replication use cases.
  • Lifecycle rules transition or expire objects according to age/access pattern.
  • Replication can copy objects within or across Regions according to requirements.
  • Presigned URLs grant time-limited object access without making a bucket public.
2

S3 storage classes

  • Standard fits frequent access.
  • Intelligent-Tiering automatically moves eligible objects between access tiers based on observed access and is useful for unknown/changing patterns.
  • Standard-IA and One Zone-IA fit infrequent access with retrieval charges; One Zone trades AZ resilience for lower cost.
  • Glacier Instant Retrieval / Flexible Retrieval / Deep Archive cover increasingly archival access patterns with different retrieval trade-offs.
3

EBS

  • Persistent block storage for EC2 in one AZ.
  • gp3 is a common general-purpose SSD choice because capacity and performance can be provisioned independently.
  • io-class SSD fits demanding IOPS/latency workloads; HDD classes fit large sequential workloads where appropriate.
  • Snapshots provide point-in-time backup and can restore volumes in other AZs/Regions after copy.
4

EFS + FSx

  • EFS is elastic NFS-style shared storage for Linux workloads and can span AZs through mount targets.
  • EFS performance/throughput modes should match access patterns.
  • FSx for Windows File Server provides managed SMB/Windows integration.
  • FSx for Lustre targets high-performance parallel file workloads; other FSx families serve ONTAP/OpenZFS use cases.
5

Data protection

  • AWS Backup can centralize backup plans and retention across supported services.
  • Encryption at rest commonly integrates with KMS.
  • Cross-Region/cross-account backup strategies can improve protection from regional or account-level incidents.
  • Recovery requirements—not backup creation alone—should drive architecture.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Share files across AZs

A Linux web fleet in three AZs needs concurrent POSIX file access and automatic capacity growth. Mount regional EFS through mount targets in each AZ. EBS volumes are zonal and generally not a shared multi-AZ filesystem, while S3 does not provide native POSIX semantics.

1 Regional NFS→2 Concurrent access→3 Elastic capacity
WORKED SCENARIO

Retain rarely retrieved records

Compliance records must remain for seven years, are almost never read, and can tolerate hours before retrieval. Use S3 Glacier Deep Archive with lifecycle transitions and retention controls as required. S3 Standard pays for immediate access that is not needed, while EBS requires provisioned block capacity.

1 Lowest archive cost→2 Long retention→3 Hours acceptable
WORKED SCENARIO

Migrate an SMB namespace

Windows applications require managed SMB shares, Active Directory integration, and native Windows file features. Use Amazon FSx for Windows File Server joined to the directory. EFS exposes NFS rather than SMB, and S3 object storage cannot preserve normal SMB filesystem behavior.

1 Native SMB→2 AD integrated→3 Windows features

06 · KNOWLEDGE CHECK

Five SAA-style questions

Q1Linux instances in three AZs need simultaneous access to a shared POSIX filesystem that grows automatically. Which storage service is appropriate?
Answer: B. The deciding constraints are concurrent multi-AZ NFS access and elastic capacity. EFS is a regional managed filesystem built for this pattern.
Q2A high-performance computing workload needs a parallel filesystem integrated with S3 and optimized for very high throughput. Which service should be selected?
Answer: C. The deciding constraints are parallel HPC I/O and S3 integration. FSx for Lustre is optimized for this workload.
Q3An EC2 database needs durable low-latency block storage, and the instance and volume will remain in one Availability Zone. Which choice fits?
Answer: D. The deciding constraints are attached block semantics and predictable low-latency IOPS. Provisioned IOPS EBS is designed for such databases.
Q4Objects are accessed with unpredictable frequency, must remain immediately available, and should automatically move to the cheapest suitable access tier. What fits?
Answer: A. The deciding constraints are unknown access patterns and immediate availability. Intelligent-Tiering monitors access and moves objects among eligible tiers.
Q5A Windows application requires managed SMB shares, Active Directory authentication, and Windows ACL support. Which service meets all requirements?
Answer: B. The deciding constraints are SMB, AD, and Windows ACL semantics. FSx for Windows File Server natively provides them.
