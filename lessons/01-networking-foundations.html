01 · VISUAL MODEL

See the architecture before memorising the services

①Route before reachability

Trace the subnet route table first: an internet gateway serves public IPv4 paths, while a NAT gateway gives private subnets outbound-only internet access.

②State lives in security groups

Security groups are stateful and attach to ENIs; network ACLs are stateless subnet boundaries, so return traffic must be allowed explicitly.

③Private service paths

Gateway endpoints keep S3 and DynamoDB traffic off NAT, while interface endpoints use PrivateLink ENIs and security groups for supported services.

④Availability by AZ

A NAT gateway is zonal. Place one per active Availability Zone and route each private subnet locally to avoid cross-AZ dependency and charges.

02 · DEEP DIVE

What you actually need to understand

1

VPC + CIDR

  • The VPC CIDR is the private address space for the network.
  • Subnets are carved from that space and belong to one Availability Zone.
  • Plan non-overlapping CIDRs when future peering, Transit Gateway or hybrid routing is likely.
  • IPv4 routing uses longest-prefix match: the most specific matching route wins.
2

Public vs private subnets

  • A subnet is public because its route table has a route to an Internet Gateway.
  • An instance also needs a public IPv4 address or Elastic IP plus permissive security controls to be directly internet reachable.
  • A private subnet normally has no direct IGW route.
  • Public ALBs and NAT Gateways normally live in public subnets; application/database tiers normally live in private subnets.
3

IGW + NAT Gateway

  • An Internet Gateway is attached to the VPC and enables internet routing for public resources.
  • A NAT Gateway enables private IPv4 resources to initiate outbound internet connections.
  • The NAT Gateway itself sits in a public subnet and uses an Elastic IP for public IPv4 egress.
  • For resilience, use a NAT Gateway per AZ and route each private subnet to its same-AZ NAT.
4

Security Group vs NACL

  • Security Groups are stateful: allowed request traffic automatically permits the response path.
  • Security Groups contain allow rules, not explicit deny rules.
  • Network ACLs are stateless and are evaluated at the subnet boundary.
  • NACLs support allow and deny rules and require return-path rules, including ephemeral ports where relevant.
5

VPC endpoints

  • Gateway endpoints are especially important for S3 and DynamoDB.
  • Interface endpoints use private ENIs and AWS PrivateLink for many AWS services.
  • Endpoints keep supported service traffic private and may avoid NAT processing/data-path cost.
  • Endpoint policies can further restrict permitted actions/resources.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Reach S3 without NAT

Private EC2 instances need S3 access but must not traverse the internet or pay NAT processing charges. Add an S3 gateway endpoint and restrict its endpoint policy and bucket policy. An internet gateway does not make private instances reachable, and an interface endpoint adds unnecessary hourly cost here.

1 No public path →2 No NAT charge →3 Policy controlled
WORKED SCENARIO

Resilient private-subnet egress

A two-AZ workload needs outbound patch access and must survive one AZ failure. Deploy a NAT gateway in each AZ and point each private subnet at its local NAT. One shared NAT creates an AZ dependency, while an internet gateway cannot provide outbound access to instances without public addresses.

1 AZ independent →2 Outbound only →3 Local routing
WORKED SCENARIO

Block a hostile CIDR

Administrators must deny a known CIDR across every instance in a subnet while retaining application security groups. Add an explicit deny in the subnet network ACL and allow required return ports. Security groups have no deny rules, and route tables are not packet-filtering policy.

1 Explicit deny →2 Subnet scope →3 Stateless returns
05 · EXAM LANGUAGE DECODER

Words in the question that should trigger a design instinct

“publicly accessible”
→ Look for IGW + public addressing + routing/security.
“private instances need updates”
→ Think NAT Gateway.
“explicit deny”
→ Think NACL or a higher-level security control; Security Groups have allow rules only.
“access S3 without internet/NAT”
→ Think S3 Gateway Endpoint.
“highly available VPC”
→ Spread subnets/resources across AZs; avoid one-AZ NAT dependency.
06 · KNOWLEDGE CHECK

Five SAA-style questions

Q1Private EC2 instances must download objects from S3 without internet routes and with the lowest recurring network cost. Which design meets the requirement?
Answer: A. The deciding constraints are private routing and low recurring cost; an S3 gateway endpoint has no hourly endpoint or NAT processing charge.
Q2A subnet must reject one malicious source CIDR even when an attached application security group allows its port. Which control should be changed?
Answer: B. The deciding constraint is an explicit subnet-level deny. Network ACLs support ordered allow and deny rules, whereas security groups allow only.
Q3Instances in two private subnets across two AZs require highly available IPv4 internet egress. Which architecture removes a single-AZ dependency?
Answer: C. The deciding constraint is AZ-resilient IPv4 egress. NAT gateways are zonal, so each subnet should use a NAT in its own AZ.
Q4A security group allows TCP 443 inbound from a client. No outbound rule explicitly allows the response ephemeral port. Why can the response still return?
Answer: D. The deciding behavior is connection tracking: security groups automatically permit response traffic for an allowed flow.
Q5An IPv6-only private workload needs outbound internet access but must reject unsolicited inbound internet connections. Which VPC component is appropriate?
Answer: A. The deciding constraints are IPv6 and outbound-only internet access. An egress-only internet gateway provides that behavior without IPv4 NAT.
