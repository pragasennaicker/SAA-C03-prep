01 · ARCHITECTURE DRAWING

Build connectivity one path at a time

ARCHITECTURE

AWS Cloud

A Region is the boundary for Transit Gateway, Direct Connect gateways, and VPC attachments. Every path that follows is drawn inside this box except on-premises and remote users.

ARCHITECTURE

On-premises

The data centre sits outside AWS. Hybrid design starts by naming what must reach which VPC — a dedicated path, an encrypted path, or only DNS.

ARCHITECTURE

Two VPCs

App VPC A (10.0.0.0/16) and VPC B (10.1.0.0/16). They do not route to each other until you add a path chip. CIDRs do not overlap — required for peering and for Transit Gateway attachments.

ARCHITECTURE

VPC Peering

Peering adds VPC C (10.2.0.0/16) as a point-to-point route with A. It is not transitive: on-premises and VPC B cannot use A as a hop to C. Overlapping CIDRs would block this connection.

ARCHITECTURE

Transit Gateway

A regional hub with transitive routing. A and B attach. Prefer TGW over a peering mesh when many VPCs or hybrid attachments must talk.

ARCHITECTURE

Direct Connect

Dedicated path: data centre → Direct Connect → Direct Connect Gateway → Transit Gateway → app in VPC A. Traffic is not encrypted by default — add VPN or MACsec when the exam requires encryption.

ARCHITECTURE

Site-to-Site VPN

Encrypted path: customer gateway → IPsec VPN → Transit Gateway → app in VPC A. Higher, more variable latency than Direct Connect; often the encrypted backup onto the same hub.

ARCHITECTURE

Client VPN

Remote users, not a site-to-site link: user → Client VPN endpoint in VPC B → private app in B. After the session is up you still need target network associations, authorization rules, and routes; the instance security group must allow the Client VPN security group.

ARCHITECTURE

PrivateLink

The consumer in VPC A sends traffic to an interface endpoint in its own VPC. PrivateLink carries that privately to an NLB in VPC B, which forwards to the service. No VPC routes are shared and CIDRs may overlap.

ARCHITECTURE

Route 53

On-premises resolvers reach private AWS names through a Resolver inbound endpoint in the VPC. A private hosted zone alone does not answer them. Route 53 is DNS — it does not move packets.

ARCHITECTURE

Every path on one drawing

DX and VPN both attach to Transit Gateway so A and B are transitive with on-premises. Peering adds C as a point-to-point link with A only. Client VPN is a user TLS path into B. PrivateLink is the private hop from A’s interface endpoint to B’s NLB. Route 53 answers DNS via a Resolver inbound endpoint.

02 · DEEP DIVE

What you actually need to understand

1

VPC Peering

  • Private point-to-point routing between two VPCs.
  • No transitive routing: A↔B and A↔C does not create B↔C.
  • Peered VPC CIDRs cannot overlap. Identical prefix lengths are not required; 10.0.0.0/16 cannot peer with 10.0.128.0/17 because the second block sits inside the first.
  • Peering across AWS accounts and across Regions is supported when CIDRs do not overlap.
  • Routes must be added to relevant route tables and security controls still apply.
  • Private DNS across a peering connection needs DNS resolution (and DNS hostnames) enabled on both VPCs; that setting does not create a route.
2

Transit Gateway

  • Hub-and-spoke routing for many VPCs and hybrid connections.
  • Transit routing is controlled with Transit Gateway route tables — associations and propagations let you isolate spoke domains (for example production cannot route to development).
  • Reduces the operational complexity of a full peering mesh.
  • Can centralize inspection/egress patterns and aggregate VPN/Direct Connect connectivity.
  • Transit Gateway peering joins two regional Transit Gateways; it is not a substitute for attaching every VPC in one Region.
3

Site-to-Site VPN

  • IPsec encrypted connectivity over internet paths.
  • AWS provides redundant VPN tunnels; design customer-side redundancy as well.
  • Good when encrypted connectivity is needed quickly.
  • Network performance can vary because the path uses the internet.
4

Direct Connect

  • Dedicated connectivity from your network to AWS through a Direct Connect location/provider.
  • Useful for consistent hybrid network performance and sustained data transfer.
  • Direct Connect traffic is not encrypted by default; add a Site-to-Site VPN over the DX path, or MACsec where supported, when encryption is required.
  • A Direct Connect gateway lets one connection reach VPCs in multiple Regions (associate each Region’s virtual private gateway or Transit Gateway).
  • For resiliency, use two connections at two Direct Connect locations; add a Site-to-Site VPN as an internet backup when a second DX location is not yet available.
5

Client VPN

  • A managed TLS VPN for remote users into a VPC — not a replacement for Site-to-Site VPN or Direct Connect.
  • A successful session is not enough. Associate target networks, add authorization rules for the destination CIDRs, and install routes so client traffic reaches those subnets.
  • Instance security groups must allow the Client VPN security group (or the client CIDR) on the application ports.
  • Site-to-Site VPN joins a whole network; Direct Connect is the dedicated private path from a data centre.
6

PrivateLink + Route 53

  • PrivateLink exposes a specific service privately rather than routing entire networks together. The provider publishes an NLB-backed endpoint service; each consumer creates an interface VPC endpoint in its own VPC.
  • Excellent provider/consumer pattern and useful with overlapping address spaces — no VPC routes are shared.
  • Route 53 is DNS, not a packet router: it tells clients which endpoint to use.
  • Hybrid DNS is directional. A Resolver inbound endpoint receives queries that on-premises resolvers forward into the VPC. A Resolver outbound endpoint plus forwarding rules sends selected VPC queries to on-premises DNS.
  • Failover routing with health checks is active/passive: Route 53 returns the primary record while it is healthy and switches to the secondary when the health check fails. Weighted, latency, geolocation and geoproximity are different policies, taught in Lesson 12 for global steering.
7

S3 gateway vs interface endpoints

  • A gateway VPC endpoint for Amazon S3 (or DynamoDB) is a prefix-list route in the VPC route table. It is the in-VPC, no-hourly-charge default and never leaves the AWS network.
  • Gateway endpoints do not extend past the VPC. On-premises clients, Transit Gateway attachments, and peered VPCs cannot use another VPC’s gateway endpoint to reach S3.
  • Those clients use an interface VPC endpoint (PrivateLink) for S3, which has a private ENI they can route to over Direct Connect, VPN, Transit Gateway, or peering.
  • When both in-VPC and on-premises traffic must stay private, keep the gateway endpoint for in-VPC requests and add an interface endpoint for the hybrid path — paying the interface charge only for traffic that cannot use the gateway.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Build a transitive network hub

Dozens of VPCs and two offices need centralized, transitive routing with segmented route domains. Attach them to a Transit Gateway and use separate TGW route tables. A peering mesh grows quadratically and peering cannot route transitively through another VPC.

1 Transitive hub→2 Route domains→3 Fewer links
WORKED SCENARIO

Private predictable hybrid path

A data center transfers steady large volumes to AWS and requires consistent network performance, with encrypted failover. Use Direct Connect as the primary path and a site-to-site VPN as backup, adding VPN over DX if primary-path encryption is mandatory. VPN alone depends on internet conditions, while Direct Connect alone lacks native encryption.

1 Predictable path→2 Encrypted option→3 Backup route
WORKED SCENARIO

Expose only an internal service

A provider must serve hundreds of customer VPCs, including overlapping CIDRs, without granting broad network access. Put the service behind an NLB and publish it through PrivateLink endpoint services. Peering requires non-overlapping CIDRs and exposes routed network reachability beyond the single service.

1 Overlap safe→2 Service scoped→3 No route sharing
05 · EXAM LANGUAGE DECODER

Words in the question that should trigger a design instinct

“transitive routing”
→ Transit Gateway, not VPC Peering.
“dedicated connection”
→ Direct Connect.
“encrypted connection quickly”
→ Site-to-Site VPN.
“remote workers / Client VPN”
→ Associations, authorization rules, and routes — a session alone is not enough.
“private access to a service only”
→ PrivateLink.
“on-premises to S3 privately”
→ Interface endpoint. A gateway endpoint stops at the VPC.
“two Direct Connect locations”
→ Resilient DX. VPN is the internet backup, not a second location.
“10% / 90% traffic split”
→ Route 53 Weighted.
“lowest latency Region”
→ Route 53 Latency routing.
“fail over when unhealthy”
→ Route 53 failover + health checks.
06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A company connects VPC A to VPC B with a VPC peering connection, and connects VPC B to VPC C with a second peering connection. An application in VPC A must send packets to an Amazon EC2 instance in VPC C by using private IP addresses. The CIDR blocks do not overlap. After the second peering connection is active, VPC A still cannot reach VPC C. Which explanation accounts for this behavior?
Answer: B. VPC peering is point-to-point. A–B plus B–C does not create a route from A to C. Each pair needs a direct peering connection, or the VPCs need a Transit Gateway hub.

Good to know: In the same Region, a security group can reference a peered security group. That is not why A cannot reach C. PrivateLink is the tool when you must expose one service without routing entire CIDRs, not a requirement of peering itself.
Q2A company wants to create a VPC peering connection between VPC A (10.0.0.0/16) in one AWS account and VPC B (10.0.128.0/17) in a second account in the same AWS Region. The peering connection fails to create. The accounts are different and the prefix lengths are not the same. Which restriction is causing the failure?
Answer: D. Peered VPC CIDRs cannot overlap. 10.0.128.0/17 is a subset of 10.0.0.0/16, so peering cannot be created. Cross-account peering is supported, and identical prefix lengths are not required.

Good to know: Peering across accounts and across Regions is supported when CIDRs do not overlap. If the CIDRs overlap, use AWS PrivateLink for service-only access or renumber one VPC.
Q3A company has VPC A in the us-east-1 Region in one AWS account and VPC B in the eu-west-1 Region in a second account. The CIDR blocks do not overlap. Applications in VPC A must send packets to private IP addresses in VPC B and must resolve Amazon EC2 private DNS names that belong to VPC B. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. Peering works across accounts and Regions when CIDRs do not overlap. Routes make the packets flow. Enabling DNS resolution on the peering connection is a separate setting that lets instances resolve private DNS names in the peer VPC.

Good to know: A Transit Gateway is regional. Attaching a VPC in another Region requires a second transit gateway and a transit gateway peering attachment. PrivateLink would expose a service, not arbitrary private IPs and EC2 DNS names.
Q4A company has two VPCs in the same AWS Region and the same AWS account. The CIDR blocks do not overlap. The VPCs must route traffic to each other. The company does not expect to add more VPCs or connect an on-premises network. Which solution will meet these requirements with the LEAST operational overhead?
Answer: A. Two non-overlapping VPCs with no need for transitive routing are the peering case. A transit gateway would work but adds a hub to operate. PrivateLink shares a service, not the whole CIDR. A Site-to-Site VPN is a hybrid pattern.

Good to know: Choose a Transit Gateway when the number of VPCs will grow, when on-premises must join the same hub, or when you need centralized route tables. Peering is the simple point-to-point answer only while the mesh stays small.
Q5A company operates 50 VPCs across several AWS accounts in a single AWS Region. The VPCs must communicate with each other and with an on-premises network that connects to AWS through AWS Direct Connect. The company currently maintains a mesh of VPC peering connections and finds that each new VPC requires many new connections and route table updates. Which solution will meet these requirements with the LEAST operational overhead?
Answer: B. Transit Gateway is the transitive hub for many VPCs plus hybrid attachments. Peering is not transitive and a mesh grows with every new VPC. PrivateLink does not join networks. A private hosted zone is DNS, not a packet path.

Good to know: Route 53 private hosted zones can make names resolve across those VPCs, but they do not move packets. PrivateLink is the right tool when each VPC should consume one service without sharing routes.
Q6A company attaches production, development, and shared-services VPCs to one AWS Transit Gateway in a single AWS Region. Production and development must each reach directory and logging services in the shared-services VPC. A compliance rule requires that production must not be able to route to development. All three VPC CIDR blocks are unique. Which solution will meet these requirements?
Answer: A. Transit Gateway route tables control which attachments can reach which others. Separate associations keep production and development from learning each other's routes, while both still learn shared services.

Good to know: Security groups can still restrict ports after routing exists, but they do not remove a route that a shared Transit Gateway table already advertised. DNS isolation does not stop packets that have a route.
Q7A company has several VPCs in the us-east-1 Region and several VPCs in the eu-west-1 Region. An on-premises data center must reach both Regions over one AWS Direct Connect connection. VPCs in each Region must also communicate with each other by using private IP addresses, including traffic between the two Regions. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and E. A Direct Connect gateway associated with virtual private gateways is not transitive between those VPCs. Transit Gateways in each Region associated with a Direct Connect gateway give hybrid reach. Transit Gateway peering is the separate path that carries VPC-to-VPC traffic between Regions.

Good to know: Associating many virtual private gateways with one Direct Connect gateway is a valid hybrid pattern when the VPCs do not need to talk to each other through that path. The extra constraint here is VPC-to-VPC, which is what forces Transit Gateway peering.
Q8A company has an AWS Transit Gateway in us-east-1 with 12 VPC attachments and another Transit Gateway in eu-west-1 with 8 VPC attachments. VPCs in us-east-1 must send private traffic to VPCs in eu-west-1. The CIDR blocks do not overlap. Which solution will meet these requirements with the LEAST operational overhead?
Answer: B. Transit Gateway peering joins two regional hubs so every attached VPC can reach the remote CIDRs through one attachment, instead of a cross-Region peering mesh.

Good to know: A full VPC peering mesh across 12 × 8 VPCs is operationally heavy and still non-transitive. PrivateLink is service-scoped and would require an endpoint per consumer–provider pair.
Q9A company wants all east-west traffic between spoke VPCs to pass through a shared inspection VPC that runs firewall appliances. The company already uses AWS Transit Gateway to attach the spoke VPCs and the inspection VPC. Spoke VPCs must not learn routes to each other directly. Which solution will meet these requirements?
Answer: A. Centralized inspection is a Transit Gateway routing pattern: spokes do not learn each other's routes directly. They send east-west traffic to the inspection attachment, and the inspection VPC routes back to the spokes.

Good to know: Gateway VPC endpoints exist only for Amazon S3 and DynamoDB prefix lists, not for arbitrary spoke CIDRs. Route 53 can change which name a client resolves; it does not steer packets through a firewall VPC.
Q10A company needs encrypted connectivity from its on-premises network to a VPC within two days so that a migration can start. The company already has a reliable internet connection at the data center. Consistent latency is not required for this phase. The company will evaluate AWS Direct Connect after the application is running. Which solution will meet these requirements?
Answer: A. A Site-to-Site VPN can be brought up quickly over existing internet connectivity and provides IPsec encryption. Direct Connect is the dedicated path but is not the fast option. Client VPN is for remote users, not site routers. Peering does not connect on-premises networks.

Good to know: When the exam later asks for predictable throughput, switch the answer to Direct Connect. When it asks for encryption on that dedicated path, add a VPN over Direct Connect (or MACsec where supported).
Q11A company uses an AWS Site-to-Site VPN from one customer gateway device to a virtual private gateway. The AWS Management Console shows two tunnels on that VPN connection. During a maintenance window on the customer gateway, the VPN is unavailable even though both tunnels were healthy the day before. Which solution will provide high availability on the on-premises side?
Answer: A. AWS provides two tunnels for AWS-side redundancy, but both typically terminate on the same customer gateway. A second on-premises device and a second VPN connection protect against customer-gateway failure.

Good to know: Accelerated Site-to-Site VPN improves performance by using the AWS global network; it does not add a second customer gateway. An internet gateway is the VPC's path to the public internet, not a hybrid VPN terminator.
Q12A company transfers several terabytes each day from an on-premises data center to AWS. The current AWS Site-to-Site VPN saturates during business hours, and latency varies with internet conditions. The company needs a dedicated path with consistent performance for this sustained transfer and is willing to wait for a cross-connect. Which solution will meet these requirements?
Answer: A. Direct Connect is the dedicated private path for consistent hybrid performance and sustained transfer. A second VPN tunnel on the same device still uses the internet. Client VPN is for users. Peering does not attach a data center.

Good to know: The two tunnels that AWS already provides on one VPN connection are for AWS-side redundancy, not extra internet bandwidth. If encryption is also required on the dedicated path, add a VPN over Direct Connect.
Q13A company needs a dedicated, predictable network path from its data center to AWS for a steady replication workload. A compliance rule requires that all application traffic also be encrypted in transit on that path. The company is willing to add a second overlay if the dedicated path alone does not encrypt traffic. Which solution will meet these requirements?
Answer: D. Direct Connect supplies the dedicated path but is not encrypted by default. A Site-to-Site VPN over that path adds IPsec so both constraints are met.

Good to know: MACsec can encrypt Direct Connect at the link layer where the location and port support it. On the exam, 'VPN over Direct Connect' is the reliable encryption answer. Peering never rides Direct Connect as a connection type.
Q14A company has one AWS Direct Connect connection at one Direct Connect location. That connection is the only path from the data center to AWS. The company needs a resilient hybrid design that survives the failure of that Direct Connect location. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and E. Resilient Direct Connect uses two connections at two locations and two customer routers so a location or device failure does not isolate the data center.

Good to know: A second connection at the same location still fails if that location is lost. An AWS Site-to-Site VPN is a valid internet backup when a second location is not available, but it does not meet a two-location Direct Connect design.
Q15A company has an AWS Direct Connect connection in the us-east-1 Region. VPCs in us-east-1 and ap-southeast-2 must receive traffic from on-premises over that single connection. The VPCs do not need to communicate with each other through the Direct Connect path, and the company wants to avoid operating a Transit Gateway if it is not required. Which solution will meet these requirements?
Answer: A. A Direct Connect gateway lets one connection reach virtual private gateways in multiple Regions. Because the VPCs do not need to talk to each other through that path, Transit Gateway is extra operational overhead.

Good to know: Virtual private gateways associated with the same Direct Connect gateway are not transitive with each other. If the stem had required VPC-to-VPC traffic as well, the answer would move to Transit Gateway plus Transit Gateway peering.
Q16A company wants thousands of remote employees to reach an application that runs in a private subnet. Each employee uses a laptop on a home network rather than a corporate office LAN. The company does not need to connect entire branch offices or data centers. Which solution will meet these requirements?
Answer: A. Client VPN is the managed TLS VPN for remote users into a VPC. Site-to-Site VPN and Direct Connect join whole networks. Peering does not attach home networks.

Good to know: A working Client VPN session is not enough on its own. You still need target network associations, authorization rules, routes, and a security group that allows the Client VPN security group on the application port.
Q17An enterprise is implementing AWS Client VPN so that remote workers can reach private backend instances. After a VPN session is established successfully, traffic from the clients still does not reach the instances. There is no authorization rule for the destination CIDR, and the instance security group does not allow the Client VPN security group. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and E. A successful session already means at least one target network is associated. The remaining gaps named in the stem are an authorization rule for the destination CIDR and an instance security group that allows the Client VPN security group.

Good to know: If the destination is outside the associated VPC CIDR, you also need a Client VPN route for that CIDR. A NAT gateway is for outbound internet from private subnets, not a Client VPN attachment.
Q18A software provider must offer one TCP service to hundreds of customer VPCs. Several customer CIDR blocks overlap the provider VPC, so VPC peering connections cannot be created. The provider must not share VPC routes with customers or grant access to any resource other than that service. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. PrivateLink is two sides of one pattern. The provider publishes an NLB-backed endpoint service. Each customer creates an interface endpoint in its own VPC. No routes are shared, so overlapping CIDRs are allowed.

Good to know: Peering and Transit Gateway both require non-overlapping CIDRs and create routed reachability beyond the single service. Use them when the customer should reach the whole network, not one API.
Q19A customer VPC must consume a shared file service that another AWS account publishes through AWS PrivateLink. The CIDR blocks overlap, so a VPC peering connection cannot be created. The customer must keep all traffic on private IP addresses inside its own VPC and must not receive routes to the provider VPC. Which solution will meet these requirements?
Answer: B. The consumer-side PrivateLink action is to create an interface endpoint in the customer VPC. Traffic stays on private ENIs. Overlapping CIDRs do not matter because no VPC routes are shared.

Good to know: Gateway VPC endpoints exist only for Amazon S3 and DynamoDB. A custom TCP service published by another account is always an interface endpoint. Peering cannot be created while the CIDRs overlap.
Q20A company uses a gateway VPC endpoint so that Amazon EC2 instances in private subnets can reach Amazon S3 without a NAT gateway. Security wants to ensure that those instances can access only one specific bucket through the endpoint and cannot use the endpoint to list or read other buckets. Which solution will meet these requirements?
Answer: A. A VPC endpoint policy is an IAM resource policy on the endpoint. It can restrict which buckets and actions the endpoint will permit, in addition to the bucket policy.

Good to know: A bucket policy that requires the endpoint (aws:SourceVpce) is the complementary control when you also want to deny access that bypasses the endpoint. Moving the bucket to another Region would break the gateway endpoint entirely.
Q21A company needs Amazon S3 access that never uses the public internet. Amazon EC2 instances in a VPC must use a no-additional-charge path. On-premises servers that connect through AWS Direct Connect must use the same private S3 access pattern. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. A gateway endpoint is the in-VPC, no-hourly-charge path. Gateway endpoints cannot be reached from on-premises, so the Direct Connect clients need an interface endpoint (PrivateLink) they can route to.

Good to know: Keeping both endpoints is the cost-aware design: in-VPC traffic stays on the free gateway path, and you pay the interface charge only for traffic that cannot use the gateway. A NAT gateway still sends S3 to the public endpoint.
Q22On-premises applications connect to a VPC through AWS Direct Connect. The VPC already has a gateway VPC endpoint for Amazon S3, and in-VPC instances use that endpoint successfully. The on-premises applications still reach S3 over the public internet. Which solution will provide private connectivity to Amazon S3 for the on-premises applications?
Answer: B. Gateway endpoint connections cannot be extended out of the VPC. Direct Connect, VPN, Transit Gateway, and peering clients that need private S3 use an interface endpoint.

Good to know: The existing gateway endpoint remains the right path for in-VPC instances. Do not delete it when you add the interface endpoint for hybrid clients. You cannot peer with Amazon S3 as if it were a VPC.
Q23On-premises DNS servers must resolve records in a Route 53 private hosted zone that is already associated with a VPC. The VPC is connected to the data center through AWS Direct Connect, and route tables already include the on-premises CIDR. On-premises queries still fail to resolve those private names. Which solution will meet these requirements?
Answer: A. The query direction is on-premises to AWS. A Resolver inbound endpoint receives those forwarded queries. Associating the private hosted zone with the VPC is necessary but not sufficient for on-premises resolvers.

Good to know: An outbound endpoint is the other direction: VPC clients resolving on-premises names. A public hosted zone would publish the names on the internet, which is not private resolution.
Q24A company needs hybrid DNS. On-premises servers must resolve names in a Route 53 private hosted zone. Amazon EC2 instances in the VPC must resolve names in an on-premises DNS domain. The networks are connected by AWS Direct Connect. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. Hybrid DNS is two directions. Inbound endpoints accept queries that on-premises resolvers forward into the VPC. Outbound endpoints plus forwarding rules send selected VPC queries to on-premises DNS.

Good to know: A private hosted zone associated with the VPC answers queries that already arrive at the VPC resolver. It does not, by itself, pull queries in from on-premises or push VPC queries out. Peering DNS resolution applies to a peered VPC, not a data center.
Q25A company serves an API from a primary Regional endpoint and a standby Regional endpoint. Amazon Route 53 must return the primary endpoint while it is healthy and must return the standby endpoint only when the primary fails a health check. Users must not be split across both endpoints while the primary is healthy. Which solution will meet these requirements?
Answer: A. Failover routing is active/passive. Route 53 returns the primary record while the health check passes and switches to the secondary when it fails. Weighted and latency policies would split traffic while both endpoints are healthy.

Good to know: Weighted routing is the 10/90 gradual-release answer. Latency routing is the lowest-latency Region answer. Both belong to Lesson 12's global steering set; this lesson's DNS fork is hybrid resolution versus failover.
