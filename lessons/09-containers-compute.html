02 · DEEP DIVE

What you actually need to understand

1

ECS

  • AWS-native container orchestration with services/tasks and tight AWS integration.
  • Can run tasks on EC2 capacity or Fargate.
  • ECS services maintain desired task count and integrate with load balancers/autoscaling.
  • Good default when Kubernetes APIs/ecosystem are not a requirement.
2

EKS

  • Managed Kubernetes control plane and AWS integrations.
  • Use when Kubernetes portability/ecosystem/API compatibility is a real requirement.
  • Worker compute can be EC2 managed node groups or Fargate for supported workloads.
  • Kubernetes adds operational concepts; do not choose it merely because it is fashionable.
3

Fargate

  • Serverless compute engine for containers used with ECS and EKS.
  • Removes EC2 worker-node provisioning/patching responsibilities.
  • Pay for task/pod compute resources rather than idle cluster instances.
  • Useful when container packaging is desired but infrastructure management should be minimized.
4

ECR + image lifecycle

  • Private/public container registry integrated with IAM.
  • Store versioned images and scan/manage lifecycle according to requirements.
  • Orchestrators pull images from ECR and run them; ECR itself does not execute containers.
  • Immutable image/versioning practices improve repeatability.
5

Batch + platform options

  • AWS Batch schedules queued batch jobs onto suitable compute resources.
  • Elastic Beanstalk abstracts much of application environment provisioning while retaining underlying AWS resources.
  • Outposts extends AWS infrastructure on premises for latency/data-residency use cases.
  • ECS/EKS Anywhere are recognition-level options for customer-managed/on-premises container environments.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Simple microservice platform

Constraint: a small team needs managed container orchestration without Kubernetes expertise. Design: ECS services on Fargate pull private images from ECR and register tasks with an ALB. Why alternatives fail: EKS adds Kubernetes administration, while plain EC2 lacks orchestration.

1 ECS minimizes control work→2 Fargate removes nodes→3 ECR stores images
WORKED SCENARIO

Portable Kubernetes workloads

Constraint: an organization requires Kubernetes APIs, Helm charts, and familiar ecosystem tooling. Design: EKS supplies the managed control plane with managed node groups or Fargate profiles. Why alternatives fail: ECS does not expose Kubernetes APIs, and self-managed Kubernetes increases operational burden.

1 EKS preserves Kubernetes→2 Nodes or Fargate run pods→3 AWS manages control plane
WORKED SCENARIO

Private image delivery

Constraint: deployments need private, scanned, versioned images close to AWS compute. Design: push immutable tags to ECR, enable scanning, and grant task execution roles pull access. Why alternatives fail: S3 is not an OCI registry, and public registries weaken private access control.

1 ECR is managed registry→2 Execution role pulls→3 Immutable tags reduce drift

06 · KNOWLEDGE CHECK

Five SAA-style questions

Q1A team wants to run ECS tasks without patching instances or managing cluster capacity providers. Which compute choice best satisfies the requirement?
Answer: A. Fargate provides serverless compute for ECS tasks, removing EC2 host provisioning and patching.
Q2A company must reuse Helm charts and Kubernetes operators after moving to AWS. Which managed orchestration service is the appropriate target?
Answer: B. EKS exposes a managed Kubernetes control plane compatible with Kubernetes tooling and APIs.
Q3An ECS task in awsvpc network mode needs distinct inbound rules from other tasks. Which resource can be assigned directly to that task networking?
Answer: A. awsvpc mode gives each task an elastic network interface to which security groups can be attached.
Q4Private ECS tasks must pull ECR images without traversing a NAT gateway. Which design keeps image access on the AWS network?
Answer: A. Private ECR pulls use ECR interface endpoints and the S3 gateway endpoint for image layers.
Q5An ECS service behind an ALB must maintain six healthy copies during deployments and failures. Which setting represents that application capacity?
Answer: B. The ECS service scheduler maintains the desired task count and replaces unhealthy tasks.
