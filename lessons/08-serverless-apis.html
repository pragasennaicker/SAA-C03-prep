LESSON 08

Serverless, APIs & Front Ends

Key words

Lambda, API Gateway, Cognito, AppSync and Amplify

PerformanceResilienceCostSecurity

EXIT GOALDesign low-operations APIs and event-driven applications, and know when serverless is not the best fit.

01 · ARCHITECTURE DRAWING

Build Cognito to API Gateway to Lambda

ARCHITECTURE

Users

Browser or mobile clients never call DynamoDB with long-lived keys. Identity and an API sit in front.

ARCHITECTURE

Amplify / S3

The static front end. Amplify hosts it; S3 + CloudFront is the equivalent building block.

ARCHITECTURE

Cognito

User pools authenticate people. Identity pools can mint temporary AWS credentials for the app.

ARCHITECTURE

API Gateway

HTTP/REST/WebSocket front door: auth, throttling, and integration to Lambda.

ARCHITECTURE

Lambda

Run the handler with an execution role. Reserve concurrency on the path that must not starve.

ARCHITECTURE

DynamoDB

The default serverless data store. Scale is automatic; design the partition key.

ARCHITECTURE

AppSync

GraphQL front door with subscriptions. Clients reach AppSync directly — not via API Gateway.

ARCHITECTURE

The full serverless path

The front end is Amplify/S3. Cognito authenticates. REST goes API Gateway → Lambda → DynamoDB. GraphQL goes to AppSync, not through API Gateway.

02 · DEEP DIVE

What you actually need to understand

1

Lambda execution model

  • Runs functions in response to events with automatic scaling.
  • Memory allocation also influences available CPU; tune memory from measured cost/performance rather than minimum size.
  • Use execution roles for AWS access and environment/secrets patterns carefully.
  • Concurrency controls protect downstream systems; asynchronous invocations and event-source mappings have different retry semantics.
  • Keep functions stateless and persist durable state externally.
2

API Gateway

  • Managed front door for REST, HTTP and WebSocket API patterns.
  • Supports throttling, authentication/authorization integrations, stages and request handling features.
  • Can invoke Lambda or integrate with other AWS services/backends.
  • Use caching or CloudFront where appropriate for read-heavy global APIs.
3

Cognito

  • User Pools provide application sign-up/sign-in and token issuance.
  • Identity Pools can exchange authenticated identities for temporary AWS credentials in suitable app patterns.
  • Use for customer/application identity, not as a replacement for workforce Identity Center.
  • Integrates with external identity providers.
4

AppSync + Amplify

  • AppSync provides managed GraphQL APIs, subscriptions/real-time features and multiple data-source integrations.
  • Amplify provides front-end development/deployment capabilities and hosting workflows.
  • Choose AppSync when GraphQL and flexible data-source resolution are core requirements.
  • Do not pick it merely because the application is serverless—API style matters.
5

Serverless trade-offs

  • Excellent for variable workloads and low operational overhead.
  • Cold-start, concurrency, runtime and service-integration constraints must be understood conceptually.
  • Very long-running, highly stateful or specialized compute may fit containers/EC2 better.
  • Event-driven design should protect downstream services with queues, rate limits and idempotency.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Bursting mobile checkout

Constraint: a mobile checkout API has sharp bursts and must authenticate customers. Design: Cognito user pools issue tokens, API Gateway validates them, and Lambda writes idempotently to DynamoDB. Why alternatives fail: EC2 adds capacity management, while an identity pool alone does not provide a user directory.

1 User pool authenticates→2 API Gateway validates JWT→3 Idempotency absorbs retries
WORKED SCENARIO

Live collaborative dashboard

Constraint: web clients need GraphQL queries and near-real-time updates with minimal connection management. Design: AppSync subscriptions push changes and resolvers access DynamoDB or Lambda. Why alternatives fail: API Gateway REST needs custom fan-out, and polling wastes requests and increases latency.

1 AppSync manages GraphQL→2 Subscriptions push updates→3 Resolvers reach data
WORKED SCENARIO

Database-safe Lambda ingestion

Constraint: asynchronous jobs can spike beyond an RDS database's connection capacity. Design: buffer work in SQS, cap Lambda reserved concurrency, and use RDS Proxy. Why alternatives fail: provisioned concurrency reduces cold starts but does not cap database pressure; direct invocation removes buffering.

1 SQS smooths bursts→2 Reserved concurrency caps load→3 RDS Proxy pools connections
05 · EXAM LANGUAGE DECODER

Words in the question that should trigger a design instinct

→ Serverless is worth evaluating.
“customer sign-up/sign-in”
→ Cognito.
“REST API front door”
→ API Gateway.
“GraphQL + subscriptions”
→ AppSync.
“function overwhelms DB”
→ Concurrency controls / queue / RDS Proxy.
06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A startup receives spiky HTTP traffic for a photo-upload API. Traffic is idle most of the night and can jump many times during a campaign. The team wants the LEAST operational overhead and will not manage Amazon EC2 capacity. Each request runs for under a second and is stateless. Which solution will meet these requirements?
Answer: A. Short, variable, stateless requests with low operational overhead select Lambda behind API Gateway. A fixed EC2 fleet is the capacity-management path the stem forbids.

Good to know: Amazon EC2 or containers would be correct if the work were long-running or highly stateful. AppSync would be correct if the API had to be GraphQL with subscriptions.
Q2A Lambda function writes to a relational database that supports only 40 concurrent connections. Event bursts cause the function to scale to hundreds of concurrent executions and exhaust the database. The team must cap concurrent executions of this function. Predictable cold starts are not the requirement. Which solution will meet these requirements?
Answer: C. Reserved concurrency places a hard ceiling on concurrent executions and protects the downstream database. Provisioned concurrency warms environments; it does not cap database pressure.

Good to know: Provisioned concurrency would be correct if the stem asked to reduce cold starts for predictable traffic. An SQS buffer would appear if producers needed burst absorption in front of the worker.
Q3A latency-sensitive Lambda function serves a morning traffic spike that is predictable from week to week. Amazon API Gateway invokes the function. Users report delays on the first requests after idle periods. Operations must keep execution environments initialized ahead of those requests. The database is not being overwhelmed. Which solution will meet these requirements?
Answer: B. Provisioned concurrency keeps initialized execution environments ready and addresses predictable cold starts. Reserved concurrency guarantees and limits capacity but does not pre-initialize environments.

Good to know: Reserved concurrency would be correct if the problem were protecting a downstream system from unbounded scale. Throttling at API Gateway would be correct if the API itself were being overwhelmed.
Q4A company runs a public mobile checkout API. The app needs customer sign-up, sign-in, password recovery, and JWT tokens. The REST API must validate those tokens before invoking AWS Lambda. The team must not build a custom user directory and must not mint long-lived AWS access keys for each player. Which solution will meet these requirements?
Answer: D. A user pool is the customer directory and JWT issuer. API Gateway validates those tokens before Lambda. An identity pool alone does not provide sign-up.

Good to know: An identity pool would be correct if the app needed temporary AWS credentials to call AWS APIs directly. IAM Identity Center would be correct for workforce access to AWS accounts.
Q5A mobile game authenticates players with a social identity provider. After sign-in, the app must upload photos directly to Amazon S3 using temporary AWS credentials. The team does not want to embed IAM user keys in the app and does not need Amazon API Gateway for this upload path. Which solution will meet these requirements?
Answer: A. Identity pools exchange authenticated identities for temporary AWS credentials. A user pool issues JWTs for app sign-in; it does not by itself mint AWS keys.

Good to know: A user pool would be correct for sign-up, sign-in, and JWT validation at API Gateway. Together, a user pool can be an identity provider to an identity pool.
Q6A company needs a managed HTTPS front door for a REST API that Lambda and an existing HTTP backend will serve. The API must support usage plans and per-client throttling. The team will not manage reverse proxies on Amazon EC2. Clients need REST, not GraphQL. Which solution will meet these requirements?
Answer: C. API Gateway is the managed REST front door with throttling, usage plans, and integrations to Lambda or HTTP backends. AppSync is the GraphQL path.

Good to know: AppSync would be correct if the stem required GraphQL and subscriptions. An Application Load Balancer with a Lambda target would appear without usage plans and API-stage throttling.
Q7Thousands of browsers use a live dashboard. Web clients need GraphQL queries and near-real-time updates when Amazon DynamoDB items change. The team wants a managed GraphQL service with subscriptions and does not want to build WebSocket fan-out on Amazon API Gateway. Polling is not acceptable. Which solution will meet these requirements?
Answer: B. AppSync provides managed GraphQL, resolvers, and subscriptions. Clients reach AppSync directly rather than through API Gateway REST fan-out.

Good to know: API Gateway WebSocket would be closer if the stem required a custom WebSocket API without GraphQL. REST plus polling is the high-overhead alternative the scenario rejects.
Q8A team must host a static single-page application with a managed front-end workflow, including builds from a Git repository. They want AWS to operate the hosting rather than Amazon EC2 web servers. The REST API will remain a separate backend. Customer authentication is out of scope for this hosting choice. Which solution will meet these requirements?
Answer: D. Amplify Hosting is the managed front-end hosting and Git-based deploy path. EC2 web servers are the operational model the stem rejects.

Good to know: Amazon S3 with CloudFront would also host a static SPA if the stem did not require Amplify's front-end toolchain. AppSync would be the GraphQL API, not the static host.
Q9Producers on Amazon EC2 in private subnets can emit tens of thousands of events in a few seconds. A Lambda worker would overwhelm a downstream database if it scaled with every event. The team must absorb bursts between producer and worker. Message ordering guarantees are not required. Which solution will meet these requirements?
Answer: A. SQS between producer and worker is the lesson's burst-absorption pattern. Direct invoke removes the buffer; provisioned concurrency increases readiness, not decoupling.

Good to know: Reserved concurrency would still be needed if the worker itself must be capped. Provisioned concurrency would be correct for predictable cold starts, not burst absorption.
Q10An application invokes AWS Lambda asynchronously. When a third-party endpoint is down, the function fails repeatedly. After retries are exhausted, the team must retain the original event payload for later analysis. The function is not an Amazon SQS event-source mapping and is not behind Amazon API Gateway. Which solution will meet these requirements?
Answer: C. After asynchronous retries, Lambda can send exhausted events to an on-failure destination or a supported DLQ. Caching and identity pools are not failure stores.

Good to know: For an SQS event-source mapping, a redrive policy on the queue is the usual DLQ. Provisioned concurrency does not prevent third-party outages.
Q11A CPU-bound Lambda function finishes just inside the timeout. Amazon API Gateway invokes the function synchronously. Metrics show the function uses little of its allocated memory. The team must speed up the function without rewriting the algorithm. They know memory size also controls available CPU. Which solution will meet these requirements?
Answer: B. Lambda CPU scales with the memory setting. Raising memory is how you give a CPU-bound function more compute without a code rewrite.

Good to know: Reserved concurrency would be correct to protect a downstream system. EBS is not an attachable volume for the Lambda runtime.
Q12A Lambda function invoked by Amazon API Gateway must write items to Amazon DynamoDB. Developers must not put AWS access keys in environment variables or in the deployment package. The function already has an execution role attached. The table is private to the account. Which solution will meet these requirements?
Answer: D. Lambda reaches AWS services through its execution role. Embedded access keys violate the constraint against long-lived credentials in the package.

Good to know: A Cognito identity pool would be correct if end-user apps needed temporary AWS credentials. Secrets Manager would be correct for rotating a database password.
Q13A Lambda function currently writes session files to /tmp and expects the next invocation to read them. Amazon API Gateway invokes the function on every HTTP request. Under load, users lose sessions because another execution environment handles the request. The function must remain serverless and store durable session state outside the runtime. Which solution will meet these requirements?
Answer: A. Lambda must stay stateless; durable state belongs in an external store such as DynamoDB. /tmp is per environment and is not shared across invocations.

Good to know: Amazon EC2 or containers would be correct if the stem required long-lived local disk and in-memory state that serverless cannot hold. Provisioned concurrency warms environments; it does not share /tmp.
Q14A public REST API on Amazon API Gateway is overwhelmed by a traffic spike from a partner integration. The backend Lambda is healthy at normal load. The company must limit request rates at the API front door without using Lambda reserved concurrency as the first control. Which solution will meet these requirements?
Answer: C. API Gateway throttling (and usage plans) rate-limits at the managed API front door. Reserved concurrency caps the function, which the stem says not to use first.

Good to know: Reserved concurrency would be correct if the Lambda worker were overwhelming a database. Cognito authenticates users; it is not an HTTP rate limiter.
Q15A chat application needs a managed WebSocket API so browsers can hold persistent connections. The team does not need GraphQL, and message fan-out must not require a GraphQL schema. AWS Lambda should handle connect, message, and disconnect events. They will not run a WebSocket fleet on Amazon EC2. Which solution will meet these requirements?
Answer: B. API Gateway WebSocket APIs are the managed persistent-connection front door with Lambda integrations. AppSync subscriptions assume a GraphQL API.

Good to know: AppSync would be correct if clients needed GraphQL queries plus subscriptions. REST polling is the alternative the live-dashboard scenario rejects.
Q16A video encoder must run for 45 minutes, keep a large in-memory working set, and write checkpoints to local disk during the job. The job is a batch encoder, not an HTTP request handler. The team tried AWS Lambda and hit timeout and ephemeral-storage limits. They want compute without a Lambda-style duration cap. Which solution will meet these requirements?
Answer: D. Long-running, highly stateful work fits Amazon EC2 (or containers) rather than Lambda. Lambda has a maximum duration well below 45 minutes.

Good to know: Lambda would be correct for short event-driven handlers. Provisioned concurrency reduces cold starts; it does not extend the maximum runtime.
Q17A SaaS product needs a managed customer directory with sign-up, sign-in, and JWT tokens for a REST API. Temporary AWS credentials for S3 uploads are not required in this release. IAM Identity Center is already used for employees and must not be the customer directory. Which solution will meet these requirements?
Answer: A. Cognito user pools are application customer identity and JWT issuance. Identity Center is workforce access; an identity pool is for temporary AWS credentials.

Good to know: An identity pool would be correct if the app needed temporary AWS credentials after sign-in. Identity Center remains the employee AWS access portal.
Q18A REST API on Amazon API Gateway serves mostly identical GET responses. Lambda origin load is high because every client hits the integration. Operations wants method-level cache TTLs inside API Gateway, not a separate CDN distribution, and will not rewrite the API as GraphQL. Which solution will meet these requirements?
Answer: C. API Gateway caching is the method-level TTL control on a REST stage. Provisioned concurrency warms Lambda; it does not cache GET bodies.

Good to know: CloudFront would be correct if the stem required a global CDN in front of the API. AppSync would be correct for GraphQL, not a REST cache retrofit.
Q19A company runs a mobile checkout API on Amazon API Gateway and AWS Lambda. The API has sharp bursts and must authenticate customers. The team wants the LEAST custom identity code. An identity pool alone is not a user directory. Lambda must run only after tokens are validated. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. A user pool supplies the directory and JWTs; API Gateway validates them before Lambda. Those two steps are the bursting-checkout pattern.

Good to know: An identity pool would be added if the app also needed temporary AWS credentials. SQS is the burst buffer between producers and workers, not the HTTPS customer API.
Q20A company ingests asynchronous jobs with AWS Lambda. Producers are Amazon EC2 applications in one Region. Those jobs spike beyond what a downstream database can accept. Direct Lambda invoke removes buffering. Provisioned concurrency is already on for latency and did not cap database pressure. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. SQS absorbs bursts; reserved concurrency caps how many workers hit the database. Provisioned concurrency does not provide that ceiling.

Good to know: Provisioned concurrency remains the cold-start control. A connection pooler taught in the databases lesson would help sessions, not replace the queue or the concurrency cap.
Q21The product is a live collaborative dashboard in the browser. Web clients need GraphQL queries and server-pushed updates when data changes. They must not poll a REST API, and they must not place Amazon API Gateway in front of the GraphQL service. Resolvers may read Amazon DynamoDB. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. AppSync is the managed GraphQL front door, and subscriptions provide the push path. Clients call AppSync directly, not through API Gateway.

Good to know: API Gateway WebSocket would be correct for a custom non-GraphQL persistent API. Amplify Hosting is the static front end, not the GraphQL engine.
Q22A company exposes a latency-sensitive Lambda function through Amazon API Gateway. The function has predictable morning traffic and also writes to a database with a connection limit. Cold starts are unacceptable in the morning, and unbounded scale would exhaust the database. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. Provisioned concurrency warms environments for predictable load. Reserved concurrency caps concurrent executions so the database is not overwhelmed.

Good to know: Provisioned concurrency counts toward reserved concurrency, so the reserved value must be at least the provisioned value. SQS would buffer async work, not replace an HTTPS API.
Q23A team needs a hosted static front end and customer sign-in for that app. They do not want Amazon EC2 web servers or IAM users for customers. The API will be added later. Workforce IAM Identity Center must not be the customer directory. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. Amplify Hosting is the managed front-end host; Cognito user pools are customer identity. Identity Center remains workforce AWS access.

Good to know: S3 with CloudFront would also host a static SPA without the Amplify toolchain. An identity pool would be added if the browser needed temporary AWS credentials.
Q24An application invokes AWS Lambda asynchronously. After retries fail, events must land in Amazon SQS for operators. The execution role must be able to deliver those failed events. The team must not use API Gateway cache as the failure store. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Async failures go to an on-failure destination or DLQ, and the execution role must be allowed to send to that queue. Those two steps are jointly required.

Good to know: For SQS event-source mappings, configure a redrive policy on the source queue. Cognito identity pools issue temporary AWS credentials, not failure events.
Q25A Lambda function must persist order records and must not keep them in /tmp across invocations. Orders must survive a cold start on a new execution environment. It must call Amazon DynamoDB without embedded access keys. The function already exists and is invoked by Amazon API Gateway. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. Durable state belongs outside the execution environment, and the execution role is how Lambda is authorized to write to DynamoDB.

Good to know: Embedded keys would be the anti-pattern the execution-role model replaces. API Gateway usage plans throttle callers; they do not store orders.
