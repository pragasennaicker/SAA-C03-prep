01 · VISUAL MAP

See the architecture before memorising the services

Diagram cue: Tool by workload: MGN for servers, DMS for databases, DataSync/Snow for large file movement.
①Match mover to source

Use DMS for databases, DataSync for online file or object transfer, MGN for server replication, Snow devices for offline bulk data, and Transfer Family for managed partner protocols.

②Separate migration from access

A one-time or recurring copy is different from hybrid low-latency access. Storage Gateway presents file, volume, or tape interfaces backed by AWS storage.

③Mark downtime and change flow

Draw initial load, ongoing replication, validation, cutover, rollback, and the point applications stop writing to the source.

④Quantify the network

Compare dataset size, available bandwidth, migration window, encryption, Direct Connect or VPN, and whether an offline Snow workflow is faster.

03 · DEEP DIVE

What you actually need to understand

1

Application Migration Service

  • AWS Application Migration Service (MGN) supports lift-and-shift server migration by continuously replicating source servers.
  • Launch test/cutover instances in AWS after replication.
  • Good when moving whole servers/applications with minimal architectural change.
  • Modernization can happen separately after migration.
2

DMS

  • Database Migration Service moves/replicates supported databases with low-downtime patterns.
  • Full load plus change data capture can keep target synchronized until cutover.
  • Homogeneous and heterogeneous database migrations differ; heterogeneous migrations may require schema conversion.
  • DMS is for database data, not generic file-system migration.
3

DataSync

  • Managed online transfer between on-premises storage, S3, EFS and FSx-related targets/source patterns.
  • Optimizes network transfer and handles integrity/metadata according to supported modes.
  • Use for large file/object transfers when a working network path exists.
  • Can schedule recurring synchronization.
4

Snow Family

  • Physical/edge devices move large datasets when network transfer would take too long or connectivity is constrained.
  • Estimate transfer time from bandwidth before choosing online vs offline methods.
  • Also useful in edge/disconnected processing patterns depending on device/service generation.
  • Physical logistics/security are part of the architecture.
5

Transfer Family + Storage Gateway

  • Transfer Family provides managed SFTP/FTPS/FTP-style endpoints backed by AWS storage.
  • Storage Gateway presents familiar on-premises storage interfaces while integrating with AWS cloud storage.
  • Useful when legacy applications cannot immediately change storage protocols.
  • Direct Connect/VPN can complement these hybrid services but solve connectivity rather than application protocol migration.

05 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Low-downtime database move

Constraint: a production database must move with only a brief cutover. Design: DMS performs full load plus change data capture, with Schema Conversion Tool where engines differ. Why alternatives fail: DataSync copies files, and MGN replicates servers rather than database changes.

1 DMS moves data→2 CDC follows changes→3 SCT converts schema
WORKED SCENARIO

Recurring NAS transfer

Constraint: an on-premises NFS share must synchronize nightly to S3 with verification and bandwidth controls. Design: DataSync agents perform incremental scheduled transfers. Why alternatives fail: Storage Gateway exposes ongoing hybrid access, while Snow devices are offline and not nightly synchronization.

1 DataSync handles files→2 Incremental copies save bandwidth→3 Verification checks transfer
WORKED SCENARIO

Petabyte migration with weak link

Constraint: petabytes must reach AWS while the WAN would take months. Design: use an appropriate AWS Snow device workflow and track encrypted shipment. Why alternatives fail: DataSync remains bandwidth-bound, and Transfer Family does not create physical transport capacity.

1 Snow bypasses WAN→2 Data stays encrypted→3 Capacity drives device choice

07 · KNOWLEDGE CHECK

Five SAA-style questions

Q1A PostgreSQL database must migrate to Amazon Aurora with minimal downtime while source writes continue until cutover. Which service captures ongoing changes?
Answer: A. DMS change data capture replicates ongoing source changes after or during the initial full load.
Q2An enterprise needs scheduled incremental transfers from an on-premises NFS server to S3, including integrity verification. Which service is purpose-built?
Answer: A. DataSync is an online transfer service for file and object storage with scheduling, verification, and network controls.
Q3Hundreds of VMware servers must be continuously replicated to AWS and launched as EC2 instances during cutover. Which migration service fits?
Answer: A. AWS MGN performs block-level server replication and orchestrates test and cutover launches into EC2.
Q4External partners must upload files over SFTP into Amazon S3 while AWS manages the protocol endpoint. Which service should be selected?
Answer: A. Transfer Family provides managed SFTP, FTPS, FTP, and AS2 endpoints backed by S3 or EFS.
Q5On-premises applications need an NFS file share with local caching while objects are durably stored in S3. Which hybrid service meets this pattern?
Answer: A. S3 File Gateway exposes NFS or SMB with local caching and stores files as objects in S3.
