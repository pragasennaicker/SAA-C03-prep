02 · DEEP DIVE

What you actually need to understand

1

Application Migration Service

  • AWS Application Migration Service (MGN) supports lift-and-shift server migration by continuously replicating source servers.
  • Launch test/cutover instances in AWS after replication.
  • Good when moving whole servers/applications with minimal architectural change.
  • Modernization can happen separately after migration.
2

DMS

  • Database Migration Service moves/replicates supported databases with low-downtime patterns.
  • Full load plus change data capture can keep target synchronized until cutover.
  • Homogeneous and heterogeneous database migrations differ; heterogeneous migrations may require schema conversion.
  • DMS is for database data, not generic file-system migration.
3

DataSync

  • Managed online transfer between on-premises storage, S3, EFS and FSx-related targets/source patterns.
  • Optimizes network transfer and handles integrity/metadata according to supported modes.
  • Use for large file/object transfers when a working network path exists.
  • Can schedule recurring synchronization.
4

Snow Family

  • Physical/edge devices move large datasets when network transfer would take too long or connectivity is constrained.
  • Estimate transfer time from bandwidth before choosing online vs offline methods.
  • Also useful in edge/disconnected processing patterns depending on device/service generation.
  • Physical logistics/security are part of the architecture.
5

Transfer Family + Storage Gateway

  • Transfer Family provides managed SFTP/FTPS/FTP-style endpoints backed by AWS storage.
  • Storage Gateway presents familiar on-premises storage interfaces while integrating with AWS cloud storage.
  • Useful when legacy applications cannot immediately change storage protocols.
  • Direct Connect/VPN can complement these hybrid services but solve connectivity rather than application protocol migration.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Low-downtime database move

Constraint: a production database must move with only a brief cutover. Design: DMS performs full load plus change data capture, with Schema Conversion Tool where engines differ. Why alternatives fail: DataSync copies files, and MGN replicates servers rather than database changes.

1 DMS moves data→2 CDC follows changes→3 SCT converts schema
WORKED SCENARIO

Recurring NAS transfer

Constraint: an on-premises NFS share must synchronize nightly to S3 with verification and bandwidth controls. Design: DataSync agents perform incremental scheduled transfers. Why alternatives fail: Storage Gateway exposes ongoing hybrid access, while Snow devices are offline and not nightly synchronization.

1 DataSync handles files→2 Incremental copies save bandwidth→3 Verification checks transfer
WORKED SCENARIO

Petabyte migration with weak link

Constraint: petabytes must reach AWS while the WAN would take months. Design: use an appropriate AWS Snow device workflow and track encrypted shipment. Why alternatives fail: DataSync remains bandwidth-bound, and Transfer Family does not create physical transport capacity.

1 Snow bypasses WAN→2 Data stays encrypted→3 Capacity drives device choice

06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A retailer must move 200 on-premises application servers to AWS with as little redesign as possible. Each server should be replicated continuously, then launched as Amazon EC2 instances at cutover. The company is not treating databases as a separate CDC project and does not need a file-transfer tool. Which solution will meet these requirements?
Answer: A. MGN is lift-and-shift server replication with test and cutover onto EC2. DMS moves database data, and DataSync and Transfer Family move files, not whole servers.

Good to know: Modernize after cutover if needed. DMS would be correct if the stem were a database full load plus CDC with a brief cutover.
Q2A company is using AWS Application Migration Service to move factory Windows and Linux servers. Before production cutover, operators must launch instances in AWS, validate the applications, and only then switch users. Architectural redesign can wait until after the move. The team is not using database CDC or a file-transfer tool as the server test path. Which solution will meet these requirements?
Answer: C. MGN continuously replicates source servers and supports launching test and cutover instances in EC2 so validation happens before users move.

Good to know: DMS is database CDC, not a server test path. Snow Family is physical dataset transport when the WAN cannot carry petabytes.
Q3A production PostgreSQL database on premises must move to Amazon RDS for PostgreSQL. Writes must continue on the source until a brief cutover. The team needs an initial copy plus ongoing replication of changes and is not moving file shares or whole servers. The engines already match, so schema conversion is not the deciding constraint. Which solution will meet these requirements?
Answer: B. DMS full load plus CDC keeps a supported database target synchronized until cutover. Homogeneous engine pairs still use DMS for the data movement.

Good to know: MGN would be correct if the constraint were lift-and-shift of the whole server. DataSync copies files and objects, not database CDC.
Q4An on-premises Oracle database must move to Amazon Aurora PostgreSQL with only a short outage. Table data must be copied and then kept current with source writes. The engines differ, so schema objects cannot be assumed to match without conversion. Copying data files with a NAS tool will not keep the target synchronized. Which solution will meet these requirements?
Answer: D. Heterogeneous migrations may need schema conversion, then DMS full load plus CDC for low-downtime data movement. DMS is not a file copier.

Good to know: Homogeneous moves can skip conversion when the engines already match. MGN replicates servers, not database change streams.
Q5A factory keeps millions of files on an on-premises NFS NAS. The files must copy to Amazon S3 over the existing WAN on a nightly schedule, and each transfer must be verified. The company is not migrating servers or databases, and the network path is already working. Applications do not need a local NFS cache after the copy. Which solution will meet these requirements?
Answer: A. DataSync is the online file and object transfer service with scheduling and integrity checks when a working network path exists.

Good to know: Storage Gateway File Gateway would be correct for ongoing local NFS access with S3 as the durable store, not a scheduled one-way migration. Snow Family is for when the WAN cannot finish the job.
Q6Linux applications in AWS must read a POSIX file system. The source is an on-premises NFS export that should be copied online, with validation, onto Amazon EFS. A working network path already exists, and the team does not want a physical appliance shipment. The team needs a managed file copy, not database CDC or server cutover. Which solution will meet these requirements?
Answer: C. DataSync moves large file datasets between on-premises NAS, S3, EFS, and FSx when the network can carry the transfer.

Good to know: Snow Family is the offline answer when bandwidth would take too long. File Gateway would apply if the Linux apps still needed a local NFS cache instead of a copy onto EFS.
Q7A company must copy a large on-premises file share into an Amazon FSx file system in AWS. A reliable network path already exists, and operators want managed online transfer with integrity checking rather than a petabyte-scale physical shipment. Servers and databases are out of scope. Which solution will meet these requirements?
Answer: B. DataSync supports online transfers to FSx-related targets when the network is usable. DMS and MGN address databases and servers, not this file copy.

Good to know: Transfer Family is the managed SFTP, FTPS, or FTP endpoint into S3 or EFS when partners must keep those protocols. Snow Family is the weak-WAN physical path.
Q8A media archive of several petabytes must reach Amazon S3. The data center WAN would take many months at the available bandwidth, and the company will not wait for that online copy. Files are cold objects, not a running database or a fleet of application servers. Which solution will meet these requirements?
Answer: D. Snow Family is physical transfer for petabyte-scale datasets when the network is too slow or too constrained. Online tools stay bandwidth-bound.

Good to know: DataSync is correct when a working network can finish the copy on an acceptable schedule. Transfer Family does not add WAN capacity.
Q9External partners must keep using SFTP to upload files. AWS should operate the protocol endpoint, and objects must land in Amazon S3. The company already has private connectivity but does not want to run SFTP servers on Amazon EC2. Direct Connect and VPN are already available for network paths and must not be treated as the SFTP service. Which solution will meet these requirements?
Answer: A. Transfer Family is the managed SFTP, FTPS, or FTP endpoint backed by S3 or EFS. Connectivity services do not replace that protocol endpoint.

Good to know: DataSync is scheduled NAS and object transfer with a working network, not a partner SFTP front door. File Gateway is local NFS or SMB cache in front of S3.
Q10A supplier still uses FTPS clients that cannot be rewritten this quarter. Files must land in Amazon EFS so Linux applications can mount them. The company wants AWS to manage the FTP-style endpoint rather than EC2 FTP daemons. Partners will not install DataSync agents, and SFTP is not the only client protocol in use. Which solution will meet these requirements?
Answer: C. Transfer Family provides managed FTP and FTPS as well as SFTP, and it can store files in S3 or EFS.

Good to know: File Gateway presents NFS (or SMB) on premises while objects live in S3; it is not the managed internet FTP service. DataSync is online sync, not an FTP endpoint.
Q11On-premises applications must keep using an NFS file share with local caching. New files should be stored durably as objects in Amazon S3. This is ongoing hybrid access, not a one-time migration of a NAS, and the applications cannot change protocols this year. A scheduled copy job is not an acceptable file interface for those applications. Which solution will meet these requirements?
Answer: B. S3 File Gateway exposes NFS with a local cache and keeps objects in S3, which is the hybrid interface the lesson teaches.

Good to know: DataSync is the scheduled online copy when you are moving files, not keeping a local NFS facade. Volume and tape gateways exist in the family but are not the NFS-plus-S3 pattern this lesson quizzes.
Q12Factory software must continue to mount NFS on the plant network while objects are retained in Amazon S3. Operators considered a nightly DataSync job, but the applications need a live local file interface rather than a batch copy. The software cannot switch to SFTP, and a Snow device is not a daily NFS server. Which solution will meet these requirements?
Answer: D. File Gateway is ongoing hybrid access. DataSync is transfer and synchronization; it does not replace a local NFS mount for applications that cannot change.

Good to know: Transfer Family would win if partners had to keep SFTP into S3 or EFS. Snow Family is offline bulk movement, not a daily NFS server.
Q13Partners must upload over SFTP into Amazon S3. The company already has AWS Direct Connect for private IP connectivity to VPCs. Direct Connect does not terminate SFTP for those partners, and the team will not run SFTP on Amazon EC2. A Site-to-Site VPN is also not an SFTP application endpoint. Which solution will meet these requirements?
Answer: A. Direct Connect and VPN provide connectivity. They do not migrate or replace the SFTP application protocol. Transfer Family is that managed endpoint.

Good to know: The same split applies to File Gateway: DX or VPN can carry NFS traffic, but the hybrid file interface is still Storage Gateway.
Q14A company must copy a 20 TB NFS dataset to Amazon S3. The WAN can finish the job in a few days, and operators want scheduled incremental runs with integrity verification. Petabyte-scale physical shipping is unnecessary. The source is a file system, not a database, and servers are not being lifted to Amazon EC2. Which solution will meet these requirements?
Answer: C. When a working network can complete the file copy, DataSync is the online tool. Snow Family is for when bandwidth would take too long.

Good to know: Estimate transfer time from bandwidth before choosing online versus offline. MGN and DMS remain the wrong movers for a NAS file dataset.
Q15An on-premises NFS file server holds application documents that must move to Amazon S3. A colleague suggested AWS Database Migration Service because the documents are important. The source is a file system, not a database, and a working network path exists. Schema conversion and server replication are the wrong movers for this dataset. Which solution will meet these requirements?
Answer: B. DMS is for database data, not generic file-system migration. DataSync is the online file and object mover when the network exists.

Good to know: MGN is equally wrong here because it replicates servers, not document trees. File Gateway would apply if the apps still needed a local NFS cache.
Q16A production MySQL database must move to Amazon Aurora MySQL with ongoing replication until cutover. A colleague suggested AWS Application Migration Service because the database runs on a server. The requirement is database change capture, not lift-and-shift of the host. Copying table files with a NAS tool will not apply in-flight transactions. Which solution will meet these requirements?
Answer: D. MGN replicates servers for lift-and-shift onto EC2. Database CDC and full load are DMS, including homogeneous MySQL-to-Aurora patterns.

Good to know: MGN can still move a database host if the exam asks to lift the whole server unchanged. This stem’s deciding constraint is database CDC.
Q17Hundreds of VMware virtual machines must be continuously replicated into AWS and launched as Amazon EC2 instances during a planned cutover. The company wants lift-and-shift with later modernization. File sync and database CDC tools are not the right mover for the VM fleet. Test launches should happen before users are switched. Which solution will meet these requirements?
Answer: A. MGN is the server replication and cutover path onto EC2. DataSync, DMS, and Transfer Family match files, databases, and FTP-style protocols.

Good to know: Test launches in MGN come before production cutover. Do not use MGN when the stem is only CDC between database engines.
Q18A studio must move 8 PB of video masters to Amazon S3. Online tools were estimated to need many months on the current WAN. The company will accept physical logistics and encryption in transit to AWS. Partners do not need SFTP, and no database cutover is involved. Which solution will meet these requirements?
Answer: C. Petabytes plus a weak or slow WAN select Snow Family physical transfer. Protocol and database services do not create that capacity.

Good to know: If the estimate showed days rather than months, DataSync over the existing path would be the online answer. Device generation follows capacity and edge needs, which this lesson does not pin to a quota number.
Q19A company will lift-and-shift 80 application servers to Amazon EC2 using AWS Application Migration Service. Operators must keep replicating the sources, launch instances to validate the applications, and then cut over users. Database CDC and file-transfer services are not the server mover. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. MGN’s pattern is continuous server replication plus test and cutover launches into EC2. Those two steps are jointly required for a controlled lift-and-shift.

Good to know: DMS remains the database full-load-plus-CDC answer. DataSync does not replace block-level server replication.
Q20A production SQL Server database must move to Amazon RDS for SQL Server with only a brief cutover. Source writes must continue until the switch. The move is homogeneous, so schema conversion is not the deciding problem. The team must not use a file copier or a server replication tool as the CDC path. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. Low-downtime database migration is full load plus CDC in DMS. Homogeneous engine pairs still need both steps when writes continue until cutover.

Good to know: Add schema conversion when the stem is heterogeneous. MGN would be correct for lifting the whole database host as a server.
Q21An on-premises Oracle database must move to Amazon Aurora PostgreSQL. Data must be copied and then kept current with source changes, and the engines differ so objects cannot be assumed to match. File copy and server replication will not convert schema or capture database changes. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Heterogeneous migrations may require schema conversion. DMS then moves and replicates the data with full load plus CDC until cutover.

Good to know: Skip conversion when source and target engines already match. File and server tools do not perform database CDC.
Q22An on-premises NFS NAS must synchronize to Amazon S3 every night. Operators need incremental copies, integrity verification, and bandwidth-aware online transfer. The WAN is sufficient, and this is not a database or server move. Applications do not need a persistent local NFS cache after each copy. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. DataSync is the online NAS-to-S3 mover. Scheduling and integrity checks are the operational controls the lesson pairs with that transfer.

Good to know: File Gateway would be the answer if applications still needed a local NFS cache in front of S3. Snow Family is offline bulk movement.
Q23Several petabytes of backups must reach Amazon S3. Bandwidth calculations show the current WAN would take months. The company will use a physical device workflow and track encrypted shipment. Online file transfer and SFTP endpoints cannot add that transport capacity. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. Snow Family bypasses a weak WAN with physical transport. Device choice follows capacity; logistics and encryption are part of the architecture.

Good to know: DataSync remains correct when the network can finish in an acceptable time. Transfer Family does not create physical transport capacity.
Q24External partners must keep SFTP clients and upload into Amazon S3. AWS must operate the protocol endpoint so the company does not manage SFTP on Amazon EC2. Direct Connect already exists for private VPC access but does not provide SFTP. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Transfer Family is the managed SFTP service, and S3 is the taught durable backend (EFS is the other). DX is connectivity, not a protocol endpoint.

Good to know: FTPS and FTP are the same Transfer Family family of endpoints when clients are not SFTP. File Gateway is for on-premises NFS in front of S3.
Q25On-premises applications must keep an NFS mount with local caching while files are stored as objects in Amazon S3. This is ongoing hybrid access, not a one-time NAS copy, and the applications will not switch to SFTP. A scheduled DataSync job is not an acceptable live file interface. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. File Gateway is the hybrid NFS interface with an S3 object store behind a local cache. Both the gateway and the NFS-plus-S3 mapping are required.

Good to know: DataSync would be correct for scheduled online migration of the share. Transfer Family is for partners that must keep SFTP, FTPS, or FTP.
