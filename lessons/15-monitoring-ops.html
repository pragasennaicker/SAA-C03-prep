01 · VISUAL MAP

See the architecture before memorising the services

Diagram cue: CloudTrail answers who called which API; Config answers what the resource configuration was.
①Assign each evidence source

CloudWatch holds metrics, logs, alarms, and events; CloudTrail records API activity; Config evaluates resource configuration and history.

②Separate observe from act

Draw the alarm or compliance signal, EventBridge routing, automation target, approval boundary, and rollback path.

③Prefer managed fleet access

Use Systems Manager Session Manager, Run Command, Patch Manager, and State Manager instead of inbound SSH and manually maintained bastions where supported.

④Show governance hierarchy

Map organizations, OUs, accounts, Control Tower guardrails, SCP boundaries, Config rules, and CloudFormation StackSets without treating SCPs as grants.

03 · DEEP DIVE

What you actually need to understand

1

CloudWatch

  • Collects/observes metrics, logs and alarms across AWS workloads.
  • CloudWatch Logs centralizes logs; metric filters can derive metrics from log events.
  • Alarms can notify or trigger automated actions and scaling.
  • Dashboards visualize operational health; use application-specific metrics when infrastructure metrics are insufficient.
2

CloudTrail

  • Records AWS API/account activity for audit and investigation.
  • Management events capture control-plane actions; data events can capture high-volume resource-level operations for supported services when enabled.
  • Organization trails can centralize multi-account auditing.
  • If the question asks 'who changed/deleted/created this resource?', CloudTrail is usually central.
3

AWS Config

  • Records resource configuration changes and relationships.
  • Config Rules evaluate configurations against desired conditions/compliance standards.
  • Conformance packs group rules/remediation patterns.
  • Use when the question asks whether resource configuration is compliant, not who called the API.
4

Systems Manager + CloudFormation

  • Systems Manager provides fleet inventory, patching, Session Manager, automation and Parameter Store among other operational capabilities.
  • Session Manager can provide shell access without opening inbound SSH when configured appropriately.
  • CloudFormation defines infrastructure as code for repeatable deployments.
  • Immutable/reproducible infrastructure improves reliability and recovery.
5

Governance + optimization

  • Control Tower establishes/governs a multi-account landing zone using AWS Organizations and controls.
  • Trusted Advisor surfaces best-practice checks according to account/support availability.
  • Compute Optimizer recommends rightsizing for supported resources.
  • AWS Health Dashboard reports AWS events affecting services/resources; License Manager and Service Catalog address specialized governance.

05 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Who changed the security group?

Constraint: investigators need the identity, time, source, and API call that modified a security group. Design: search CloudTrail event history or a centralized trail. Why alternatives fail: CloudWatch metrics show behavior, and Config history shows configuration change but is not the primary API caller record.

1 CloudTrail records API→2 Identity appears in event→3 Central trails aid audit
WORKED SCENARIO

No-ingress server administration

Constraint: operators must access private EC2 instances without opening port 22 or distributing SSH keys. Design: use SSM Session Manager with managed-instance permissions and connectivity. Why alternatives fail: a bastion still needs inbound access, and CloudFormation is not an interactive shell.

1 Session Manager avoids inbound→2 IAM controls sessions→3 Logs support audit
WORKED SCENARIO

Governed multi-account growth

Constraint: new accounts need repeatable baselines, centralized logging, and preventive or detective controls. Design: Control Tower establishes the landing zone and guardrails, with Organizations and account factory. Why alternatives fail: Config alone does not provision accounts, and CloudFormation alone lacks landing-zone governance.

1 Control Tower builds baseline→2 Guardrails govern OUs→3 Account factory standardizes

07 · KNOWLEDGE CHECK

Five SAA-style questions

Q1Security asks which principal called DeleteBucket and from which IP address yesterday. Which AWS service provides the authoritative API activity event?
Answer: A. CloudTrail management events record API calls with identity, timestamp, source IP, request, and response details.
Q2A team must detect that an S3 bucket became public and view how its configuration changed over time. Which service directly tracks this state?
Answer: A. Config records resource configuration history and evaluates resources against compliance rules.
Q3Administrators need shell access to private EC2 instances without inbound ports, bastions, or SSH keys. Which Systems Manager feature is designed for this?
Answer: A. Session Manager brokers IAM-controlled sessions through the SSM service without requiring inbound SSH.
Q4A CloudFormation stack resource was manually modified, and operators need to identify divergence from its template. Which feature should they run?
Answer: A. Drift detection compares supported resources' actual configuration with expected CloudFormation properties.
Q5A company needs a governed multi-account landing zone with account vending and preconfigured controls. Which service provides the highest-level solution?
Answer: A. Control Tower orchestrates a landing zone, account factory, centralized controls, and guardrails using underlying AWS services.
