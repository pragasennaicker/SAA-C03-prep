02 · DEEP DIVE

What you actually need to understand

1

CloudWatch

  • Collects/observes metrics, logs and alarms across AWS workloads.
  • CloudWatch Logs centralizes logs; metric filters can derive metrics from log events.
  • Alarms can notify or trigger automated actions and scaling.
  • Dashboards visualize operational health; use application-specific metrics when infrastructure metrics are insufficient.
2

CloudTrail

  • Records AWS API/account activity for audit and investigation.
  • Management events capture control-plane actions; data events can capture high-volume resource-level operations for supported services when enabled.
  • Organization trails can centralize multi-account auditing.
  • If the question asks 'who changed/deleted/created this resource?', CloudTrail is usually central.
3

AWS Config

  • Records resource configuration changes and relationships.
  • Config Rules evaluate configurations against desired conditions/compliance standards.
  • Conformance packs group rules/remediation patterns.
  • Use when the question asks whether resource configuration is compliant, not who called the API.
4

Systems Manager + CloudFormation

  • Systems Manager provides fleet inventory, patching, Session Manager, automation and Parameter Store among other operational capabilities.
  • Session Manager can provide shell access without opening inbound SSH when configured appropriately.
  • CloudFormation defines infrastructure as code for repeatable deployments.
  • Immutable/reproducible infrastructure improves reliability and recovery.
5

Governance + optimization

  • Control Tower establishes/governs a multi-account landing zone using AWS Organizations and controls.
  • Trusted Advisor surfaces best-practice checks according to account/support availability.
  • Compute Optimizer recommends rightsizing for supported resources.
  • AWS Health Dashboard reports AWS events affecting services/resources; License Manager and Service Catalog address specialized governance.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Who changed the security group?

Constraint: investigators need the identity, time, source, and API call that modified a security group. Design: search CloudTrail event history or a centralized trail. Why alternatives fail: CloudWatch metrics show behavior, and Config history shows configuration change but is not the primary API caller record.

1 CloudTrail records API→2 Identity appears in event→3 Central trails aid audit
WORKED SCENARIO

No-ingress server administration

Constraint: operators must access private EC2 instances without opening port 22 or distributing SSH keys. Design: use SSM Session Manager with managed-instance permissions and connectivity. Why alternatives fail: a bastion still needs inbound access, and CloudFormation is not an interactive shell.

1 Session Manager avoids inbound→2 IAM controls sessions→3 Logs support audit
WORKED SCENARIO

Governed multi-account growth

Constraint: new accounts need repeatable baselines, centralized logging, and preventive or detective controls. Design: Control Tower establishes the landing zone and guardrails, with Organizations and account factory. Why alternatives fail: Config alone does not provision accounts, and CloudFormation alone lacks landing-zone governance.

1 Control Tower builds baseline→2 Guardrails govern OUs→3 Account factory standardizes

06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A retail company runs an Auto Scaling group of Amazon EC2 web servers behind an Application Load Balancer in two Availability Zones. Operators need CPU utilization on a graph, a threshold that pages the on-call channel, and scale-out when the fleet is hot. They do not need API caller identity or configuration-history reports. Which solution will meet these requirements?
Answer: A. CPU, paging, and scale-out are CloudWatch metrics and alarms. CloudTrail is API audit; Config is configuration compliance, not live utilization.

Good to know: CloudTrail would be correct if the stem asked which principal launched or terminated instances. Config would win for whether the group’s settings stayed compliant over time.
Q2A payments team stores application logs in Amazon CloudWatch Logs. Security wants a numeric metric whenever a log line contains PAYMENT_FAIL, and an alarm when that count exceeds a limit in five minutes. The team must not parse logs on Amazon EC2 and does not need a record of which IAM principal called which API. Which solution will meet these requirements?
Answer: C. Metric filters derive CloudWatch metrics from log events, and alarms fire on those metrics. CloudTrail records API callers, not application log patterns.

Good to know: CloudTrail would be the answer if investigators needed who called FilterLogEvents. Config would apply if the question was whether the log group’s retention setting stayed compliant.
Q3A site-reliability team supports a three-tier application in one VPC across two Availability Zones. They want one screen that graphs Amazon EC2 CPU, Application Load Balancer 5xx count, and Amazon RDS connections. The services already emit CloudWatch metrics. The team does not need API audit tables or configuration timelines. Which solution will meet these requirements?
Answer: B. Operational health visualization across metrics is a CloudWatch dashboard. CloudTrail and Config do not replace metric graphs for CPU, 5xx, and connections.

Good to know: CloudTrail would be correct for who changed the load balancer. Config would be correct for how the RDS instance’s configuration changed over weeks.
Q4A media company stores objects in a private Amazon S3 bucket in one Region. Security investigators need the IAM principal, source IP address, and time that called DeleteBucket on that bucket yesterday. The bucket’s current public-access block setting is already known. The team needs the API activity event, not a configuration snapshot. Which solution will meet these requirements?
Answer: D. Who called which API, from which IP, and when is CloudTrail. Config shows how the resource was configured, not the caller record.

Good to know: Config would be correct if the stem asked whether the bucket was public and how that setting changed. CloudWatch would win for storage size or request metrics.
Q5A company must record which IAM principal read a specific object in a private Amazon S3 bucket, including the source IP. An organization trail already logs management events. Object-level GetObject activity is not captured today. Configuration history of the bucket policy is out of scope. Which solution will meet these requirements?
Answer: A. S3 object-level reads are data events, which a trail does not capture until you enable them. Management events cover control-plane calls such as CreateBucket, not GetObject.

Good to know: Management events alone would be enough if the stem asked who created or deleted the bucket. Config would win for whether the bucket policy was public, not who downloaded an object.
Q6A security team governs a growing AWS Organizations structure with many member accounts. They must collect API history from every account into one destination bucket. New member accounts must emit events without a per-account setup ticket. The team needs caller identity and source IP, not resource configuration snapshots. Which solution will meet these requirements?
Answer: C. An organization trail centralizes API audit from current and future member accounts. Config snapshots are configuration state, not the caller-and-IP record.

Good to know: Control Tower would appear if the stem also required a landing zone, account vending, and guardrails rather than only a multi-account trail. Per-account trails would fail the no-ticket-for-new-accounts constraint.
Q7A healthcare company stores objects in Amazon S3 in one account. Compliance must prove whether a bucket was public last month and how its bucket policy and public-access block settings changed over that period. Investigators do not need the IAM user who called PutBucketPolicy and will not parse CloudWatch metrics for this proof. Which solution will meet these requirements?
Answer: B. Was the bucket public and how configuration changed is Config history. CloudTrail answers who called the API, which this stem explicitly does not need.

Good to know: CloudTrail would be correct if the stem asked which principal and IP issued PutBucketPolicy. Use both when auditors want caller identity and configuration timeline.
Q8A bank runs Amazon EC2 in a VPC with many security groups. It requires continuous evaluation of whether those groups allow inbound 0.0.0.0/0 on port 22. Operations wants noncompliant groups listed over time against a desired condition. The question is configuration compliance, not which principal changed a rule yesterday. Which solution will meet these requirements?
Answer: D. Config rules evaluate resource configuration against a desired condition and keep a compliance history. CloudTrail would identify who changed a rule, not whether the current config is compliant.

Good to know: CloudTrail is the answer when investigators need the identity and source IP for the API that opened port 22. Conformance packs group many such rules when the stem asks for a pack rather than one rule.
Q9A software company runs Amazon EC2 application instances in private subnets in two Availability Zones. Administrators must open a shell on those instances. The security team forbids inbound SSH, bastion hosts, and distributing SSH keys. Instances already run the SSM Agent and can reach Systems Manager. Which solution will meet these requirements?
Answer: A. Session Manager brokers IAM-controlled shells without inbound SSH, bastions, or host keys. A bastion still needs inbound access, which the stem forbids.

Good to know: A bastion would appear if Session Manager were unavailable and inbound SSH from a locked CIDR were allowed. CloudFormation provisions infrastructure; it is not an interactive shell.
Q10A company runs a fleet of Amazon EC2 instances in private subnets behind an Application Load Balancer. It must apply OS patches on a schedule and report patch compliance. Operators will not log in to each host, will not open inbound SSH, and will not build a custom patch farm on EC2. Which solution will meet these requirements?
Answer: C. Patch Manager plus a maintenance window is the managed fleet-patching path. CloudTrail validation protects log integrity; it does not patch operating systems.

Good to know: Session Manager would be correct if the stem asked for an interactive shell without SSH. Inventory would win if the need were installed-package lists rather than applying patches.
Q11Amazon EC2 application servers must retrieve a runtime configuration string and an API endpoint URL without baking them into the AMI. The operations team already uses AWS Systems Manager and does not want a custom configuration database. Rotation of database credentials is not in scope. Which solution will meet these requirements?
Answer: B. Parameter Store is the Systems Manager store for configuration strings the fleet can retrieve at runtime. Dashboards, Config, and CloudTrail are not a parameter database.

Good to know: AWS Secrets Manager would be the nearer answer if the stem required managed rotation of database credentials. Config would win for tracking whether an instance’s recorded configuration stayed compliant.
Q12A platform team manages Amazon EC2 instances in private subnets with the SSM Agent installed. Operators must run a documented multi-step runbook: stop a process, apply a patch document, then restart a service. They will not SSH to each host and will not write a custom orchestrator on EC2. Which solution will meet these requirements?
Answer: D. Systems Manager Automation runs multi-step operational documents against managed instances without inbound SSH. Dashboards and trails do not orchestrate a patch-and-restart runbook.

Good to know: Patch Manager alone would be enough if the stem only required scheduled OS patching. Session Manager would win for an interactive shell rather than an unattended runbook.
Q13An application team must provision the same VPC, subnets, and Auto Scaling group in three AWS accounts in one Region. Console clicking last quarter produced drift between accounts. The company wants declarative templates and repeatable updates rather than a runbook of console steps or a new landing zone. Which solution will meet these requirements?
Answer: A. CloudFormation is infrastructure as code for repeatable stacks across accounts. Ops notes and Trusted Advisor checks do not provision the network as a template.

Good to know: Control Tower would be correct if the stem required a governed landing zone and account vending, not only identical application stacks. Drift detection then finds later console edits on those stacks.
Q14A platform team deployed an Application Load Balancer and security groups from an AWS CloudFormation stack in one account. An engineer later changed a listener in the console. Operators need to identify which stack resources no longer match the template before the next update and are not asking who made the API call. Which solution will meet these requirements?
Answer: C. Drift detection compares supported resources’ actual configuration with the stack template. CloudTrail Insights looks for unusual API activity, not template divergence.

Good to know: CloudTrail would tell you who changed the listener. AWS Config would show the security group’s configuration history even for resources not in a stack.
Q15A company is expanding from one AWS account to many member accounts in AWS Organizations. New accounts must receive a repeatable baseline, centralized logging, and preventive or detective controls without a custom landing-zone engineering project. Account vending must be self-service for approved application teams. Which solution will meet these requirements?
Answer: B. Control Tower establishes a landing zone, guardrails, and Account Factory on Organizations. Config in one account does not vend accounts or install the baseline.

Good to know: CloudFormation alone would be correct for repeating one application stack, not a multi-account landing zone. Organizations without Control Tower would still leave landing-zone assembly to the customer.
Q16A solutions architect reviews a single AWS account that already runs production workloads. They need best-practice checks for idle load balancers, unassociated Elastic IP addresses, and MFA on the root user. The company does not need a new multi-account landing zone. Support already includes the relevant Trusted Advisor checks. Which solution will meet these requirements?
Answer: D. Trusted Advisor surfaces best-practice checks on the account, including cost and security findings when the support level includes them. Health Dashboard reports AWS service events, not idle-EIP checks.

Good to know: Health Dashboard would be correct if AWS had an incident affecting a service you use. Control Tower would win for landing-zone account vending rather than in-account best-practice checks.
Q17A company runs over-provisioned Amazon EC2 instances and Auto Scaling groups in one production Region. CloudWatch utilization metrics already exist. The team wants machine-learning recommendations to right-size those supported resources. They are not asking who called RunInstances and are not building a landing zone. Which solution will meet these requirements?
Answer: A. Compute Optimizer recommends rightsizing for supported resources from utilization metrics. CloudTrail identifies API callers; it does not recommend instance sizes.

Good to know: Trusted Advisor also has some cost checks, but Compute Optimizer is the rightsizing-recommendation service the stem asked for. Cost Explorer (Lesson 16) analyzes spend; it does not output EC2 size findings.
Q18An application team runs Amazon RDS in one Region and must know when AWS has a service event that affects those databases. They do not need rightsizing advice, a new account factory, or an API caller list. On-call engineers should see AWS-side incidents, not only their own CloudWatch CPU alarms. Which solution will meet these requirements?
Answer: C. Health Dashboard reports AWS events that affect services and resources. Compute Optimizer rightsizes; Control Tower vends accounts; drift compares templates.

Good to know: Trusted Advisor would be correct for best-practice findings about your configuration, such as idle resources. CloudWatch alarms would win for your RDS CPU, not an AWS Regional service event.
Q19A support team stores API error lines in Amazon CloudWatch Logs. They need a custom metric counted from matching log events and an alarm that pages when errors spike. They will not run a parser on EC2 and do not need configuration snapshots. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. A metric filter turns matching log events into a metric, and an alarm on that metric pages the team. Both steps are required for log-derived alerting.

Good to know: Config would be correct if the need were log-group retention compliance. CloudTrail would win for who called PutLogEvents, not application error lines.
Q20Security must audit which principal called DeleteDBInstance in every member account of AWS Organizations, including source IP. New Organization accounts must be included automatically without a per-account trail ticket. Configuration compliance of the Amazon RDS databases is out of scope. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. DeleteDBInstance is a management event. An organization trail with management events supplies caller and IP from every current and future member account.

Good to know: Config would be correct if the stem asked whether instances were publicly accessible. Data events would appear if the need were S3 object-level reads rather than control-plane deletes.
Q21Auditors review Amazon S3 buckets in one AWS account. They ask whether any bucket is public and how each bucket’s public-access block settings changed over the last 90 days. They are not asking which IAM user called PutBucketAcl and do not need CloudWatch object-count graphs. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Config recording supplies configuration history; a Config rule evaluates whether buckets are public. Together they answer state-over-time and compliance, not API caller identity.

Good to know: CloudTrail would be the pair with a trail if the stem asked who made the bucket public. CloudWatch object-count graphs do not show public-access configuration.
Q22A company runs Amazon EC2 instances in private subnets in two Availability Zones. Operators need interactive shells on those instances. Security forbids inbound SSH, bastion hosts, and SSH key distribution. Instances already run the SSM Agent and can reach Systems Manager endpoints. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. Session Manager needs IAM permissions on the instance role and is the shell path that avoids inbound SSH. Bastions and public port 22 violate the security constraint.

Good to know: A VPC endpoint for Systems Manager would appear if the stem said instances had no NAT and still must not use the internet path. Patch Manager would win for scheduled OS patching rather than a shell.
Q23A platform team must deploy identical VPC networking stacks in two AWS accounts from one template and later detect console edits that diverged from that template. Click-ops is not acceptable for the initial build, and the company is not asking for a Control Tower landing zone. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. CloudFormation provides the repeatable template; drift detection then finds resources that no longer match it. Both are required for the build-and-detect story.

Good to know: AWS Config would still track configuration if the resources were not in a stack. Control Tower would be the answer for a full landing zone rather than one network template.
Q24A company is moving from one AWS account to many. It needs a governed multi-account landing zone, self-service account vending, and guardrails on organizational units. A single AWS Config recorder in one account is not enough, and CloudWatch dashboards are not an account factory. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Control Tower on Organizations is the landing-zone service; Account Factory is how approved teams vend accounts with the baseline. Config alone does not provision accounts.

Good to know: CloudFormation would still deploy individual stacks inside those accounts. Organizations without Control Tower leaves landing-zone guardrails and vending as a custom project.
Q25A platform team in a shared AWS account must let projects launch only approved AMIs from a catalog and must track Windows Server license counts on Amazon EC2 against entitlements. Ad-hoc console stacks and untracked BYOL instances are forbidden. The team is not building a landing zone. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. Service Catalog constrains teams to approved products. License Manager tracks and can enforce license entitlements. The two governance needs are independent and both required.

Good to know: Control Tower would appear if the stem required account vending and landing-zone guardrails. CloudTrail would win for who launched an instance, not for license counting or a product catalog.
