02 · DEEP DIVE

What you actually need to understand

1

Compute economics

  • Right-size from observed utilization and performance requirements.
  • Use Auto Scaling so idle peak capacity is not permanently provisioned.
  • Savings Plans reduce cost for predictable committed compute usage.
  • Spot lowers price for interruption-tolerant workloads; combine with diversified/replaceable designs.
  • Serverless/Fargate may reduce idle infrastructure and ops cost but compare total usage economics.
2

Storage economics

  • S3 lifecycle transitions automate movement to cheaper classes as access decreases.
  • Intelligent-Tiering helps unknown/changing access patterns.
  • Delete obsolete snapshots, unattached volumes and expired objects according to retention requirements.
  • Provision EBS performance independently when possible instead of over-sizing capacity purely for performance.
  • One Zone classes cost less because they trade multi-AZ resilience.
3

Database economics

  • Right-size DB instance families and storage/IOPS.
  • Use serverless/autoscaling database capacity for variable workloads where appropriate.
  • Caching can reduce expensive repeated database reads but adds cache cost/complexity.
  • Read replicas solve performance; do not add them when there is no read-scale requirement.
  • Choose purpose-built DBs that match access patterns rather than scaling an unsuitable engine.
4

Network economics

  • NAT Gateway processing and data transfer can become material at scale.
  • Use VPC endpoints for supported AWS service paths where security/cost requirements favor them.
  • Cross-AZ and cross-Region data movement can cost money; architecture placement matters.
  • CloudFront can reduce repeated origin transfer/load for cacheable global content.
  • Direct Connect may change data-transfer economics for sustained hybrid traffic, but the decision includes port/provider costs.
5

Cost tools

  • Cost Explorer analyzes historical spend/usage trends.
  • AWS Budgets creates thresholds and notifications.
  • Cost and Usage Report provides highly detailed billing/usage data for analysis.
  • Compute Optimizer provides rightsizing recommendations for supported resources.
  • Tags and multi-account structures improve allocation/accountability.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Stable baseline with bursts

Constraint: compute has a steady year-round baseline plus unpredictable peaks. Design: cover the measured baseline with a suitable Savings Plan and run peaks on demand or Spot where interruptible. Why alternatives fail: committing to peak wastes money, and Spot is unsafe for noninterruptible baseline capacity.

1 Commit only baseline→2 On-Demand handles uncertainty→3 Spot fits interruption
WORKED SCENARIO

Unknown object access

Constraint: millions of long-lived objects have changing, unpredictable access frequency. Design: S3 Intelligent-Tiering moves eligible objects among access tiers automatically. Why alternatives fail: rigid lifecycle dates can misclassify changing access, and Standard keeps every object at the higher frequent-access rate.

1 Monitoring learns access→2 No retrieval fee for access tiers→3 Archive tiers are optional
WORKED SCENARIO

Expensive private downloads

Constraint: private instances download large S3 datasets through NAT gateways, creating processing charges. Design: add an S3 gateway endpoint and route S3 traffic privately. Why alternatives fail: a larger NAT gateway does not reduce per-byte processing, and an internet gateway cannot serve private instances directly.

1 Gateway endpoint avoids NAT→2 S3 route stays private→3 No endpoint hourly charge

06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A company runs Amazon EC2 web servers behind an Application Load Balancer in two Availability Zones. CloudWatch shows 12 percent CPU and low memory. Finance wants a lower bill before any one-year commitment. The application must keep the same architecture and Multi-AZ placement. Which solution will meet these requirements with the LEAST ongoing compute cost?
Answer: A. Right-size from measured utilization before buying a commitment. A Savings Plan on oversized instances locks in waste. Dedicated Hosts and unused replicas raise cost.

Good to know: A Compute Savings Plan would be next after the fleet is sized to real load and the remaining baseline is predictable. Auto Scaling would win if the stem said idle peak capacity stayed provisioned all day.
Q2An ecommerce site provisions Amazon EC2 capacity for Black Friday all year because last year’s peak required that many instances. Daily traffic is far lower. The architecture already uses an Application Load Balancer. Finance wants idle peak capacity not to remain a permanent bill. Which solution will meet these requirements?
Answer: C. Auto Scaling lets peak capacity exist only while load needs it. Committing to last year’s peak as Reserved Instances makes that idle cost permanent.

Good to know: Savings Plans would cover a measured steady baseline after scale-in is in place. Spot would appear if the extra peak work were interruptible batch rather than customer-facing web.
Q3A company has a predictable minimum compute spend for three years across Amazon EC2, but may change instance families, operating systems, and Regions. Some of the same spend also runs on AWS Fargate and AWS Lambda. The team wants one commitment that still discounts those compute types and will not use Spot for this baseline. Which solution will meet these requirements?
Answer: B. Compute Savings Plans apply across eligible EC2 families, sizes, OS, tenancy, and Regions, and also to Fargate and Lambda. Standard RIs and Dedicated Hosts do not follow those moves.

Good to know: An EC2 Instance Savings Plan would be correct if the stem locked the family in one Region and did not need Fargate or Lambda coverage. Spot would win only for interruption-tolerant capacity, not a noninterruptible baseline.
Q4FinOps already right-sized a steady Amazon EC2 fleet that runs 24 hours a day in one Region. Next year the same spend may move to a different instance family in another Region. The workload cannot tolerate Spot interruption and is not a Reserved Instance lock-in to one size. Which commitment gives the MOST flexibility while still discounting that predictable compute?
Answer: D. Compute Savings Plans continue to apply when family and Region change. Standard RIs are tied to a specific family, size, OS, and Region. Capacity Reservations hold capacity; they are not the discount vehicle.

Good to know: EC2 Instance Savings Plans discount a family in a Region more deeply but fail the cross-family and cross-Region constraint. Convertible RIs are still EC2-only and less flexible than a Compute Savings Plan.
Q5A genomics lab runs fault-tolerant batch jobs on Amazon EC2 in one VPC. Workers checkpoint results to Amazon S3 and resume if a node is reclaimed. The scheduler can replace interrupted workers. Finance wants the deepest compute discount that still fits interruption and will not buy Dedicated Hosts for this fleet. Which solution will meet these requirements?
Answer: A. Spot uses spare capacity at a steep discount and can be interrupted, which checkpointed, replaceable batch can accept. Reservations and Dedicated Hosts raise cost without matching that model.

Good to know: On-Demand or a Savings Plan would be correct for the noninterruptible scheduler. Lesson 03 owns mixed-instance interruption architecture; this item is the cost choice once the work is already fault-tolerant.
Q6Application logs land in Amazon S3 Standard. After 90 days they are almost never read, and legal still requires them for four years. Restores may take hours. Operations wants Amazon S3 to move objects automatically by age and does not want a nightly copy job. Which solution will meet these requirements?
Answer: C. Known age, rare access, and long retention are a lifecycle transition into an archive class. Intelligent-Tiering is for unknown access, not a fixed 90-day archive handoff.

Good to know: Intelligent-Tiering would win if access patterns were unknown or changing. Glacier Instant Retrieval would appear if rare reads still needed millisecond access.
Q7A media company stores millions of long-lived objects in Amazon S3. Access frequency varies by title and changes over months, so the team cannot pick a fixed lifecycle day. Objects must stay immediately available. Operations wants Amazon S3 to move objects between access tiers automatically. Which solution will meet these requirements?
Answer: B. Unknown or changing access plus immediate availability is Intelligent-Tiering. Deep Archive requires a restore. One Zone-IA is a single-AZ infrequent class, not automatic multi-tier movement.

Good to know: A lifecycle rule would be correct if age were known (for example, archive after 90 days). One Zone-IA would win if infrequent access and a single-AZ cost trade-off were explicit.
Q8A backup application writes large objects to Amazon S3. Objects are read only a few times a month but must remain immediately available. The company can accept storing them in a single Availability Zone to reduce cost. A zone failure may require rebuilding backups from the source. Which storage class will meet these requirements?
Answer: D. Infrequent access, immediate reads, and an explicit single-AZ cost trade-off select One Zone-IA. Standard-IA still stores across AZs; Deep Archive is not immediately available.

Good to know: Standard-IA is the answer when infrequent access must still survive an Availability Zone failure. Intelligent-Tiering would win if access were unknown rather than known-infrequent.
Q9Amazon EC2 workers in private subnets in one VPC download terabytes from Amazon S3 through a NAT gateway every night, and NAT data-processing charges dominate the bill. The buckets stay in the same Region. Instances must remain private and must not use public IP addresses. Which change most directly removes those NAT processing charges for the S3 traffic?
Answer: A. An S3 gateway endpoint keeps that Regional S3 path off the NAT gateway and has no hourly endpoint charge. A larger NAT still bills per-GB processing.

Good to know: An interface endpoint would appear for services that lack a gateway endpoint, and it does have hourly charges. Transfer Acceleration is a long-distance transfer feature, not a NAT bypass.
Q10Application servers in private subnets send high request volumes to Amazon DynamoDB through a NAT gateway. NAT processing cost is rising. The table is in the same Region as the VPC. Servers must not use public IP addresses and must not move to public subnets. Which solution will meet these requirements MOST cost-effectively?
Answer: C. DynamoDB, like S3, supports a gateway VPC endpoint so private instances reach the service without NAT processing charges. Public IPs violate the private-server constraint.

Good to know: An S3 gateway endpoint is the same pattern when the heavy traffic is S3 instead of DynamoDB. Interface endpoints are the PrivateLink pattern for other AWS APIs and are not the zero-hourly-charge gateway path.
Q11Last month AWS spend in a multi-account organization rose sharply. Leadership wants to know which service, account, and usage type drove the increase. The team needs an interactive breakdown over time before they buy any commitment. Threshold email alerts are not the immediate need. Which solution will meet these requirements?
Answer: B. Cost Explorer is the tool for why spend rose, sliced by service, account, tag, and usage type. Budgets notify at a threshold; they do not explain the driver.

Good to know: The Cost and Usage Report would be correct if the stem demanded the most detailed line-item export for analysis in Athena or a BI tool. Budgets would win if the ask were a threshold notification.
Q12Finance wants an email when actual or forecasted AWS cost in a linked account exceeds a monthly dollar threshold. The workloads already run in that account. The team does not need a full line-item export and is not yet investigating a past spike in Cost Explorer. Which solution will meet these requirements?
Answer: D. AWS Budgets exist to notify (and optionally act) when actual or forecasted cost or usage crosses a threshold. Cost Explorer analyzes history; it does not send that threshold email by itself.

Good to know: Cost Explorer would be correct for diagnosing why last month rose. CUR would win for a detailed export. Compute Optimizer recommends rightsizing, not budget emails.
Q13A FinOps analyst in a payer account needs the most detailed AWS billing and usage line items, including resource IDs where available, delivered on a schedule for custom analysis. Cost Explorer’s interactive view is not granular enough for this request. Threshold email is already configured. Which solution will meet these requirements?
Answer: A. The Cost and Usage Report is the detailed billing and usage export. Budgets alert; they are not a line-item feed. CloudWatch estimated charges are a coarse metric.

Good to know: Cost Explorer would be enough if the stem only needed an interactive breakdown of why spend rose. Athena against CUR is a common next step; lake layout itself belongs to Lesson 13.
Q14After a traffic drop, several Amazon EC2 Auto Scaling groups and Amazon EBS volumes in one Region look oversized. The team wants service-generated rightsizing recommendations from utilization rather than guessing families. They are not asking for a spend-spike explanation in Cost Explorer and will not buy a Savings Plan on the current size. Which solution will meet these requirements?
Answer: C. Compute Optimizer produces rightsizing findings for supported EC2, ASG, and EBS resources from utilization. Buying a Savings Plan on oversized capacity freezes the waste.

Good to know: Cost Explorer would be correct for attributing a bill increase. Right-size first, then commit a Savings Plan to the remaining predictable baseline.
Q15Three product teams share one AWS account that runs Amazon EC2 and Amazon S3. Finance must allocate that cost to each team in Cost Explorer. Resource names are inconsistent. The company will not split into three accounts this quarter and will not rely on Health Dashboard for allocation. Which solution will meet these requirements?
Answer: B. Tags, once activated as cost allocation tags, let Cost Explorer and CUR break spend down by team without a multi-account split. A single budget with no dimension does not allocate.

Good to know: Separate accounts in Organizations would also isolate bills if the stem allowed an account-per-team move. Budgets can filter on tags after those tags exist.
Q16A web application has a steady year-round Amazon EC2 baseline plus unpredictable peaks behind an Application Load Balancer. Peaks are not interruptible. The company wants discounted baseline hours without paying a commitment for peak capacity that often sits idle, and will not put the baseline on Spot. Which solution will meet these requirements?
Answer: D. Commit only the predictable baseline; On-Demand (or Auto Scaling) covers uncertain peaks. Committing to peak wastes money. Spot is unsafe for noninterruptible work.

Good to know: Spot would join the design if the stem marked the peaks as fault-tolerant batch. Right-size the baseline before choosing the Savings Plan amount.
Q17A storage review of a production AWS account finds years of unused Amazon EBS snapshots and unattached volumes left after instance replacements. Retention policy allows deletion of backups older than 35 days. The company wants that waste gone without changing the running application architecture or buying a compute commitment. Which solution will meet these requirements?
Answer: A. Idle snapshots and unattached volumes are a common bill leak; delete what retention allows. Savings Plans do not discount leftover EBS. Intelligent-Tiering is an S3 class, not an EBS setting.

Good to know: AWS Backup lifecycle would automate snapshot expiration if the stem asked for a managed retention plan going forward. S3 lifecycle would win for objects, not EBS volumes.
Q18An Amazon RDS for MySQL instance supports a three-tier application in one Region. CloudWatch CPU and connections stay low. Reads are not the bottleneck. The company wants a lower database bill without adding components that do not address a stated need, such as unused read replicas. Which solution will meet these requirements?
Answer: C. Right-size the database to utilization. Read replicas solve read scale and add cost when reads are not the problem. A NAT gateway is not a database rightsizing tool.

Good to know: Read replicas would be correct if the stem required read scale-out. A serverless or autoscaling database option would appear if the load were highly variable rather than steadily oversized.
Q19A company wants to cut a predictable Amazon EC2 web-tier bill in one Region. CloudWatch shows the instances are oversized, and the remaining 24/7 load is steady for the next year. The team may later change instance family and will not move the web tier to Spot. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. Right-size first so the commitment is not bought on waste, then a Compute Savings Plan discounts the predictable leftover baseline and still allows family changes.

Good to know: Auto Scaling would be the extra step if idle peak capacity stayed up all year. Spot would be correct only if the web tier could tolerate interruption.
Q20Private Amazon EC2 jobs in one VPC pull large Amazon S3 datasets through a NAT gateway, driving processing charges. The buckets are in the same Region. Instances must stay in private subnets and must not receive Elastic IP addresses. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. A gateway endpoint plus routes that send S3 traffic to it removes that path from NAT processing. Both the endpoint and the routes are required.

Good to know: The same pair with a DynamoDB gateway endpoint would apply if the heavy private traffic were DynamoDB. A larger NAT does not remove per-byte processing.
Q21A media company stores millions of objects in Amazon S3 in one bucket. Access is changing and unpredictable. The company wants automatic cost-tier movement without guessing lifecycle dates, and objects in the frequent and infrequent tiers must remain immediately readable. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Intelligent-Tiering monitors access and moves eligible objects among online tiers. Leaving optional Archive Access tiers disabled keeps millisecond reads. Deep Archive on upload would violate immediate availability.

Good to know: A lifecycle transition would be correct if age and rarity were known. One Zone-IA would win only with an explicit single-AZ cost trade-off.
Q22Leadership asks why last quarter’s AWS bill rose and which product team caused it in a shared account. Resources already have a Team tag, but Cost Explorer does not split on it yet. The team also wants an interactive view by service and is not asking for a budget email. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. Cost allocation tags must be activated before Cost Explorer can group on them. Explorer then answers why spend rose by service and team. Both steps are required.

Good to know: CUR would be the detailed export if Explorer were not enough. Budgets would add a threshold email after you already know how to slice the bill.
Q23Finance must receive email when a linked account’s actual monthly AWS cost exceeds a dollar threshold and again if the forecast is expected to exceed it. Workloads already run in that account. They do not need a line-item dump to Amazon S3 for this request. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. Budgets are the threshold tool; actual and forecasted notifications are the two alerts the stem asked for. CUR is a detailed export, not that email path.

Good to know: Cost Explorer would explain a past spike. A budget action could stop resources if the stem added an automated response, not only email.
Q24A company has a noninterruptible 24/7 Amazon EC2 control plane in one Region and a large fault-tolerant batch fleet that checkpoints to Amazon S3. Finance wants discounts on the steady control plane and the deepest discount on the batch workers. The control plane must not run on Spot. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Savings Plans fit predictable, noninterruptible baseline compute. Spot fits interruption-tolerant batch. Putting the control plane on Spot violates the noninterruptible constraint.

Good to know: On-Demand would cover control-plane hours if the baseline were still too uncertain to commit. Lesson 03 covers how to architect Spot interruption; this item is the purchasing split.
Q25A FinOps team in a payer account needs both an interactive view of why last month’s spend rose by service and a scheduled, highly detailed usage export for custom reports. Threshold email is already handled with AWS Budgets. They are not asking for rightsizing findings. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. Cost Explorer answers why spend rose in an interactive view. CUR is the detailed export for custom analysis. Budgets and Health do not replace either feed.

Good to know: Athena on CUR can query line items; do not treat lake file layout as the Lesson 16 answer. Compute Optimizer would appear if the need were EC2 rightsizing findings rather than billing detail.
