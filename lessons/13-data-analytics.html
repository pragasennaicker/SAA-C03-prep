01 · VISUAL MODEL

See the architecture before memorising the services

①Classify velocity and latency

Separate real-time stream processing, near-real-time delivery, interactive S3 queries, ETL catalogs, warehouse analytics, and transactional workloads.

②Show shards and partitions

For Kinesis, annotate shard throughput and partition keys; for S3 analytics, show partitioned prefixes and columnar formats that reduce scans.

③Distinguish delivery from processing

Data Firehose buffers, transforms optionally, and delivers to destinations; Kinesis Data Streams retains ordered records for custom consumers.

④Place the metadata layer

Glue crawlers and the Data Catalog describe datasets; Athena queries S3 in place, while Redshift stores and optimizes warehouse data.

02 · DEEP DIVE

What you actually need to understand

1

Kinesis Data Streams

  • Real-time streaming service for producers and multiple consumers.
  • Partition/shard key design determines distribution and ordering scope.
  • Use when applications need direct control over consuming/processing a stream.
  • Enhanced fan-out and scaling concepts matter at architecture level; avoid hot partitions.
2

Data Firehose

  • Managed delivery of streaming data to supported destinations such as S3, Redshift and OpenSearch.
  • Reduces operational work when the goal is delivery rather than custom stream-consumer control.
  • Can buffer and transform records before delivery.
  • Think 'streaming delivery pipe' rather than a general message queue.
3

S3 data lake + Glue

  • S3 is the durable data-lake storage layer.
  • Glue Data Catalog stores table/schema metadata for analytics services.
  • Glue ETL jobs transform datasets into query-friendly formats/partitions.
  • Lake Formation simplifies data-lake governance and permissions on top of lake resources.
4

Athena + Redshift

  • Athena performs serverless SQL queries on data in S3; cost is strongly influenced by data scanned, so columnar formats/partitioning help.
  • Redshift is a managed analytical data warehouse for repeated warehouse-style analytics.
  • Use Redshift Spectrum capabilities where appropriate to query data outside warehouse storage.
  • OLTP databases are not interchangeable with analytics warehouses.
5

EMR + OpenSearch + BI

  • EMR runs managed big-data frameworks such as Spark and Hadoop.
  • OpenSearch is useful for search, log analytics and near-real-time indexing/query patterns.
  • AWS's current in-scope analytics list also includes Amazon Quick for BI/analytics recognition.
  • Choose from processing/query pattern rather than dataset size alone.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Replayable telemetry stream

Constraint: several consumers need ordered device telemetry and must replay records after failures. Design: Kinesis Data Streams partitions by device and retains records for independent consumers. Why alternatives fail: Firehose is delivery-focused, and SQS does not provide the same shard-based replay stream.

1 Partition key preserves order →2 Consumers read independently →3 Retention enables replay
WORKED SCENARIO

Serverless log investigation

Constraint: analysts sporadically query years of logs in S3 without loading a warehouse. Design: catalog partitioned Parquet data with Glue and query it using Athena. Why alternatives fail: Redshift adds provisioned warehouse concerns, and RDS is not optimized for lake scans.

1 Athena queries S3 →2 Glue supplies schema →3 Parquet reduces bytes scanned
WORKED SCENARIO

Repeated BI joins

Constraint: many users run frequent complex joins and aggregations over curated enterprise data. Design: load a dimensional model into Redshift and scale or isolate workloads appropriately. Why alternatives fail: Athena can be less predictable for repeated high-concurrency BI, and DynamoDB lacks relational joins.

1 Redshift is columnar →2 MPP accelerates analytics →3 Workload controls concurrency

06 · KNOWLEDGE CHECK

Five SAA-style questions

Q1Multiple applications must independently consume and replay ordered clickstream records for up to several days. Which ingestion service best meets the need?
Answer: A. Kinesis Data Streams retains records and supports multiple consumers; partition keys order records within a shard.
Q2A company wants a fully managed service to buffer streaming records and deliver compressed files to S3 with almost no consumer code. What should it use?
Answer: B. Data Firehose manages buffering, optional conversion or transformation, and delivery to destinations such as S3.
Q3Athena queries scan too much S3 data and cost too much. Which two data-layout changes provide the most direct improvement?
Answer: A. Columnar Parquet reads needed columns, and partitions let Athena skip files outside common filter predicates.
Q4Analysts need a shared schema registry for S3 datasets discovered automatically and queried by Athena. Which service provides this metadata?
Answer: A. Glue crawlers can infer schemas and populate the Glue Data Catalog, which Athena uses for table metadata.
Q5A BI platform runs frequent complex joins over terabytes of curated data and needs a columnar massively parallel warehouse. Which service is designed for it?
Answer: A. Redshift is a columnar MPP data warehouse designed for large-scale analytic queries and joins.
