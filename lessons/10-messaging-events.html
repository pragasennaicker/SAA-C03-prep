01 · ARCHITECTURE DRAWING

Build queue, fan-out, bus, and workflow

ARCHITECTURE

Producer

The API should not wait on slow downstream work. Decouple with a queue, topic, or bus.

ARCHITECTURE

SQS

One consumer group, durable buffer. Standard vs FIFO. Always give it a DLQ.

ARCHITECTURE

Workers

Lambda or EC2/ECS poll the queue. Scale consumers independently of the producer.

ARCHITECTURE

SNS

Fan-out: one event, many subscribers (SQS, Lambda, HTTP). Push, not poll.

ARCHITECTURE

EventBridge

Route by source and pattern across accounts and SaaS. Prefer this for application events.

ARCHITECTURE

Step Functions

Orchestrate a multi-step workflow with retries and a visual state machine. Not a queue.

ARCHITECTURE

Amazon MQ

Managed ActiveMQ/RabbitMQ when the constraint is an existing broker protocol.

ARCHITECTURE

The full integration picture

Buffer with SQS, fan out with SNS, route with EventBridge, orchestrate with Step Functions. Amazon MQ is only when the protocol is already a broker.

02 · DEEP DIVE

What you actually need to understand

1

SQS

  • Queue decouples producers and consumers and absorbs bursts.
  • Standard queues prioritize scale and at-least-once delivery; consumers should be idempotent.
  • FIFO queues add ordering and deduplication semantics for workloads that require them.
  • Visibility timeout prevents another consumer from immediately processing an in-flight message.
  • Dead-letter queues isolate repeatedly failing messages for investigation/replay.
2

SNS

  • Topic-based pub/sub fanout to multiple subscribers.
  • A strong pattern is SNS → separate SQS queues per downstream service, so each consumer owns its backlog/retries.
  • Can deliver to supported endpoints such as SQS, Lambda and notifications.
  • Filtering can reduce unnecessary deliveries to subscribers.
3

EventBridge

  • Event bus routes events using rules/patterns.
  • Useful for AWS service events, custom domain events and SaaS integrations.
  • Decouples event producers from consumers without each producer knowing every destination.
  • Schedules are available through EventBridge scheduling capabilities, but distinguish event routing from durable work queues.
4

Step Functions

  • State-machine orchestration for multi-step workflows.
  • Handles branching, retries, waiting and error paths explicitly.
  • Useful when business process state must be visible and coordinated.
  • Contrast choreography (events between services) with orchestration (central workflow).
5

Amazon MQ + integration

  • Amazon MQ supports familiar broker protocols/engines for migrations requiring traditional messaging compatibility.
  • AppFlow handles managed data transfer between supported SaaS and AWS services.
  • Choose purpose-built native services when protocol compatibility is not required and operational simplicity matters.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Independent order processors

Constraint: billing, fulfillment, and analytics must each process every order independently and survive downtime. Design: publish to SNS with a separate SQS subscription per consumer. Why alternatives fail: one shared queue load-balances messages instead of copying them, and direct calls couple availability.

1 SNS copies each event→2 SQS buffers per consumer→3 Policies isolate access
WORKED SCENARIO

Long-running approval flow

Constraint: a process waits for approval, branches on risk, and retries selected steps for days. Design: Step Functions Standard orchestrates services with waits, choices, and error handling. Why alternatives fail: Lambda cannot run for days, and SQS alone does not model workflow state.

1 Standard supports long runs→2 State machine records progress→3 Retries are per state
WORKED SCENARIO

Cross-application business events

Constraint: many targets need only events matching attributes such as source and detail type. Design: EventBridge rules filter events and route them to targets, with archives or DLQs where needed. Why alternatives fail: SNS filtering is subscription-oriented, and SQS is not an event bus.

1 Rules match content→2 Bus decouples producers→3 Targets receive selected events

06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1An order API on Amazon EC2 must accept requests in milliseconds and must not wait while a downstream fulfillment worker on Amazon ECS runs for minutes. Traffic bursts several times a day. Workers must scale independently of the API. Messages must still exist if every worker is down. An event bus must not be the only backlog. Which solution will meet these requirements?
Answer: A. A durable queue buffers bursts and decouples the producer from slow consumers. EventBridge routes events; it is not the durable work queue in this lesson.

Good to know: SNS would be correct if the same event had to fan out to many independent subscribers. Synchronous HTTP couples API availability to worker runtime.
Q2A media site collects clicks on Amazon EC2 and must ingest them at very high throughput from many producers. Occasional duplicate deliveries are acceptable if consumers handle them safely. Strict ordering across all clicks is not required. Workers will scale independently of the collectors. The team wants a durable queue, not an event bus or a workflow engine. Which solution will meet these requirements?
Answer: C. Standard queues prioritize scale and at-least-once delivery, so consumers must be idempotent. A single FIFO group would serialize the whole site for an ordering need the stem does not have.

Good to know: FIFO is the answer when per-group order and deduplication are required. Amazon MQ is for legacy broker protocols, not extra SQS scale.
Q3A payments platform on Amazon ECS workers already polls Amazon SQS. It must process each customer's transactions in order and must suppress duplicate submissions of the same payment. Different customers may be processed in parallel. Throughput can be lower than a standard queue. The team will not switch to an event bus for this backlog. Which solution will meet these requirements?
Answer: B. FIFO provides ordering and deduplication; message group IDs keep order per customer while allowing other groups to run in parallel. Standard queues do not give that contract.

Good to know: A standard queue remains correct when scale and at-least-once delivery matter more than order. EventBridge is pattern routing, not a per-customer FIFO log.
Q4Amazon SQS workers sometimes take four minutes to finish a message. A second worker must not receive that same message while the first is still working. If a worker crashes, the message should become visible again so another worker can retry. The team will not replace the queue with an event bus. Which solution will meet these requirements?
Answer: D. Visibility timeout hides an in-flight message from other consumers until it is deleted or the timeout expires. Zero timeout would cause overlapping processing.

Good to know: A DLQ isolates poison messages after failed retries; it does not replace visibility for healthy in-flight work. Heartbeat-style timeout extension is the follow-on when processing time varies widely.
Q5An Amazon SQS consumer on Amazon ECS repeatedly fails a malformed message and retries it. After a bounded number of receives, that message must leave the main queue so other work continues. Operators must inspect it later for replay. Increasing retention alone is not enough, and CloudWatch must not be the redrive mechanism. Which solution will meet these requirements?
Answer: A. A redrive policy moves a message to a DLQ after it exceeds maxReceiveCount. Retention only keeps the poison message blocking useful retries on the source queue.

Good to know: SNS filter policies reduce deliveries to a subscription; they do not isolate failed SQS receives. CloudWatch is observability, not a queue redrive.
Q6An ecommerce API on Amazon EC2 places an order record and then must notify billing, a mobile push notifier, and an HTTP webhook. Each of those three systems must receive a copy of the same event. The producer must not call them synchronously. Strict per-customer queue order is not required. Which solution will meet these requirements?
Answer: C. SNS is pub/sub fanout to multiple subscribers. One shared SQS queue load-balances messages instead of copying them to every consumer.

Good to know: SNS to a dedicated SQS queue per consumer is the next step when each subscriber needs its own durable backlog. Amazon MQ is for existing broker protocols.
Q7A retailer API publishes one order event per checkout. Billing, fulfillment, and analytics must each process every order, survive independent outages, and retry at their own rates. The producer must publish once. A single shared queue would give each message to only one consumer. Direct synchronous calls from the API are not acceptable. Which solution will meet these requirements?
Answer: B. SNS copies the event; a separate SQS subscription per service gives each team an independent durable backlog and retry loop.

Good to know: EventBridge would be the router if the constraint were content-based matching across many sources rather than simple topic fanout. A shared queue is competing consumers, not fanout.
Q8Many microservices already subscribe to an Amazon SNS topic that carries several event types. The inventory service should receive only messages whose attribute type is Restock. The company wants to avoid delivering every message to inventory and does not want inventory workers to discard most payloads in application code. Which solution will meet these requirements?
Answer: D. SNS filtering reduces unnecessary deliveries on a subscription. Dropping in consumer code still incurs the delivery the stem wants to avoid.

Good to know: EventBridge rules would be the answer if routing were by event source and detail-type on a bus rather than SNS subscription attributes.
Q9Internal applications and a supported SaaS partner emit JSON events into AWS. Only events with a given source and detail-type should reach a fulfillment AWS Lambda function. Producers must not hard-code every target. The team wants an event bus with pattern routing, not a durable work queue for a multi-hour backlog. Which solution will meet these requirements?
Answer: A. EventBridge routes by rule patterns on source and detail-type and decouples producers from targets. SQS is a queue, not a pattern-matching bus.

Good to know: SNS subscription filters would fit attribute-based fanout on a topic. AppFlow is managed SaaS data transfer, not per-event routing.
Q10A plant control API produces work items that workers on Amazon ECS must drain after a multi-hour outage. Delivery can be at-least-once, and workers must scale independently of the API. Other applications already consume domain events from a bus, but the plant backlog itself must be a durable work queue rather than that bus. Which solution will meet these requirements?
Answer: C. SQS is the durable buffer for work that must wait through an outage. EventBridge routes events; this lesson distinguishes that bus from a work queue.

Good to know: Keep EventBridge for pattern routing of the same business events to other targets. Step Functions orchestrates workflows; it is not a replacement queue.
Q11A lending process in AWS waits days for a human approval, then branches on risk score, retries a credit check, and must show operators a visible execution history. AWS Lambda cannot stay running for the wait. A queue alone cannot model those branches and waits as a single coordinated process. Which solution will meet these requirements?
Answer: B. Step Functions is the state-machine orchestrator for long workflows with waits, branches, retries, and visible history. SQS does not record that business process state.

Good to know: Event-driven choreography on EventBridge would fit if services coordinated through events without a central workflow. Standard Workflows are the long-run shape taught for day-scale waits.
Q12A company wants a central state machine to coordinate inventory reserve, payment, and shipping with explicit retries and a single execution history. Teams do not want each service's events to be the source of truth for progress. The process can run longer than a function timeout. Choreography through events alone is not the desired control model. Which solution will meet these requirements?
Answer: D. A visible, coordinated process is orchestration with Step Functions. Choreography lets services react to events without a central state machine.

Good to know: EventBridge remains the right bus when the stem prefers choreography and pattern routing. SQS still buffers work inside a step; it is not the workflow engine.
Q13A Java application uses JMS against on-premises ActiveMQ and publishes from existing clients. The migration to AWS must keep the broker protocol so those producers are not rewritten to Amazon SQS APIs. The team wants a managed broker in AWS rather than operating ActiveMQ on Amazon EC2. Which solution will meet these requirements?
Answer: A. Amazon MQ is the managed traditional broker for ActiveMQ or RabbitMQ when the constraint is existing JMS or AMQP clients. SQS is not a drop-in JMS broker.

Good to know: Native SQS or SNS would be preferred once protocol compatibility is no longer required. RabbitMQ on Amazon MQ is the other engine when that protocol is named.
Q14A Salesforce operations team must run managed, scheduled transfers of records into Amazon S3 without writing a custom connector. They need SaaS-to-AWS data transfer, not an application event bus and not a worker queue. The records are bulk extracts rather than individual JSON events that must be pattern-routed. Which solution will meet these requirements?
Answer: C. AppFlow is managed data transfer between supported SaaS and AWS services. EventBridge routes events; it is not a bulk Salesforce extract.

Good to know: EventBridge partner integrations would be correct for routing individual SaaS events by pattern. SQS would buffer work after a transfer, not perform it.
Q15An image pipeline on Amazon ECS has many identical workers that should share a backlog so each image is processed once. Fan-out to every worker would duplicate work. The producer API must not wait on a worker. Messages must persist if workers are scaled to zero overnight. Which solution will meet these requirements?
Answer: B. Competing consumers on one SQS queue share work so each message is processed once (at-least-once). SNS fanout would copy the image to every worker.

Good to know: SNS plus a queue per distinct service is the fanout pattern when every team must see every event. Identical workers should compete on one queue.
Q16Security findings from AWS services, a custom fraud application, and a supported SaaS product must all route by pattern to different targets in one account. Each producer must not list every destination. The team wants an event bus, not a durable worker queue and not CloudWatch as the router. Which solution will meet these requirements?
Answer: D. EventBridge is built for AWS, custom, and SaaS events with pattern rules. SQS and CloudWatch Logs are not that bus.

Good to know: AppFlow would be correct for scheduled SaaS-to-AWS data movement. Put a queue behind a rule when a target needs its own backlog.
Q17A finance team needs a nightly report to start at 02:00 and then run a multi-step workflow with branches and retries. That start time is a schedule, not a multi-day plant backlog. Operators still need visible workflow history after the schedule fires. Amazon SQS delay seconds are not the daily clock. Which solution will meet these requirements?
Answer: A. EventBridge provides scheduling; Step Functions then orchestrates the report. SQS delay is not a daily cron, and AppFlow is SaaS data transfer.

Good to know: SQS would still buffer individual report tasks inside a state if workers need a backlog. Do not treat EventBridge as the durable queue for plant outages.
Q18Producers on an ecommerce API publish order events to a topic. Inventory should not receive marketing events, and marketing should not receive restock events. Each team already has its own Amazon SQS queue. The company wants filtering at the subscription rather than in every worker, and CloudWatch must not rewrite attributes. Which solution will meet these requirements?
Answer: C. SNS filtering on each subscription delivers only matching events to that team's queue. A shared unfiltered queue mixes both streams.

Good to know: EventBridge rules would be the equivalent control on a bus using source and detail-type. CloudWatch is not a message filter.
Q19An ecommerce API must notify billing, fulfillment, and analytics for every order. Each team must keep an independent backlog during outages and retry at its own rate. The producer will publish once and must not call the three systems synchronously. Competing consumers on one queue would split orders instead of copying them. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. SNS fans the event out; a queue per consumer is the durable, independently retried backlog. Competing on one queue would split orders, not copy them.

Good to know: EventBridge plus targets would be the pair if routing were by event pattern across many sources. Step Functions would orchestrate a single ordered process instead of independent consumers.
Q20A brokerage platform already has workers that consume Amazon SQS. It must process each account's trades in order and suppress duplicate submissions of the same trade. Trades for different accounts may run in parallel. A standard queue would not provide that per-account contract. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. FIFO supplies order and deduplication; the message group ID is the per-account ordering key that still allows other accounts to proceed.

Good to know: A standard queue plus idempotent consumers is the high-scale path when order is not required. EventBridge does not replace FIFO message groups.
Q21Workers on Amazon ECS poll an Amazon SQS queue. Malformed messages keep failing the consumer and delaying healthy work. After a bounded number of failed receives, those messages must move aside for inspection and possible replay. Raising visibility timeout alone must not be the isolation design. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. The DLQ is the isolation destination; maxReceiveCount is how many failed receives occur before the move. Visibility timeout alone does not drain poison messages.

Good to know: Tune visibility timeout so healthy messages are not copied to the DLQ while still in flight. CloudWatch does not redrive SQS.
Q22Custom application events and a supported SaaS integration must reach different Lambda and queue targets according to source and detail-type. Producers must not maintain a list of destinations. The bus is not a substitute for a worker backlog, and CloudWatch dashboards must not route events. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. EventBridge is the bus; rules are the pattern/source routing. SQS and CloudWatch are not that router.

Good to know: Subscribe an SQS queue as a rule target when a consumer needs a durable backlog. Amazon MQ remains the legacy-protocol answer.
Q23An insurance claim process in AWS waits days for an adjuster, then branches on fraud score and retries a document check. Operators need a visible execution history. Keeping a function running for the wait is not allowed, and a queue visibility timeout must not be the workflow engine. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. Step Functions is the orchestrator; wait and choice states are how long delays and branches are modeled with visible history.

Good to know: Choreography on EventBridge would be the alternative if services coordinated through events without a central machine. SQS still buffers work inside a state.
Q24Existing clients speak JMS or AMQP to a self-managed broker in a data center. The move to AWS must keep those protocols. The team will not rewrite producers to Amazon SQS or Amazon SNS in this change, and it will not operate the broker on unmanaged Amazon EC2. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Amazon MQ is the managed traditional broker; keeping client protocols is the second required step. SQS and EventBridge are not JMS providers.

Good to know: After a later rewrite, native SQS or SNS would usually be simpler. AppFlow transfers SaaS data; it is not a broker.
Q25A company must copy supported SaaS records into Amazon S3 on a schedule without custom connector code. The need is managed data transfer, not an event bus and not a worker queue. Individual JSON events do not need pattern routing for this bulk extract. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. AppFlow is the managed transfer service; picking a supported source and S3 as destination is how that transfer is configured.

Good to know: EventBridge would route individual SaaS events by pattern. SQS would buffer downstream processing after the files land in S3.
