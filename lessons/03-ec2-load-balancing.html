01 · VISUAL MODEL

See the architecture before memorising the services

①Choose the load-balancer layer

ALB makes Layer 7 host and path decisions for HTTP; NLB preserves Layer 4 performance, static IP needs, and TCP or UDP handling.

②Scale replaceable capacity

Keep instances stateless behind a load balancer and let an Auto Scaling group replace unhealthy capacity across multiple AZs.

③Separate launch from scaling

A launch template defines instance configuration; target tracking, step, scheduled, or predictive policies decide desired capacity.

④Align every health signal

Use load balancer health checks with Auto Scaling so instances that boot but cannot serve the application are replaced.

02 · DEEP DIVE

What you actually need to understand

1

EC2 families + sizing

  • General purpose balances CPU/memory/network.
  • Compute optimized fits CPU-heavy processing.
  • Memory optimized fits large in-memory datasets and memory-heavy databases.
  • Storage optimized fits high local I/O workloads; accelerated instances use GPUs/accelerators.
  • Right-size from workload metrics rather than choosing the largest instance.
2

ALB vs NLB

  • ALB is Layer 7 and understands HTTP/HTTPS; it supports host/path routing and modern app patterns.
  • NLB is Layer 4 for TCP/UDP/TLS, very high throughput/low latency and static IP-style requirements.
  • Gateway Load Balancer is for deploying/scaling virtual network appliances.
  • Cross-zone and health-check behavior matters for resilience.
3

Auto Scaling

  • An ASG has minimum, desired and maximum capacity.
  • Target tracking keeps a metric near a chosen target and is common for elastic workloads.
  • Step/simple scaling reacts to thresholds; scheduled scaling helps predictable patterns.
  • Use ELB health checks and multiple AZs to replace unhealthy instances automatically.
4

EC2 purchase models

  • On-Demand: flexibility, no long commitment.
  • Savings Plans: discount for committed compute spend/usage patterns.
  • Reserved capacity/pricing constructs are useful for steady predictable workloads depending on service/model.
  • Spot: deep discounts but interruption is possible; design fault-tolerant workloads.
  • Dedicated Hosts/Instances address isolation, compliance or licensing requirements.
5

Placement + storage

  • EBS persists independently of an EC2 instance lifecycle depending on configuration.
  • Instance store is ephemeral local storage and should not hold unique durable data.
  • Placement groups can optimize latency/throughput/failure spread for specialized workloads.
  • Use AMIs and launch templates for repeatable immutable capacity.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Route by hostname and path

One HTTPS entry point must route api.example.com and /images to different target groups. Use an ALB with host- and path-based listener rules and ACM certificates. An NLB does not inspect HTTP paths, and DNS routing cannot split requests by URL path.

1 Layer 7 rules →2 TLS support →3 Target groups
WORKED SCENARIO

Serve allowlisted TCP traffic

Partners require fixed IP addresses for a latency-sensitive TCP service deployed across AZs. Use an internet-facing NLB with Elastic IP addresses per enabled AZ. ALB addresses can change and ALB is intended for HTTP-family protocols, while Global Accelerator is unnecessary if regional entry points suffice.

1 Static addresses →2 Layer 4 →3 Cross-AZ service
WORKED SCENARIO

Scale ahead of a known event

A sale starts at a fixed time and instance initialization takes several minutes. Configure scheduled scaling to raise ASG capacity before the event, then use target tracking for live demand. Reactive scaling alone starts too late, and larger fixed instances waste capacity after the sale.

1 Known schedule →2 Warm capacity →3 Elastic follow-up

06 · KNOWLEDGE CHECK

Five SAA-style questions

Q1A web platform must route requests to different target groups based on hostname and URL path while terminating HTTPS. Which load balancer should it use?
Answer: C. The deciding constraints are Layer 7 host and path inspection. ALB listener rules provide both and can terminate HTTPS.
Q2External clients allowlist fixed IPv4 addresses for a high-throughput TCP application. Which regional load-balancing design satisfies this?
Answer: D. The deciding constraints are static IP addresses and TCP performance. NLB supports Layer 4 traffic and per-AZ Elastic IPs.
Q3An ASG instance passes EC2 status checks but its web process is dead. The company wants automatic replacement. What should be configured?
Answer: A. The deciding constraint is application-level failure. Enabling ELB health checks lets the ASG replace targets that fail the load balancer check.
Q4Traffic tracks CPU utilization unpredictably throughout the day. The ASG should maintain CPU near 50 percent with minimal policy management. Which policy fits?
Answer: B. The deciding constraint is maintaining a metric target under variable load. Target tracking adjusts capacity around the selected CPU value.
Q5A batch fleet can tolerate interruption and needs the lowest EC2 compute cost, but it must replace reclaimed capacity automatically. Which design is best?
Answer: C. The deciding constraints are interruption tolerance and minimum cost. Diversified Spot in an ASG reduces concentration risk and replaces lost instances.
