01 · ARCHITECTURE DRAWING

Build replaceable compute behind a load balancer

ARCHITECTURE

VPC

The same two-AZ skeleton as Lesson 01: public subnets for load-balancer nodes, private subnets for instances. The load balancer is regional; the fleet is zonal. Nothing is reachable from the internet until you add a load balancer.

ARCHITECTURE

Application Load Balancer

Users → IGW → an ALB node in each public subnet. One regional Layer-7 balancer: host and path rules, HTTP/HTTPS, target groups. You must enable at least two AZs. Cross-zone is always on at the load balancer, so either node can send to either AZ.

ARCHITECTURE

Auto Scaling

Instances in both private subnets, no public IPs. The group spans AZs so one zone outage does not take the service down. Enable ELB health checks: an instance that passes EC2 status but fails the target-group check is replaced.

ARCHITECTURE

AMI / launch template

The AMI is the baked image. Auto Scaling launches from a launch template that points at that AMI and instance type. Launch configurations are the legacy alternative — new groups use a template.

ARCHITECTURE

Network Load Balancer

A parallel Layer-4 path, not a second listener on the ALB. Users → IGW → NLB node plus Elastic IP in each public subnet → TCP targets. Use it for static addresses, TCP/UDP, or extreme performance. It does not inspect HTTP host or path.

ARCHITECTURE

The full compute path

Users hit the ALB; healthy instances in the Auto Scaling group serve HTTP. New instances come from the launch template and AMI. NLB is the parallel Layer-4 path with a static address per AZ. Gateway Load Balancer is not on this drawing — it is for appliance fleets, not application traffic.

02 · DEEP DIVE

What you actually need to understand

1

EC2 families + sizing

  • General purpose (M, T) balances CPU, memory, and network for typical web and app tiers.
  • Compute optimized (C) fits CPU-bound processing, batch, and media transcoding.
  • Memory optimized (R, X) fits large in-memory datasets, caches, and memory-heavy databases.
  • Storage optimized (I, D) fits high local I/O; accelerated instances add GPUs or other accelerators.
  • Right-size from measured utilization. A larger instance is not high availability — spread replaceable capacity across Availability Zones instead.
2

ALB

  • Layer 7 HTTP/HTTPS. Listener rules route by host header and URL path to different target groups. Attach an ACM certificate on an HTTPS listener to terminate TLS.
  • You must enable at least two Availability Zones. Nodes live in the subnets you enable; targets stay on private IPs and do not need public addresses.
  • Cross-zone load balancing is always on at the load balancer. You can turn it off only at the target group.
  • Target-group health checks must match what the application actually serves. Deregistration delay (connection draining) lets in-flight requests finish when an instance leaves the group.
  • Stickiness is a target-group setting (duration-based or application-based cookies) when a client must return to the same target. An internal scheme keeps the balancer on private IPs for VPC-only clients.
3

NLB vs GWLB

  • NLB is Layer 4 TCP/UDP/TLS: flow-hash routing, very high throughput, and a static address per enabled AZ (optionally an Elastic IP). It does not inspect HTTP host or path.
  • Cross-zone load balancing is off by default on NLB and GWLB. If one AZ has fewer targets, that AZ’s node overloads those targets until you enable cross-zone or rebalance the fleet.
  • Gateway Load Balancer steers all IP traffic to a fleet of virtual appliances over GENEVE (port 6081). Choose it to inspect or scale firewalls and IDS/IPS — not to serve application HTTP or a TCP API.
  • PrivateLink still uses NLB on the provider side (Lesson 02). That is a service-exposure pattern, not the reason to pick NLB for a public TCP app.
4

Auto Scaling

  • An Auto Scaling group has minimum, desired, and maximum capacity and should span two or more AZs so one zone outage does not take the service down.
  • Launch from a launch template that points at an AMI and instance type. Launch configurations cannot mix On-Demand and Spot or specify multiple instance types.
  • Target tracking keeps a metric (CPU, request count per target) near a chosen value under variable load. Scheduled scaling raises capacity before a known event. Step/simple scaling reacts to CloudWatch alarms.
  • By default the group replaces instances that fail EC2 status checks only. Turn on ELB health checks so an instance whose web process is dead — but whose VM still passes EC2 status — is replaced. Allow a health-check grace period for boot.
5

Purchase models

  • On-Demand: no commitment. Default for uninterruptible or unpredictable capacity you cannot yet measure.
  • Savings Plans / Reserved Instances: discount the steady, predictable baseline. Which Savings Plan type is more flexible across families and Regions is Lesson 16.
  • Spot: spare capacity at a steep discount; AWS can reclaim it with a two-minute warning. Use only for checkpointed or otherwise interruption-tolerant work, and run it in an Auto Scaling group so lost instances are replaced.
  • A mixed instances policy (launch template required) can keep an On-Demand base and fill the rest with diversified Spot across instance types and AZs.
  • Dedicated Hosts expose sockets, cores, and host ID so you can bring per-socket or per-core licenses. Dedicated Instances isolate the hardware but do not give that visibility — they are not the BYOL-socket answer.
6

Placement + instance store

  • EBS volumes persist independently of the instance (unless you set delete-on-termination). Unique durable data belongs on EBS. Volume types and snapshots are Lesson 04.
  • Instance store is ephemeral local disk. Stop, terminate, or underlying-host failure wipes it. Do not keep the only copy of data there.
  • Cluster placement groups pack instances in one AZ for lowest latency and highest throughput; a hardware event can affect many of them together.
  • Spread placement groups put instances on distinct hardware to reduce correlated failure. Partition placement groups fit large distributed stores such as Hadoop or Kafka.

04 · WORKED SCENARIOS

Apply the concepts as an architect

WORKED SCENARIO

Route by hostname and path

One HTTPS entry point must route api.example.com and /images to different target groups. Use an ALB with host- and path-based listener rules and ACM certificates. An NLB does not inspect HTTP paths, and DNS routing cannot split requests by URL path.

1 Layer 7 rules→2 TLS support→3 Target groups
WORKED SCENARIO

Serve allowlisted TCP traffic

Partners require fixed IP addresses for a latency-sensitive TCP service deployed across AZs. Use an internet-facing NLB with Elastic IP addresses per enabled AZ. ALB addresses can change and ALB is intended for HTTP-family protocols, while Global Accelerator is unnecessary if regional entry points suffice.

1 Static addresses→2 Layer 4→3 Cross-AZ service
WORKED SCENARIO

Scale ahead of a known event

A sale starts at a fixed time and instance initialization takes several minutes. Configure scheduled scaling to raise ASG capacity before the event, then use target tracking for live demand. Reactive scaling alone starts too late, and larger fixed instances waste capacity after the sale.

1 Known schedule→2 Warm capacity→3 Elastic follow-up
WORKED SCENARIO

Replace instances the app cannot serve

Users report HTTP 502s. CloudWatch shows the Auto Scaling group at desired capacity, and every instance still passes EC2 status checks. The web process has exited. Turn on ELB health checks so the group replaces instances that fail the target-group check. EC2 status only watches the hypervisor and guest agent, not the application.

1 App is down→2 VM still healthy→3 ELB health checks
05 · EXAM LANGUAGE DECODER

Words in the question that should trigger a design instinct

“path-based routing” / host header
→ ALB. NLB does not inspect HTTP.
“TCP/UDP, static IP, very high throughput”
→ NLB, Elastic IP per AZ.
“inspect traffic” / “scale firewall appliances”
→ Gateway Load Balancer, not ALB or NLB.
“unpredictable traffic”
→ Target tracking on an Auto Scaling group.
“sale starts at 09:00” / known event
→ Scheduled scaling to warm capacity, then target tracking.
“passes EC2 status but the app is down”
→ Turn on ELB health checks on the group.
“fault-tolerant batch” / interruptible
→ Spot in an Auto Scaling group so reclaimed capacity is replaced.
“license tied to physical sockets/cores”
→ Dedicated Hosts. Dedicated Instances do not expose sockets or cores.
“On-Demand and Spot in one group”
→ Launch template. Launch configurations cannot mix purchase options.
“instance store” / ephemeral disk
→ Unique data belongs on EBS; instance store is wiped on stop or terminate.
06 · KNOWLEDGE CHECK

Twenty-five SAA-style questions

Q1A media company hosts a public website and a REST API on Amazon EC2 instances in private subnets. Users must reach both applications through one HTTPS entry point. Requests for api.example.com must go to one target group, and requests whose path starts with /images must go to another. TLS must terminate at the load balancer using a certificate the company already stores in ACM. Which solution will meet these requirements?
Answer: A. Host-header and URL-path routing are Layer 7 listener rules, and ACM certificates attach to an HTTPS listener. Those two constraints select an Application Load Balancer.

Good to know: A Network Load Balancer would terminate TLS, but it does not inspect HTTP host or path. A Gateway Load Balancer steers traffic to appliances over GENEVE; Classic Load Balancers do not provide ALB-style host and path rules.
Q2A financial exchange runs a latency-sensitive TCP market-data feed on Amazon EC2 instances in two Availability Zones. Partner firms allowlist destination IPv4 addresses on their firewalls and refuse to update those lists when AWS addresses change. The feed is not HTTP. The company needs a regional entry point with a fixed address in each enabled zone. Which solution will meet these requirements?
Answer: C. The protocol is TCP, not HTTP, and partners need a static IPv4 address per zone. A Network Load Balancer is Layer 4 and is the load balancer that accepts an Elastic IP address on each enabled subnet.

Good to know: An Application Load Balancer cannot be assigned Elastic IP addresses, and it is the HTTP/HTTPS balancer. Gateway Load Balancer is for appliance fleets. CloudFront is an HTTP cache at the edge, not a regional TCP listener.
Q3A security team deploys a fleet of third-party virtual firewall appliances in a VPC. All traffic that enters and leaves application subnets must be inspected by those appliances. The team must scale the appliance fleet independently of the applications and must not convert the applications to HTTP. The appliances already speak GENEVE. Which solution will meet these requirements?
Answer: B. Gateway Load Balancer is the balancer that steers all IP traffic to a scalable appliance fleet over GENEVE. Inspection of arbitrary traffic, not application HTTP or a TCP API, is the deciding constraint.

Good to know: Use an Application Load Balancer when the stem asks for host or path routing, and a Network Load Balancer when it asks for TCP/UDP or a static IP in front of the application itself. Neither of those is an appliance-insertion fabric.
Q4A web application runs on Amazon EC2 instances in an Auto Scaling group behind an Application Load Balancer. Users begin to receive HTTP 502 errors. CloudWatch shows the group at its desired capacity, and every instance still passes EC2 status checks. On several instances the web process has exited. The company wants those instances replaced automatically. Which solution will meet these requirements?
Answer: D. By default an Auto Scaling group replaces instances that fail EC2 status checks only. ELB health checks add the target-group check, so an instance whose web process is dead is taken out even while the virtual machine still looks healthy.

Good to know: Raising maximum capacity adds more of the same unhealthy instances. Launch configurations and placement groups do not change how the group decides that an instance is unhealthy.
Q5An ecommerce site runs on Amazon EC2 instances in an Auto Scaling group behind an Application Load Balancer. Traffic varies throughout the day with no predictable schedule. The operations team wants average CPU utilization to stay near 50 percent without maintaining a set of CloudWatch alarm thresholds. Which solution will meet these requirements?
Answer: A. Target tracking keeps a chosen metric near a target value and creates the alarms for you. Unpredictable load plus a CPU target is the textbook use of that policy type.

Good to know: Scheduled scaling is the answer when the stem gives a known clock time, such as a sale that starts at 09:00. Simple or step scaling is the answer when you must react to explicit alarm thresholds rather than a target value.
Q6A retailer runs a web application on an Auto Scaling group behind an Application Load Balancer. A national sale starts at 09:00 on a published date. New instances need several minutes to bootstrap from the launch template before they can serve traffic. The team must have extra capacity ready at 09:00 and must still follow live demand after the sale opens. Which solution will meet these requirements?
Answer: C. A known start time plus a long bootstrap is scheduled scaling: warm the group before the event. Target tracking then follows the sale's live demand. Reactive scaling alone starts after CPU has already risen.

Good to know: Target tracking by itself is correct when traffic is unpredictable and there is no clock to plan around. A larger instance type is vertical scaling and wastes capacity after the sale. Spot is the interruptible-batch answer, not a flash-sale web tier.
Q7A company runs a checkpointed video-transcoding fleet on Amazon EC2. Jobs can restart from the last completed segment if an instance stops. The finance team wants the lowest compute cost, and the architecture must replace capacity automatically when AWS reclaims an instance. The fleet can use more than one instance type. Which solution will meet these requirements?
Answer: B. Spot is the purchase model for interruptible, checkpointed work, and an Auto Scaling group replaces instances AWS reclaims. Diversifying instance types in a mixed instances policy reduces the chance that one pool is empty.

Good to know: On-Demand is the answer when the stem forbids interruption. Dedicated Hosts are the per-socket license answer. A cluster placement group packs instances for latency; it does not make Spot cheaper or survive reclamation.
Q8A company is moving a licensed analytics engine onto Amazon EC2. The vendor contract charges by physical socket and physical core, and an audit requires the team to report the host ID, socket count, and core count of every machine that runs the engine. The instances must not share hardware with other AWS customers. Which solution will meet these requirements?
Answer: D. Dedicated Hosts expose sockets, cores, and host ID, which is what a per-socket or per-core bring-your-own-license contract needs. Isolation alone is not enough.

Good to know: Dedicated Instances also keep the hardware from being shared, but they do not give socket or core visibility, so they fail the audit. Spot and Savings Plans are purchase-model answers, not licensing answers.
Q9An Auto Scaling group currently uses a launch configuration to start On-Demand web instances. The company wants a mixed instances policy that keeps a small On-Demand base and fills the rest with Spot Instances across several instance types. New launches must keep the same AMI and security groups. Which solution will meet these requirements?
Answer: A. A mixed instances policy that combines On-Demand and Spot, or that specifies more than one instance type, requires a launch template. Launch configurations cannot express those options.

Good to know: Two separate groups can mix purchase models at the account level, but that is not one mixed instances policy and it splits scaling. User data cannot substitute for the launch specification the group uses to start instances.
Q10A batch worker on Amazon EC2 writes intermediate files to the instance's SSD while a job runs, then writes the finished object to Amazon S3. During a test, an operator stops the instance to change its type. After start, the intermediate files are gone and an in-flight job cannot resume. Unique data must survive stop and terminate. Which solution will meet these requirements?
Answer: C. Instance store is ephemeral: stop, terminate, or underlying-host failure wipes it. Unique data that must survive those events belongs on EBS. Volume types are a Lesson 04 decision.

Good to know: Termination protection only blocks an accidental terminate API call; it does not make instance store persistent across a stop. Placement groups and Savings Plans do not change disk lifetime.
Q11A team creates a new internet-facing load balancer for an HTTP application. They select one public subnet in a single Availability Zone and choose the Application Load Balancer type. The create operation fails. The application must stay HTTP, must keep host-based routing, and must use an Application Load Balancer. Which solution will meet these requirements?
Answer: B. An Application Load Balancer must be enabled in at least two Availability Zones. That requirement, not the HTTP protocol, is why a one-subnet create fails.

Good to know: A Network Load Balancer can be created in one Availability Zone, but it cannot do host-based HTTP routing. Gateway Load Balancer is for appliances. Classic Load Balancer is the legacy HTTP option and is not the host-routing answer.
Q12A TCP application sits behind a Network Load Balancer enabled in two Availability Zones. Eight healthy targets run in zone A and one healthy target runs in zone B. Cross-zone load balancing is still at the service default. The single zone-B target runs at 100 percent CPU while zone-A targets are idle. Clients connect through both nodes. Which solution will meet these requirements?
Answer: D. Cross-zone load balancing is off by default on a Network Load Balancer, so each node sends traffic only to targets in its own zone. The zone-B node therefore piles every client that lands on it onto the one local target.

Good to know: Application Load Balancers have cross-zone always on at the load balancer, which is why this imbalance is an NLB (or GWLB) exam item. Adding targets in zone B would also help; switching balancer type does not.
Q13An internal order API on Amazon EC2 must be reached by other microservices in the same VPC over HTTP. Clients resolve a DNS name and must never send traffic to a public address. The API uses host-based routing to several target groups. No user on the internet should be able to open a connection to the load balancer. Which solution will meet these requirements?
Answer: A. An internal Application Load Balancer has private IP addresses and still provides Layer 7 host-based routing. That combination keeps the entry point inside the VPC.

Good to know: An internet-facing balancer receives a public DNS name even if a security group is tight; the scheme is still public. A Network Load Balancer with Elastic IP addresses is the partner-allowlist TCP answer. Gateway Load Balancer is not an HTTP API front.
Q14A company runs an in-memory analytics engine on Amazon EC2. Each node holds several hundred gigabytes of working set in RAM. CPU utilization stays low, local disk I/O is modest, and the engine is not a GPU workload. The team must pick an instance family that matches this profile rather than oversizing a general-purpose type. Which solution will meet these requirements?
Answer: C. Memory-optimized families are the match when the working set is large RAM and CPU is not the bottleneck. Right-sizing starts from that measured profile.

Good to know: Compute-optimized instances fit CPU-bound processing. Storage-optimized instances fit high local I/O. Burstable T instances are for spiky, low-baseline general-purpose work, not a hundreds-of-gigabytes in-memory engine.
Q15A legacy web application on Amazon EC2 stores session state on the local disk of each instance. The fleet sits behind an Application Load Balancer. After a user authenticates, subsequent requests from that user must return to the same instance for the rest of the session. The team cannot yet move session state into a shared store. Which solution will meet these requirements?
Answer: B. Stickiness is a target-group setting on an Application Load Balancer. Duration-based or application-based cookies send the same client back to the same target.

Good to know: A Network Load Balancer hashes connections, which is not an HTTP session cookie. Placement groups affect hardware packing, not request affinity. ELB health checks replace dead instances; they do not pin sessions.
Q16A tightly coupled HPC simulation runs on Amazon EC2 instances that exchange large messages with one another. The team needs the lowest possible latency and the highest packet rate between those instances. All nodes can live in a single Availability Zone, and the team accepts that a hardware event could affect many of them together. Which solution will meet these requirements?
Answer: D. A cluster placement group packs instances close together in one Availability Zone for the lowest latency and highest throughput. Correlated hardware risk is the trade-off the stem already accepts.

Good to know: Spread placement groups put instances on distinct hardware to reduce correlated failure. Partition placement groups fit large distributed stores such as Hadoop or Kafka. Dedicated Hosts are the socket-license answer.
Q17A company has run the same 40 Amazon EC2 web instances, 24 hours a day, for 18 months and expects that baseline to continue for at least another year. Traffic above the baseline is small and already handled by Auto Scaling. The finance team wants a lower unit price for the steady 40 instances and will accept a one-year commitment. Which solution will meet these requirements?
Answer: A. A measured, long-lived baseline is what Savings Plans and Reserved Instances discount. Which Savings Plan type is more flexible across families and Regions is a Lesson 16 decision.

Good to know: Spot would cut the unit price further but can be reclaimed, which a customer-facing web baseline usually cannot accept. Dedicated Hosts are for socket-level licenses, not a generic discount. A larger On-Demand type is not a purchase-model saving.
Q18A company is launching a new customer-facing web application on Amazon EC2 in an Auto Scaling group behind an Application Load Balancer. Traffic volume is unknown and may stay low for months. The application cannot tolerate instance interruption: in-flight checkout requests must not be dropped because AWS reclaimed capacity. Which solution will meet these requirements?
Answer: B. On-Demand has no interruption and no commitment, which matches an uninterruptible workload whose size is still unknown. Spot's discount comes with a two-minute reclamation warning the checkout path cannot accept.

Good to know: Spot is correct when the stem says the work can checkpoint or retry. A long Reserved Instance term is the answer after the baseline is measured. Dedicated Hosts solve licensing, not interruption.
Q19A company must present one HTTPS hostname to the internet for a website and a REST API that run on Amazon EC2 instances in private subnets. Requests to api.example.com must reach one target group, and requests whose path starts with /static must reach another. TLS must terminate at the load balancer with a certificate already in ACM. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and C. Layer 7 host and path rules select an Application Load Balancer, and TLS termination with an ACM certificate is an HTTPS listener on that same balancer. Both pieces are required; neither NLB nor DNS can split on URL path.

Good to know: Weighted routing can split two hostnames, not a hostname versus a URL path. A Network Load Balancer does not inspect HTTP. Gateway Load Balancer is the appliance answer.
Q20A ticket vendor runs Amazon EC2 web instances in an Auto Scaling group. On-sale events start at published clock times, and new instances need several minutes to become healthy. Between events, traffic is low and variable. The architecture must have spare capacity ready when an on-sale begins and must still follow demand after the doors open. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and D. Scheduled scaling warms the group before a known clock time. Target tracking then follows live demand. The two policies solve different parts of the same day.

Good to know: A simple policy that waits for 90 percent CPU is reactive and starts too late when bootstrap takes minutes. Vertical scaling and Spot do not address the schedule.
Q21A company wants one Auto Scaling group to keep four On-Demand web instances as a base and to fill additional capacity with Spot Instances. Spot launches must spread across several instance types in the same generation so a shortage in one pool does not halt scaling. The group today uses a launch configuration. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: C and E. Mixing On-Demand with Spot and naming more than one instance type requires a launch template plus a mixed instances policy. Launch configurations cannot express either requirement.

Good to know: A cluster placement group is the HPC-latency answer. Fargate is a Lesson 09 compute model; it does not satisfy a stem that keeps an EC2 Auto Scaling group.
Q22Partners send a custom TCP protocol to a market-data service on Amazon EC2 in two Availability Zones. Each partner firewall allowlists destination IPv4 addresses and cannot follow DNS changes. The service is not HTTP. The company needs a regional load balancer whose address in each enabled zone never changes. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and E. A Network Load Balancer is the Layer 4 regional balancer, and it is the one that accepts an Elastic IP address per enabled Availability Zone. Those two steps give partners a stable TCP destination in each zone.

Good to know: Application Load Balancers cannot be assigned Elastic IP addresses and do not serve arbitrary TCP. CloudFront is HTTP at the edge. Gateway Load Balancer inserts appliances; it is not the partner-facing TCP listener.
Q23A web fleet in an Auto Scaling group sits behind an Application Load Balancer. Operators see HTTP 502 errors while CloudWatch still reports every instance as passing EC2 status checks. On several instances the web process has exited. The group must stop sending traffic to those instances and must replace them without a manual terminate. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: B and C. The target group must detect that the application is dead, and the Auto Scaling group must treat that target-group failure as instance failure. Default EC2 status checks watch the virtual machine, not the web process.

Good to know: Raising maximum capacity, changing to a launch configuration, or picking a different placement group leaves the dead processes in service. Health-check grace period matters at boot, not after a running process has already exited.
Q24A company runs third-party intrusion-detection appliances on Amazon EC2. Every packet to and from application subnets must pass through those appliances. The security team must scale the appliance fleet independently of the applications, and the applications must keep their existing TCP and UDP protocols. The appliances already accept GENEVE. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: D and E. Gateway Load Balancer plus an appliance target group is the pattern that inspects all IP traffic and scales the fleet over GENEVE. ALB and NLB sit in front of applications; they are not an inspection fabric for a third-party appliance.

Good to know: Choose an Application Load Balancer for host and path routing, or a Network Load Balancer for a static IP in front of a TCP service. Classic Load Balancer is not an IDS scaler.
Q25A company is building a new stateless web tier on Amazon EC2. Golden AMIs already contain the application. The tier must launch consistent instances, replace them automatically, and remain available if one Availability Zone fails. The team does not want to keep using launch configurations. Which combination of steps should a solutions architect take? (Select TWO.)
Answer: A and B. A launch template is the current way to start Auto Scaling instances from an AMI, and the group must span two Availability Zones so one zone outage does not take the tier down. Those two steps are the replaceable-compute baseline.

Good to know: Launch configurations cannot mix instance types or purchase options and are the legacy path the stem already rejects. Cluster placement groups do not span Availability Zones. Instance store is ephemeral and is not where unique data belongs.
